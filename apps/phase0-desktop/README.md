# Phase 0: 書き味検証プロトタイプ

設計ドキュメント([docs/DESIGN.md](../../docs/DESIGN.md))の Phase 0 に対応する、
**書き味の検証だけ**に絞ったデスクトップアプリ。UI・レイヤー・保存機能は意図的に持たない。

ここで検証するのは以下の 4 点:

1. **低遅延パイプライン** — 入力イベント → スタンプ生成 → GPU 描画を毎イベント処理
2. **手ぶれ補正** — SAI 方式の「ひも(rope)」スタビライザー
3. **入力補間** — Catmull-Rom スプラインで 60〜240Hz のイベント列を滑らかな線に
4. **ストロークバッファ方式** — ストローク中は一時バッファに描き、ペンを離した時に
   ストローク不透明度を掛けてキャンバスへ焼き込む(SAI 的な不透明度挙動)

色は RGBA16Float・リニア空間・premultiplied alpha で合成しており、
本番のタイルキャンバスと同じ前提で書き味を評価できる。

## 実行(デスクトップ)

GPU のあるデスクトップ環境(Windows / macOS / Linux)で:

```sh
cargo run --release -p phase0-desktop
```

ペンタブレット/タッチスクリーンがあれば筆圧が反映される(winit の Touch force 経由)。
マウスの場合は「速度→筆圧」シミュレーション(P キーで切替)で入り抜きの挙動を確認できる。

## 実行(iPhone / iPad の Safari)

同じコードを WebAssembly にビルドして、**Mac 不要**で iPhone / iPad の Safari から
指 / Apple Pencil で試せる。手順は [web/README.md](web/README.md) を参照。

```sh
./build-web.sh          # web/pkg を生成(ビルド済みのものも同梱済み)
cd web && python3 -m http.server 8000
# → 同一 Wi-Fi の iPhone Safari で http://<PCのIP>:8000/ を開く
```

> Web 版はあくまで触感確認用。真の低遅延・Apple Pencil 実筆圧・120Hz の評価は
> ネイティブ iOS ビルド(要 Mac)が必要。

## 操作

| 入力 | 動作 |
|---|---|
| ドラッグ | 描画 |
| `-` / `=` | ブラシサイズ |
| `[` / `]` | ブラシ硬さ |
| `,` / `.` | 手ぶれ補正強度(0〜40px) |
| `P` | 筆圧シミュレーション ON/OFF |
| `1` `2` `3` | 色の切替(墨 / 紅 / 藍) |
| `C` | キャンバスクリア |

現在の設定はウィンドウタイトルに表示される。

## 評価チェックリスト

実際に描いて確認すべき項目(Phase 0 の合格基準):

- [ ] 速い線でもカクつかず滑らかな曲線になる(スプライン補間の効果)
- [ ] 補正強度を上げると震えが消え、かつ線の終端がペンを離した位置まで届く
- [ ] 筆圧(またはシミュレーション)で線の入り抜きが自然に細くなる
- [ ] ストローク中に線が濃くならず、ストローク不透明度が確定時に一様に掛かる
- [ ] タップで点が打てる
- [ ] 描画がカーソルに吸い付く感覚があるか(遅延の体感評価)

## 構成

- `crates/brush-core` — 入力→スタンプ変換のコア(GPU 非依存、ユニットテスト済)。
  iOS / Android へはこのクレートを FFI 経由で共有する。
- `src/gfx.rs` — wgpu レンダラ(ストロークバッファ方式)。Phase 1 でタイルキャンバスに置換する
- `src/shaders.wgsl` — ブラシチップ(距離場ソフト円)とブリットのシェーダ

## 既知の制限(Phase 0 では意図的に対象外)

- キャンバスサイズは起動時のウィンドウサイズ固定(リサイズしても拡張されない)
- Undo / レイヤー / 保存なし
- OS の予測入力(iOS predictedTouches 等)は未実装 — ネイティブ移植時に追加
- 混色(ウェットミキシング)は未実装 — Phase 0 後半でコンピュートシェーダとして追加予定
