## 方針（変えないこと）

`09` と `11` で決めたことは維持する。ここで再確認しておく。

- **v1.0 はモデリング特化。** Web（TypeScript）で作り、`core/` は DOM にも Three.js にも触れない。v1.5 でここを C++ → wasm に差し替える
- **まず Maya のクローン。** 操作の割り当て、ピボット、マーキングメニューの配置は Maya に合わせ、そこからタブレットへ寄せる
- **ゲージの意味は固定。** 左の 2 本は「強度」と「範囲 / サイズ」。モードで中身が変わっても役割は変えない
- **UV は独立モード。** 選択モードの一種ではない（マーキングメニューから外した）
- **しきい値は実機の値。** 5px / 10px / 12px / 120ms / 300ms / 400ms / 指 1.8 倍。変えるなら実機で確かめ直す
- **通し確認が門番。** 実際の Chromium で通らないものは公開しない

### 追加要望（2026-09-08）: 3 本指で選択を直接変形

ユーザー要望。3 本指のピンチで、マニピュレータを触らずに選択中の面 / エッジ / 頂点 / オブジェクトを拡大縮小する。1 本指 = ツール、2 本指 = カメラ、3 本指 = 選択の変形、という割り当てにする。ねじりで回転、平行移動で移動も同じ仕組みで効かせる。何も選んでいなければ何もしない。設計と受け入れ条件は `14` のタスク 8。Phase B より先に入れる。

| 項目 | 決め |
|---|---|

- **2026-09-08: V1〜V3 通過。** V2 で `catmullClark` の頂点点規則がクリースを無視していたバグが見つかり修正した（エッジ点にしか効いていなかった）
- **2026-09-08: V4〜V6 通過。** 差分更新のために細分割の規則を `SubdivPlan` に 1 つだけ置き、全体計算と部分計算が同じ式を同じ順序で通るようにした。V6 は丸めまで含めて一致する（1e-6 どころか完全一致）。接空間基底も `FramePlan` で頂点単位に計算し直せる
