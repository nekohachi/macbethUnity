## 0. 声（`46` まで触ってもらって）

> モデリングモード。押し出し、マルチカット、ベベルなど対称の時は対称に動作して。
> また法線方向に 3 本指スワイプや回転など、法線方向を軸に、というか
> 現在の選択している軸を起点に移動回転スケールを。
> また F シフト コントロール オルトなんだけど、長押しサークルメニュー長押し中
> または右側はずっと長押し中判定で、左側で離すと長押しロックで離してもシフト状態、
> 真ん中はキャンセル。シングルタップは現状と同じロックと解除のオンオフを
> シフト・コントロール・オルトはお願い。F も基本同じでシングルタップはいまと同じ。
> 長押しロック中シングルタップで長押し解除。
> またシフト、オブジェクトがいい。指でカメラ方向 真横 真後ろなどはスカルプトのみでお願い。

4 つに分けた。

| # | 声 | いま | 直し |
|---|---|---|---|

## T1. 修飾ボタンの長押し（SHF / CTL / ALT / F）

### 読み

声の「右側はずっと長押し中判定」と「左側で離すと長押しロック」は、どちらも
**離しても効いたまま**と読める。それだと 2 つの向きに違いが無いので、こう読んだ:

| 離した所 | 意味 | 消えるとき |
|---|---|---|
| **右** | **次の 1 操作だけ**（ワンショット。押しっぱなしの代わり） | 次のドラッグ / ストローク / 選択が終わったとき |
| **左** | **ロック**（タップで入れたのと同じ） | もう一度タップ |
| **真ん中**（動かさずに離す） | **やめる**（押す前の状態へ） | — |

**右を「次の 1 操作だけ」と読んだ。違っていたら言ってほしい**（`37` の表に書く）。

### 決め

1. `ModState` を `"off" | "on" | "once"` に。`modOn()` は `on` と `once` で真。
   `once` は**操作が終わったら `off` に落とす**（ドラッグの `endDrag`、ストロークの
   `end`、矩形選択の確定、マーキングメニューの選択、タップの選択。**使わずに
   もう一度タップしたら `off`**）
2. **押している間だけ**は別の印（`state.heldMod: "shift" | "ctrl" | "alt" | null`）。
   `modOn()` はこれも見る。**離したら押す前の状態へ戻す**（ロック中に長押ししても
   ロックは消えない）
3. 長押しの判定は輪と同じ **200ms**（`HOLD_MS`）。それより短ければタップ
   （今までどおりオン・オフ）。**ロック中にタップすれば消える**（`once` も同じ）
4. 離したときの向き: 押した点から **24px** 以上右で `once`、左で `on`、
   それ以外は**やめる**（押す前へ）。輪は出さない（3 つしか無いので、ボタンの左右に
   小さく「← ロック」「1 回 →」の札を出す。`radial.ts` は使わない）
5. **見た目**: `data-state` に `once` と `held` を足す。`on` は今の塗り、`once` は
   縁取り + 点、`held` は塗りを明るく（押している間だけなので目立たなくてよい）
6. **F**: タップ = フレーム（今のまま）。長押し中 = 今の「押している間だけ」
   （矩形選択・コード）。離した向きで **右 = 次の 1 回だけ F、左 = F ロック、
   真ん中 = 何もしない**（フレームもしない。長押ししてやめたのにフレームが飛ぶと驚く）。
   F ロック中はタップで解除（フレームはしない）。`router.fHeld` に `fLock` と `fOnce` を足す
7. HUD の `modNote`（`state.modsLabel()`）に `once` は「SHF¹」、`held` は「SHF↓」

### テスト（通し確認）

- タップ: off → on → off（今までどおり）
- 長押し（`pointerdown` → 260ms）: `modOn("shift")` が真。動かさず離すと偽（やめる）
- 長押し → 右へ 30px → 離す: `once`。**頂点を 1 回ドラッグしたら `off`**
- 長押し → 左へ 30px → 離す: `on`。タップで `off`
- `on` のまま長押しして真ん中で離す: `on` のまま（押す前へ戻る）
- F: 長押し → 右 → 離す → 空白を引くと矩形選択、終わると F が消える。
  長押し → 真ん中 → **フレームしない**（カメラが動かない）

## T2. 3 本指の変形を枠に通す

### いま

`beginGestureTransform` が `gestureView` に **ワールドの軸**を控える:
`horizontal`（画面の右に近い X か Z）、`viewAxis`（視線に近い X / Y / Z）。
縦スワイプは Y 決め打ち。ALT + つまみも同じ。`45` の T2 は「3 本指はワールドのまま」と
決めたが、声はそれを求めている。

### 決め

- `gestureView` に **`frame: Frame`**（`manipFrame()`。ドラッグ開始で固定。`45` と同じ）
- 軸の選び方（枠の 3 本から）:
  | 枠 | 横スワイプ | 縦スワイプ | ひねり | ALT + つまみ |
  |---|---|---|---|---|
  | ワールド | 今と同じ（画面の右に近い X / Z） | Y | 視線に近い軸 | 縦 = Y、横 = 右に近い X / Z |
  | オブジェクト / ローカル | 枠の 3 本のうち**画面の右に近い 1 本** | **画面の上に近い 1 本** | **視線に近い 1 本** | 同じ規則 |
  | **法線** | U か V の**画面の右に近い方** | **N（法線）。常に** | **N まわり。常に** | 縦 = N、横 = U / V |
- 法線の枠だけ「常に N」にするのは、声が「法線方向にスワイプ・回転」だから。
  面がカメラを向いていると N は視線に近く、画面の上には乗らない。規則で選ぶと
  N が縦スワイプに割り当たらないことがあるので、**決め打ち**にする
- 札（`showTwist` / HUD の `note`）の軸名は `frame.labels`（U / V / N）
- `26` の T1 の「必ずワールド軸で、自由軸は返さない」は**枠がワールドのときだけ**の話に
  読み替える（枠の軸は自由軸ではない。ユーザーが選んだ 3 本）

### テスト

- `tests/frame.test.ts` に足す: 枠の 3 本から「この向きに近い 1 本」を選ぶ関数
  （`nearestAxis(frame, dir)`）が符号込みで返す（右が −U なら −U）
- 通し確認: 上面を選んで 種類 = 法線 → 3 本指の縦スワイプ → 面が +Y に動く
  （x・z は変わらない）。ひねり → 頂点が Y まわりに回る（y は変わらない）

## T3. 対称でトポロジの操作も対称に

### 考え

`45` の対称は「動かす頂点 → 相手」を写すだけ。トポロジの操作は**選択から**始まるので、
**操作の前に選択を鏡へ写す**のが一番素直で、操作ごとの分岐が要らない。
面は「頂点の集合の鏡」、エッジは「両端の鏡」、頂点は `mirror[v]`。相手が無ければ写さない
（左右非対称なトポロジ）。

マルチカットだけは選択ではなく「辺と位置」で切るので、別に扱う。

### 決め

1. **`selector.mirrorSelection(o)`**（`tools/select.ts`）: `state.comp` に鏡を足す。
   戻り値は足した数。対応表は `mirrorMapOf(o, 0, o.mesh)`（`41`）。
   - 頂点: `mirror[v]`（`≥ 0` かつ `≠ v` のとき）
   - エッジ: `edgeKey(mirror[a], mirror[b])` を `view.edges` から引く（`select.ts` の
     `keyIdx` と同じ表）
   - 面: **頂点の集合をソートした鍵**で面を引く表を 1 回作る（O(面)。対称が
     オンで操作を始めたときだけ）
2. **`symX` が立っていれば、トポロジの操作の前に写す**: 押し出し（メニューと
   **SHF ドラッグ**の両方。`extrudeForDrag`）、ベベル（`beginBevel` の `edges`）、
   削除、接続、ブリッジ、距離でマージ・中心にマージ、面の抽出、エッジの溶解。
   **`applyTopologyChange` を通るものは全部**そこで写す（1 か所）。通らないもの
   （押し出しの SHF ドラッグ、ベベル）は個別に
3. **マルチカット**: `commit` で辺 `(a, b)` を `t` で切ったあと、
   `(mirror[a], mirror[b])` が**新しいメッシュにまだ辺として残っていれば**、同じ `t` で
   もう 1 回切る（`insertEdgeLoop` は頂点の番号を保つので、`mirror` は引ける）。
   残っていないのは、1 回目のループが中心線をまたいで鏡の辺を既に割ったとき。
   予測線（黄色）も鏡側に出す
4. **ターゲットウェルド**: 掴んだ頂点 `v` を `w` へ溶接するとき、`mirror[v]` と
   `mirror[w]` が両方あれば**その組も溶接**する
5. **両側が選ばれているドラッグ**（`45` の「両側とも動く組は各自が動く」を改める）:
   両側を写した選択を動かすと、ワールド X に引いたときに**両側が同じ向きへ**動いて
   崩れる。**押した側だけを動かして、相手へ写す**:
   - `captureTarget` で、`v` と `mirror[v]` が両方 `verts` に居るなら、
     **押した側**（ドラッグ開始でポインタの下にあったコンポーネントの x の符号。
     ハンドルから始めたときは +X）の頂点だけを `verts` に残し、相手は `mirror` の組へ
   - ソフト選択の重みは対称なので、相手の重みは捨ててよい
   - 3 本指も同じ `captureTarget` を通るので、そのまま効く
6. 対称がオンで**相手が 1 つも見つからない**操作は、今までどおり片側だけに効かせて、
   トーストに「鏡の相手が見つからず、片側だけ」と出す（黙って片側にしない）

### テスト（通し確認）

- 対称オン、立方体の +X の面を 1 つ選んで押し出し → 面が 2 つ増えて左右対称
  （全頂点で `|p(a).x + p(b).x| < 1e-6`）
- 対称オン、+X のエッジを 1 本選んでベベル → 両側にベベルが入る
- 対称オン、+X の辺でマルチカット（t = 0.3）→ 左右に 1 本ずつループ。
  **中心線をまたぐループ**（Z 方向の辺）では 1 本だけ（2 回切らない）
- 対称オン、+X の頂点と −X の相手を両方選んで **X に引く** → 左右が離れる / 寄る
  （同じ向きへは動かない）
- 対称オフなら今までどおり片側だけ
- ターゲットウェルドで相手の組も溶接される（頂点が 2 減る）

## T4. SHF の吸着はスカルプトだけ。モデリングは矩形選択

### 決め

- `snapStart`（`app.ts` の router 設定）は **`mode === "sculpt"` のときだけ**
  `{ theta, phi }` を返す。モデリングでは null
- モデリングで **SHF が立っていて、指 / ペンで空白を引いた**ら、タンブルではなく
  **矩形選択**（`marqueeStart`）。足し引きは今の矩形選択の規則（SHF が立っているので
  足す）。`gestures.ts` の「メッシュの外ならタンブル」の分岐の前に入れる
- マウスの Shift + 左ドラッグは今までどおり（Maya と同じ矩形の足し）
- スカルプトは変えない（`36` の T4 のまま）

### テスト（通し確認）

- モデリング: SHF を立てて空白を引く → カメラが動かず、矩形で頂点が**足される**
- スカルプト: SHF を立てて回す → 標準ビューに吸着（`36` の確認がそのまま通る）

## やらないこと

- Y / Z の対称（`41` の対応表は X だけ）
- 対称の**トポロジが違う**メッシュで相手を作ること（相手が無ければ片側 + トースト）
- ブリッジの 2 組を対称に選ぶ賢さ（写した選択が 4 組になったら「2 組ずつ」で
  今の規則に任せる。壊れるなら片側だけにしてトースト）
- 修飾ボタンの輪（3 つしか無いので札で足りる）
