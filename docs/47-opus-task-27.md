## 0. 声（`46` まで触ってもらって）

> モデリングモード。押し出し、マルチカット、ベベルなど対称の時は対称に動作して。
> また法線方向に 3 本指スワイプや回転など、法線方向を軸に、というか
> 現在の選択している軸を起点に移動回転スケールを。

## T1. 修飾ボタンの長押し（SHF / CTL / ALT / F）

### 読み（2 回目の声で確定）

> 基本的に実際のシフトキーと同じ使い心地にしたい。長押し中は右手操作でぶれたりも
> するから、ざっくり右側は長押しで離したら解除される想定。左はロックでがっつり、
> 複数選択したいときに使う。「次の 1 回」という使い方は想定していない。
> シングルタップでロック解除。

つまり**本物の Shift キー**:

| 何 | 意味 |
|---|---|
| **押している間** | 効く（押しっぱなし） |
| **離す**（右でも真ん中でも） | 消える。**右側は「ぶれても離したら消える」ための幅**で、別の意味は無い |
| **左へずらして離す** | **ロック**（がっつり。複数選択に使う） |
| **タップ** | ロックのオン・オフ（今までどおり）。**ロック中のタップで解除** |

「次の 1 回だけ」は**作らない**（入れない方が自然、とのこと）。

### 決め

1. `ModState` は `"off" | "on"` のまま。**押している間**は別の印
   （`state.heldMod: "shift" | "ctrl" | "alt" | null`）で、`modOn()` はこれも見る
2. 長押しの判定は輪と同じ **200ms**（`HOLD_MS`）。それより短ければタップ
   （今までどおりオン・オフ）
3. **離したとき**: 押した点から **24px 以上左**なら `on`（ロック）。それ以外は **`off`**
   （右も真ん中も。ロック中に長押しして離しても `off` = 解除）
4. **見た目**: `data-state` に `held` を足す（塗りを明るく。押している間だけなので
   目立たなくてよい）。左へずらしている間は「← ロック」の小さな札をボタンの左に出す。
   `radial.ts` は使わない（選ぶものが 1 つしか無い）
5. **F**: タップ = フレーム（今のまま）。長押し中 = 今の「押している間だけ」
   （矩形選択・コード）。離すと消える（**フレームはしない**。長押ししてやめたのに
   フレームが飛ぶと驚く）。**左へずらして離すと F ロック**（`router.fLock`）。
   F ロック中はタップで解除（フレームはしない）
6. HUD の `modNote`（`state.modsLabel()`）に `held` は「SHF↓」

### テスト（通し確認）

- タップ: off → on → off（今までどおり）
- 長押し（`pointerdown` → 260ms）: `modOn("shift")` が真。**そのまま離すと偽**、
  右へ 30px ずらして離しても偽
- 長押し → 左へ 30px → 離す: `on`。タップで `off`
- `on` のまま長押しして右で離す: `off`（解除）
- F: 長押し → 左 → 離す → 空白を引くと矩形選択、F は残る。タップで消える。
  長押し → そのまま離す → **フレームしない**（カメラが動かない）

## T2. 3 本指の変形を枠に通す

### いま

`beginGestureTransform` が `gestureView` に **ワールドの軸**を控える:
`horizontal`（画面の右に近い X か Z）、`viewAxis`（視線に近い X / Y / Z）。
縦スワイプは Y 決め打ち。ALT + つまみも同じ。`45` の T2 は「3 本指はワールドのまま」と
決めたが、声はそれを求めている。

### 決め

- `gestureView` に **`frame: Frame`**（`manipFrame()`。ドラッグ開始で固定。`45` と同じ）
- 軸の選び方（枠の 3 本から）:
  | 枠 | 横スワイプ | 縦スワイプ | ひねり | ALT + つまみ |
  |---|---|---|---|---|
  | ワールド | 今と同じ（画面の右に近い X / Z） | Y | 視線に近い軸 | 縦 = Y、横 = 右に近い X / Z |
  | オブジェクト / ローカル | 枠の 3 本のうち**画面の右に近い 1 本** | **画面の上に近い 1 本** | **視線に近い 1 本** | 同じ規則 |
  | **法線** | U か V の**画面の右に近い方** | **N（法線）。常に** | **N まわり。常に** | 縦 = N、横 = U / V |
- 法線の枠だけ「常に N」にするのは、声が「法線方向にスワイプ・回転」だから。
  面がカメラを向いていると N は視線に近く、画面の上には乗らない。規則で選ぶと
  N が縦スワイプに割り当たらないことがあるので、**決め打ち**にする
- 札（`showTwist` / HUD の `note`）の軸名は `frame.labels`（U / V / N）
- `26` の T1 の「必ずワールド軸で、自由軸は返さない」は**枠がワールドのときだけ**の話に
  読み替える（枠の軸は自由軸ではない。ユーザーが選んだ 3 本）

### テスト

- `tests/frame.test.ts` に足す: 枠の 3 本から「この向きに近い 1 本」を選ぶ関数
  （`nearestAxis(frame, dir)`）が符号込みで返す（右が −U なら −U）
- 通し確認: 上面を選んで 種類 = 法線 → 3 本指の縦スワイプ → 面が +Y に動く
  （x・z は変わらない）。ひねり → 頂点が Y まわりに回る（y は変わらない）

## T3. 対称でトポロジの操作も対称に

### 考え

`45` の対称は「動かす頂点 → 相手」を写すだけ。トポロジの操作は**選択から**始まるので、
**操作の前に選択を鏡へ写す**のが一番素直で、操作ごとの分岐が要らない。
面は「頂点の集合の鏡」、エッジは「両端の鏡」、頂点は `mirror[v]`。相手が無ければ写さない
（左右非対称なトポロジ）。

マルチカットだけは選択ではなく「辺と位置」で切るので、別に扱う。

### 決め

1. **`selector.mirrorSelection(o)`**（`tools/select.ts`）: `state.comp` に鏡を足す。
   戻り値は足した数。対応表は `mirrorMapOf(o, 0, o.mesh)`（`41`）。
   - 頂点: `mirror[v]`（`≥ 0` かつ `≠ v` のとき）
   - エッジ: `edgeKey(mirror[a], mirror[b])` を `view.edges` から引く（`select.ts` の
     `keyIdx` と同じ表）
   - 面: **頂点の集合をソートした鍵**で面を引く表を 1 回作る（O(面)。対称が
     オンで操作を始めたときだけ）
2. **`symX` が立っていれば、トポロジの操作の前に写す**: 押し出し（メニューと
   **SHF ドラッグ**の両方。`extrudeForDrag`）、ベベル（`beginBevel` の `edges`）、
   削除、接続、ブリッジ、距離でマージ・中心にマージ、面の抽出、エッジの溶解。
   **`applyTopologyChange` を通るものは全部**そこで写す（1 か所）。通らないもの
   （押し出しの SHF ドラッグ、ベベル）は個別に
3. **マルチカット**: `commit` で辺 `(a, b)` を `t` で切ったあと、
   `(mirror[a], mirror[b])` が**新しいメッシュにまだ辺として残っていれば**、同じ `t` で
   もう 1 回切る（`insertEdgeLoop` は頂点の番号を保つので、`mirror` は引ける）。
   残っていないのは、1 回目のループが中心線をまたいで鏡の辺を既に割ったとき。
   予測線（黄色）も鏡側に出す
4. **ターゲットウェルド**: 掴んだ頂点 `v` を `w` へ溶接するとき、`mirror[v]` と
   `mirror[w]` が両方あれば**その組も溶接**する
5. **両側が選ばれているドラッグ**（`45` の「両側とも動く組は各自が動く」を改める）:
   両側を写した選択を動かすと、ワールド X に引いたときに**両側が同じ向きへ**動いて
   崩れる。**押した側だけを動かして、相手へ写す**:
   - `captureTarget` で、`v` と `mirror[v]` が両方 `verts` に居るなら、
     **押した側**（ドラッグ開始でポインタの下にあったコンポーネントの x の符号。
     ハンドルから始めたときは +X）の頂点だけを `verts` に残し、相手は `mirror` の組へ
   - ソフト選択の重みは対称なので、相手の重みは捨ててよい
   - 3 本指も同じ `captureTarget` を通るので、そのまま効く
6. 対称がオンで**相手が 1 つも見つからない**操作は、今までどおり片側だけに効かせて、
   トーストに「鏡の相手が見つからず、片側だけ」と出す（黙って片側にしない）

### テスト（通し確認）

- 対称オン、立方体の +X の面を 1 つ選んで押し出し → 面が 2 つ増えて左右対称
  （全頂点で `|p(a).x + p(b).x| < 1e-6`）
- 対称オン、+X のエッジを 1 本選んでベベル → 両側にベベルが入る
- 対称オン、+X の辺でマルチカット（t = 0.3）→ 左右に 1 本ずつループ。
  **中心線をまたぐループ**（Z 方向の辺）では 1 本だけ（2 回切らない）
- 対称オン、+X の頂点と −X の相手を両方選んで **X に引く** → 左右が離れる / 寄る
  （同じ向きへは動かない）
- 対称オフなら今までどおり片側だけ
- ターゲットウェルドで相手の組も溶接される（頂点が 2 減る）

## T4. SHF の吸着はスカルプトだけ。モデリングは矩形選択

### 決め

- `snapStart`（`app.ts` の router 設定）は **`mode === "sculpt"` のときだけ**
  `{ theta, phi }` を返す。モデリングでは null
- モデリングで **SHF が立っていて、指 / ペンで空白を引いた**ら、タンブルではなく
  **矩形選択**（`marqueeStart`）。足し引きは今の矩形選択の規則（SHF が立っているので
  足す）。`gestures.ts` の「メッシュの外ならタンブル」の分岐の前に入れる
- マウスの Shift + 左ドラッグは今までどおり（Maya と同じ矩形の足し）
- スカルプトは変えない（`36` の T4 のまま）

### 矩形とマニピュレータ（声の「矩形がマニピュレータにかぶると？」）

**かぶるのは問題ない。** 矩形が拾うのはコンポーネントだけで、マニピュレータは
拾わない。気を付けるのは**押し始めの点**だけ:

- **ハンドルの上で押した**ら、SHF が立っていてもハンドルのドラッグ（Maya と同じで、
  SHF + 移動 = 押し出し。`extrudeForDrag`）。矩形にはしない
- **コンポーネントの上で押した**ら、今までどおり選択（SHF で足す）
- **空白で押した**ら矩形

`gestures.ts` の `isOnMesh` はハンドルの当たりを含めて「メッシュの上」と返すので、
矩形の入口はその**あと**（空白と分かってから）に置く。F の矩形（`fHeld`）は
「ヒットテストは無視」で先に入っているが、SHF はそうしない（ハンドルの押し出しを
潰さないため）。矩形を引いている間は、マニピュレータは動かさない（選択が決まってから
`refresh` で移る）

### テスト（通し確認）

- モデリング: SHF を立てて空白を引く → カメラが動かず、矩形で頂点が**足される**
- スカルプト: SHF を立てて回す → 標準ビューに吸着（`36` の確認がそのまま通る）

### T1. 修飾ボタンの長押し — 本物の Shift キーに

- `state.heldMod: "shift" | "ctrl" | "alt" | null` を足した。`modOn()` は

- **`click` は `detail === 0` のときだけ拾う。** 指やマウスの click は pointerup の
  あとにも来るので、そのまま拾うと 1 回のタップで 2 回入り切りしてしまう。
  `detail` が 0 なのはキーボードの Enter と、確認スクリプトの `.click()` だけ

  左で `router.fLock`。**長押しして離してもフレームしない**
- HUD は押下だけ「SHF↓」（離せば消えるので、消し忘れの警告とは区別する）

### T2. 3 本指を枠へ

- `tools/frame.ts` に **`nearestAxis(frame, toward, pick?)`** と `fixedAxis(frame, axis)`。
  符号込みで返す（右が −U なら −U）。`pick` で候補を絞れる
- `gestureView` が**枠**（`manipFrame()`）と、開始時の画面の右 / 上 / 奥を控える。
  `gestureAxis("right" | "up" | "view")` が 1 か所で軸を決める:

  | 枠 | 横スワイプ | 縦スワイプ | ひねり |
  |---|---|---|---|
  | ワールド | 右に近い X / Z | Y | 視線に近い軸 |
  | オブジェクト / ローカル | 右に近い 1 本 | 上に近い 1 本 | 視線に近い 1 本 |
  | 法線 | U / V の右に近い方 | **N（常に）** | **N まわり（常に）** |

- ALT + つまみも同じ規則に乗せた。`applyGestureTransform` の `scale` に
  `{ axis, index, factor }` を足して、**枠の 1 本に沿って**伸ばせるようにした
  （前は成分ごとの掛け算で、ワールドの枠でしか合っていなかった）
- 使わなくなった `screenRightAxis` / `screenDepthAxis` / `gestureScaleAxis` は消した

### T3. 対称でトポロジも

- **`selector.mirrorSelection(o)`**: 頂点は `mirror[v]`、エッジは両端の鏡を
  `view.edges` から、面は**頂点の集合をソートした鍵**の表（O(面)、操作のときだけ作る）
- **`requireComponents()` を通れば写す。** メニューからのトポロジ操作は全部そこを
  通るので、分岐が 1 か所で済んだ。通らない道（SHF ドラッグの押し出し、ベベル、
  距離でマージ）は個別に `mirrorSelectionForOp()` を呼ぶ
- マルチカットは予測線の段階で**鏡の辺**を持ち、確定で**まだ辺として残っていれば**
  同じ `t` でもう 1 回切る。中心線をまたぐループ（1 回目が既に鏡の辺を割る）では
  切らない。予測線も鏡側に出て、ヒントに「鏡側にも」と出る
- ターゲットウェルドは `mirror[v]` と `mirror[w]` が**別の 4 頂点**のときだけ組を足す
- `captureTarget(side)`: 両側が動く組は**押した側だけ**を残して相手へ写す。
  押した側は `pressedSide()`（押した点の下のコンポーネントの x）で決める。
  ハンドルと 3 本指から始めたときは +X
- 相手が 1 つも見つからなければ今までどおり片側だけ効かせて、
  言い添えに「鏡の相手が見つからず、片側だけ」を足す（`withSymNote`）
- ブリッジだけは、写して 4 組になって繋げなかったら**片側に戻してもう一度**やる

**`core/symmetry.ts` の対応表を直した（`47` で見つかった穴）。**
押し出しは距離 0 で先端を作るので、**同じ場所に頂点が 2 つ重なる**。前の
`buildMirrorMap` は「最初に見つかった 1 つ」を相手にしていたので、
**両側の「元」どうしが組になって先端が余り**、相手なしが 8 個出ていた。
重なりは**番号の順で k 番目どうし**を組にするようにした（`rankOf`）。
テストを 2 つ足してある。

### T4. SHF の吸着はスカルプトだけ

- `snapStart` は `mode === "sculpt"` のときだけ角度を返す
- モデリングで SHF を立てて**空白**を引いたら矩形選択（足す）。
  入口は `isOnMesh` が偽と分かった**あと**に置いたので、
  ハンドルの上から引く SHF + 移動 = 押し出しは潰れない

### 数字（`?bench=1&size=25`）

| | 前 | 今 | 門 |
|---|---|---|---|
| B6a ストロークの 1 コマ | 18.5ms（`46`） | **19.5ms** | 変えない ✓ |
| B8 鏡映の対応表（24.9 万頂点） | 63.8ms（`41`）· 74.6ms（`42`） | **62.2ms** | ≤ 200ms ✓ |
| B10 2K の法線 + 高さ | 1765ms（`46`） | 1974ms | ≤ 5000ms ✓ |
| B11 2K の 曲率 + AO + 厚み | 25264ms（`46`） | 25646ms | ≤ 20000ms **✗**（`46` の 3 択のまま） |

対称の写しは**操作の前に 1 回**なので、1 打ちの重さは変わらない。
`buildMirrorMap` に重なりの順位（`rankOf`）を足したが、同じ格子の中を数えるだけなので
**B8 も変わらない**。B11 は `46` から持ち越しの宿題（下）。
