## 1. UV の取り込み（指摘 1）

### 1.1 何が起きていたか

`enterUv()` はレシピが無いと `emptyRecipe()`（`method: "lscm"`、切れ目ゼロ）を作って `recompute` していた。立方体は閉じた面なので切れ目ゼロの LSCM は 1 島に潰れ、球も同じ。プリミティブが持っていた UV（立方体は面ごとに 0〜1、球は経緯度）は上書きされて消える。**Maya は UV エディタを開いても UV を作り直さない。** ここが違っていた。

### 1.2 決め

- **レシピの初期値は「今ある UV をそのまま」。** `recipeFromMesh(mesh)`:
  - `map1` があれば `method: "none"`、`base` = `map1` の複製、`seams` = `seamsFromUv(mesh)`
  - `map1` が無ければ（正多面体、UV 無しの OBJ）`method: "projection"`、切れ目ゼロ。C2 の自動 UV ができたらそちらに替える
- **`UvRecipe.base: Float32Array | null` を足す。** 取り込んだ UV。`method: "none"` の `recompute` は `base` を土台にして `manual` を乗せる。今の実装は `mesh.uvSets["map1"]`（= 前回の出力）を土台にしているので、手の差分が recompute のたびに二重に乗る。`base` を持てばこれが消える
- `seamsFromUv(mesh, eps = 1e-6)`: 2 つの面が共有する辺で、辺の両端のコーナー UV が面をまたいで一致しなければ切れ目。境界辺（面が 1 つ）は切れ目にしない
- **展開は明示の操作。** 「展開」を押すと `method` を `"lscm"` に変えてから recompute する（履歴に残る）。オプションパネルの「ソルバー」は今の `method` を映す
- **`.mbz` に `base` を書く。** positions と同じ方法（Float32Array）
- **トポロジが変わったとき**（`reconcile`）。`method: "none"` なら **`base` を今の `map1` で取り直し、`manual` を空にする**。押し出しやベベルは UV を新しい面へ補間して持ち越すので、その時点の `map1` が「ユーザーが見ていた UV」そのもの。`manual` は既に `map1` に焼き込まれているので捨ててよい。切れ目は生き残ったものに `seamsFromUv` の結果を足す。`lscm` / `projection` のときは今までどおり（死んだ切れ目と島だけ捨てる）

### 1.3 カット / ソーが `"none"` のときに何をするか

| 操作 | `"none"` | `"lscm"` / `"projection"` |
|---|---|---|
| カット | `seams` に足すだけ。UV は動かない（Maya の Cut と同じ。島の境界として見える） | 同じ（recompute で島が分かれる） |
| ソー | `seams` から消し、**`base` の両側のコーナー UV を中点に寄せる**（Maya の Sew。島は動かない、辺だけ縫う）。core に `sewInBase(mesh, base, edges)` | `seams` から消すだけ（recompute が繋ぐ） |

「移動してソー」（小さい島を寄せてから縫う）は C3 のまま。

### 1.4 合格条件

- vitest U10: 立方体 → `seamsFromUv` が 12 本、`recipeFromMesh` + `recompute` の結果が元の `map1` と 1e-6 で一致、島 6。球 → 島 1（経線の切れ目 1 本 + 極）
- vitest U11: `"none"` で 1 辺をソー → 両側のコーナー UV が中点で一致。もう一度 recompute しても動かない（二重乗せが無い）
- vitest U12: `"none"` で押し出し → `reconcile` 後の `base` の長さがコーナー数 × 2、`manual` が空
- 通し確認: 立方体で UV モードに入る → 島 6、各島の境界箱が 0〜1 の正方形。**展開を押すまで UV は変わらない**

## 3. タップ保護（指摘 3）

### 3.1 何が起きていたか

ペンで 1 回目のタップ → 選択 → マニピュレータの中心が選択の中心に出る。2 回目のタップがその中心（16px）か選択中のコンポーネント（ツイーク）に当たり、`startTool` がその場でドラッグを始める。ペンは着地で 1〜4px ぶれるので、`TOOL_MOVE`（3px）を越えて「移動」が確定し、ダブルクリック（ループ選択など）にもならない。1 回目のタップも、すでに選んでいるものの上なら同じ理由で動く。

### 3.2 決め

**ペンと指のドラッグは「押した時点」ではなく「動きが確かになった時点」で始める。** マウスは今のまま（3px で即時。マウスはぶれない）。

- 押した時点: ハンドル（またはツイーク）を「候補」として覚え、光らせる。メッシュもオブジェクトも動かさない。スナップショットも取らない
- **ドラッグが生きる条件**（どちらか）:
  - 押した点からの移動が `TAP_MOVE`（12px）を越えた
  - 移動が `TOOL_MOVE`（3px）を越え、かつ押してから `TAP_DURATION`（300ms）が経った
- 生きた時点で `beginDrag`。**起点は押した点**（生きた点ではない）。選択がペンの位置へ追いつく形になる。飛びは最大 12px で、ペンの位置と一致することのほうが大事
- 生きる前に離した → タップ。今までの `selector.click`（単発・ダブル）に渡す
- **Shift 押し出しは生きた時点で行う。** 今は押した瞬間にメッシュを変えていたので、Shift + タップでも押し出されていた。生きるまで何もしなければ、Shift + タップは「選択に足す」になる。`finishTool` の「押し出しは動かなくても確定」の特例は要らなくなる
- 対象: 3D のハンドルとツイーク、**2D（UV）のドラッグも同じ**。矩形選択（F）、マルチカット、ベベル、3 本指、2 本指は対象外（今のまま）

新しいしきい値は作らない。`TAP_MOVE`、`TOOL_MOVE`、`TAP_DURATION` はすべて `14` の 5 章にあるもの。

### 3.3 合格条件

- 通し確認: 面を選んだ状態で、ペンでその面の中心を **6px ずらして 2 回タップ**（380ms 以内）→ 頂点座標が変わらず、ダブルクリック（シェル選択）が効く
- 通し確認: ペンでハンドルを 40px ドラッグ → 動く（今の項目のまま通る）
- 通し確認: SHF オンで面をタップ（動かさない）→ 面数が変わらない

## 4. マニピュレータのボタン（指摘 4）

### 4.1 ツール列

「変形」の区画に **「マニピュレータ」ボタン**を足す（選択・変形の次）。アイコンは十字と中心の点（`ICONS.pivot`、新規）。

| 操作 | 効果 |
|---|---|
| タップ | **ピボット編集の切替**（Maya の D / Insert）。オンの間 `aria-pressed` |
| 長押し（サークルメニュー） | 北: ピボットを移動（D）· 北東: 選択の中心へ戻す · 東: 大きく（+）· 西: 小さく（−）· 南: 初期設定に戻す |

「初期設定に戻す」= 大きさ 1.0、ピボットを選択の中心へ、マニピュレータを「ユニバーサル」に。

### 4.2 大きさ

- `state.manipSize`: 0.5〜2.0、既定 1.0。1 段は ×1.25（Maya の + / − と同じ感覚）
- `Manipulator.scaleAt` に掛ける。当たり判定の px（16px など）は変えない（大きくしても掴みやすさは同じ、見た目だけ変わる）
- キー: `+` / `=` で大きく、`-` で小さく（Maya と同じ）
- 保存: `localStorage` の `macbeth.manipSize`（パネル配置と同じ置き場）
- オプションパネル「表示」区画にスライダー「マニピュレータの大きさ」

### 4.3 ピボット編集（D）

- `state.pivot: Vector3 | null`（ワールド）。null なら今までどおり選択の中心。`pivotWorld()` は設定されていればこれを返す
- **セッション値。** 選択が変わったら（オブジェクトでもコンポーネントでも）null に戻す。Maya のオブジェクトごとのピボットの保存は後（`Transform` に `pivot` を足す仕事。今は core を触らない）
- オンの間: マニピュレータは移動の矢印と中心だけを別の色（黄緑）で出す。ドラッグは **ピボットだけを動かす**（メッシュは動かない、履歴に入れない）。**スナップは効く**（V でピボットを頂点へ寄せるのが Maya の常套手段）
- オンの間の 3 本指は何もしない（`transformBegin` が false）
- HUD のモード行に「ピボット編集」
- キー: `d` / `Insert` で切替
- UV モードでは出さない（2D にマニピュレータはまだ無い。置くときに `manipSize` をそのまま使う）

### 4.4 合格条件

- 通し確認: 「大きく」を 2 回 → `manipSize` が 1.5625。「初期設定に戻す」→ 1.0
- 通し確認: 面を選んで D → ハンドルをドラッグ → 頂点座標は変わらず `pivot` が動く → D を解除して回転 → 新しいピボットのまわりで回る（選択の中心から離れた 1 頂点の位置で確認）

## 5. スライド（指摘 5）

Shift + 移動 = 押し出しは既にある（3.2 の変更のみ）。**Shift + Ctrl + 移動 = スライド** を足す。

### 5.1 意味

選んだ頂点が、**選んでいない隣の頂点へ向かう辺（レール）に沿って**動く。エッジループを選べば Maya の Slide Edge（相対モード）と同じ動きになる。面を選べば、まわりの辺に沿って面が滑る。

- レール: 各頂点について、辺で繋がる頂点のうち選択に入っていないもの
- 向き: ペンの移動方向（画面）と最も揃うレールを頂点ごとに選ぶ。逆向きに引けばレールも反対側に替わる
- 量 `t`: 押した点に一番近い選択頂点（基準頂点）で決める。ペンの移動をそのレールの画面上の向きに射影し、レールの画面長で割る。**0〜0.99** に丸める（隣に届くと面が潰れるので 1 にはしない）。全頂点に同じ `t` を使う（Maya の相対モード）
- レールの無い頂点（まわりが全部選ばれている）は動かない
- 対称編集: 移動と同じ規則で鏡側にも掛ける。ソフト選択は効かない。スナップも効かない
- 履歴のラベル「スライド」。HUD に `t` を出す

### 5.2 core

```ts
// src/core/slide.ts（純粋関数。DOM も three も無し）
export function slideRails(mesh: Mesh, verts: Iterable<number>): Map<number, number[]>;
//   頂点 → レール先の頂点（選択外の隣）。並びは頂点番号順（決定的に）
export function slideVertices(
  mesh: Mesh,
  base: Float32Array,                 // ドラッグ開始時の positions の複製
  choice: Map<number, number>,        // 頂点 → 今回使うレール先
  t: number,                          // 0〜0.99
): void;                              // mesh.positions を書く: p = base(v) + (base(n) − base(v)) · t
```

レールの選択（画面の向き）は app（`tools/transform.ts` に `beginSlide` / `updateSlide`）。core は向きを知らない。

### 5.3 入口

`startTool` で、移動のハンドル（またはツイーク）かつコンポーネントモードかつ選択あり:

| 修飾 | 動き |
|---|---|
| なし | 移動 |
| Shift | 押し出してから移動 |
| **Shift + Ctrl** | **スライド** |
| Ctrl だけ | 移動（Ctrl は今後スナップの意味を持たない。7 章） |

修飾の判定はラッチ（6 章）と物理キーの OR。マウスも同じ。

### 5.4 合格条件

- vitest S1: 立方体を `subdivide` して 1 本のエッジループを選び、`t = 0.5` → ループの各頂点が隣のループとの中点。`t = 0` で元どおり
- vitest S2: レールの無い頂点（全部選択）は動かない
- 通し確認: SHF と CTL をオンにしてループを 40px ドラッグ → 頂点が動き、面数が変わらない（押し出しになっていない）

## 6. 修飾キーは 2 段階（指摘 6）

- `ModState = "off" | "on"`。タップで切替。**使っても消えない。** `releaseLatches()` は消す
- 見た目: `on` は今の `lock` の見た目（塗り）。`latch` の見た目（縁だけ）は消す
- HUD のモード行に、オンの修飾を出す（`· SHF` `· CTL`）。消し忘れに気づけるように
- 物理キー（Shift / Ctrl / Alt）はこれまでどおり OR
- Ctrl の意味: 選択から外す、スライド（Shift と同時）、マーキングメニューの「縮小」。**スナップではなくなる**（7 章）

## 7. スナップのツール（指摘 7）

### 7.1 スナップを CTL から切り離す

B6 では「CTL ラッチ中はスナップ」にしていた。Ctrl が 2 段階のトグルになると、選択から外すつもりで Ctrl をオンにしたままドラッグしたときに勝手に寄る。Maya でも Ctrl はスナップではない。

- `state.snapOn: boolean`（トグル）。`snapping = snapKeyHeld || snapOn`
- `SnapKind = "grid" | "vertex" | "edge" | "surface"`

### 7.2 ツール列

「変形」の区画に **「スナップ」ボタン**（磁石のアイコン `ICONS.snap`、新規）。

| 操作 | 効果 |
|---|---|
| タップ | `snapOn` の切替。種類はそのまま |
| 長押し（サークルメニュー） | 北: グリッド（X）· 東: 頂点（V）· 南: カーブ / エッジ（C）· 西: サーフェス · 南西: オフ |

種類を選ぶと `snapOn` も立つ。ボタンの `aria-pressed` は `snapOn`。

### 7.3 種類

| 種類 | Maya | 行き先 |
|---|---|---|
| グリッド | Snap to grids（X） | 刻みで丸める（今のまま） |
| 頂点 | Snap to points（V） | 画面 40px 以内の頂点（今のまま） |
| カーブ / エッジ | Snap to curves（C）。カーブは無いのでポリゴンのエッジ | 辺の上の最近点（今のまま。表示名だけ「カーブ / エッジ」） |
| **サーフェス** | Make Live の考え方 | ピボットの画面位置で `picker.pickSurface` を撃ち、当たった面の点へ。**自分のオブジェクトは除く**（コンポーネントモードでも。自分の面に当たり続けるため） |

X / V / C を押している間だけ効く動きは今のまま（Maya と同じ）。サーフェスにキーは無い。

### 7.4 UV モード

- 同じボタンを UV のツール列にも出す。種類は **グリッド**（1/8、1/16、1/32。オプション）と **UV 頂点** の 2 つ。サーフェスとエッジは出さない
- 効き方: ドラッグ中、基準コーナー（押した点に一番近い選択コーナー）の行き先を寄せ、選択全体を同じ差で動かす。UV 頂点は画面 40px 以内で選択外のもの

### 7.5 オプションパネル

「スナップ」区画: 種類の segmented に「面」を足す。「CTL で有効」の文言を消し、「ツール列のスナップ、または X / V / C を押している間」にする。UV モードでは「グリッドの刻み」を 1/8・1/16・1/32 の 3 択に。

### 7.6 合格条件

- 通し確認: スナップをオンにして頂点を別の頂点の近く（20px）へドラッグ → 座標が一致（今の B6 の項目を CTL からボタンに書き換える）
- 通し確認: 種類「サーフェス」で立方体の頂点を、別のオブジェクトの面の上へ → 頂点がその面の上に乗る（面の平面との距離 < 1e-3）
- 通し確認: UV モードでグリッド 1/8、島を 0.07 ずらす → 0.125 の倍数に揃う

## 9. 決めてあること（追加分）

| 項目 | 決め |
|---|---|
| UV モードに入っても UV を作り直さない。展開は明示の操作 | 1 章 |
| `"none"` の土台は `base`。`map1` ではない | 1.2 |
| トポロジが変わったら `"none"` は `base` を取り直す | 1.2 |
| 編集メニューの北 / 北東 / 東は 展開 / カット / ソー で固定 | 2.2 |
| ペンと指のドラッグは 12px か「3px かつ 300ms」で生きる。起点は押した点 | 3.2 |
| ピボットはセッション値。選択が変わると戻る | 4.3 |
| スライドの `t` は基準頂点で決めて全頂点に同じ値 | 5.1 |
| 修飾は 2 段階。使っても消えない | 6 |
| スナップは CTL と無関係。ボタンか X / V / C | 7.1 |
| しきい値は変えない | `14` の 5 章 |

## 10. やらないこと

- オブジェクトごとのピボットの保存（`Transform.pivot`）。セッション値で様子を見る
- スライドの絶対モード（距離指定）。相対だけ
- Maya の Cut / Sew ツール（辺をなぞって切る対話ツール）。メニューで足りるか見てから
- 2D のマニピュレータ（C1 の報告のとおり、触ってから判断）
- ビュー平面スナップ、ライブサーフェスの常時化（サーフェスは種類の 1 つとして足すだけ）
