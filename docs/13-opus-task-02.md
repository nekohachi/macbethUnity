### 作業の流れ（毎タスク共通）

1. core に関数が要るなら **先に vitest を書き、それを通す**
2. app に繋ぐ
3. **`scripts/smoke.mjs` に確認項目を 1 つ足す**（下の「通し確認の書き方」）
4. `npm run build && npm run smoke` が緑
5. `sh scripts/publish.sh` で `app/` を更新して **一緒にコミット**する（しないと `publish.yml` がボットのコミットを積む）
6. push。CI（`ci.yml`）と `publish.yml` が緑になるのを確認する

コミットは英語、末尾に指定の trailer。モデル名をコミットやコードに書かない。

### 通し確認の書き方

`scripts/smoke.mjs` を読んでから足す。守ること:

- **画面座標はキャンバス比率で**（`at(fx, fy)`）。ピクセル固定はパネル幅で壊れる
- 2 回のクリックが 380ms 以内だとダブルクリックになる。単発を続けるときは `waitForTimeout(500)`
- 指の操作は `PointerEvent` を `pointerType: "touch"` で `dispatchEvent`（7 番の項目が例）
- 確認は「状態が変わったこと」を見る（面数、座標、選択数）。見た目のスナップショット比較はしない
- 落ちたら先に **アプリのバグか手順のバグか**を切り分ける。今回はどちらも起きた（アプリ: マニピュレータの中心がクリックを吸っていた / 手順: 面を選ぶ前に判定していた）

### タスク 5: ベベル（Phase B1）

**目的:** 一番使われる未実装機能。**四角形メッシュ限定**で始める。

**core:** `src/core/bevel.ts`

```ts
export function bevelEdges(
  mesh: Mesh,
  edges: Array<[number, number]>,
  width: number,      // 元のエッジから新しいエッジまでの距離
  segments: number,   // 1 = 面取り、2 以上で丸め
): { mesh: Mesh; newFaces: number[] } | null
```

- 選んだエッジの両端を、隣接する各面の中へ `width` だけ後退させ、その間に帯を張る。頂点で複数のベベルエッジが集まる場合は、各面ごとに後退点を作って角の面で繋ぐ（Maya の既定と同じ）
- `segments >= 2` のときは帯を分割し、断面を円弧に置く（中心は両側の面法線の交点近似で足りる）
- **UV**: 新しい頂点の UV は元のコーナー UV を `width / エッジ長` で補間
- **クリース**: ベベルしたエッジのクリース値は捨てる（幾何で丸めたので不要）
- 境界エッジ、非四角形が混ざる場合は `null`（未対応を返す。壊れたメッシュを返さない）
- テスト: 立方体の 1 辺、4 辺（1 頂点に集まる 3 辺）、1 周（4 辺のループ）で、面数・頂点数・法線の向き（符号付き体積 > 0）・エッジの向きの整合を確認。`tests/primitives.test.ts` の向きチェックを再利用する

**app:**

- エッジの編集メニュー北東「ベベル」を実装。押すと **ベベルツール**に入り、マルチカットと同じく**ドラッグ中に予測表示**（黄色の線で新しいエッジ）、離して確定
- ドラッグの横移動 = 幅（画面上 100px でエッジ長の 50%）。オプションに幅とセグメント数（1〜8）のスライダー。オプションを動かしたら**確定後でも**作り直せるように、確定直前のスナップショットから再適用する（Maya の「ベベルノード」の代わり。履歴は 1 件にまとめる）
- `applyTopologyChange` を通す

通し確認に足す: 立方体の 1 辺を選んでベベル → 面数が増える → 取り消しで戻る。

### タスク 6: ターゲットウェルド（Phase B2）

- 頂点モードで、選択中の頂点をツイークでドラッグしている間、**他の頂点に近づいたら**（半径 22px、指は 1.8 倍）その頂点を光らせる
- 光っている状態で離したら、動かしていた頂点をその頂点へ溶接（`weldVertices` + `compact`）。光っていなければ普通の移動として確定
- 複数頂点を掴んでいる場合はやらない（1 つのときだけ）
- `applyTopologyChange` を通す。ラベルは「ターゲットウェルド」

通し確認に足す: 隣り合う 2 頂点で実行し、頂点数が 1 減る。

### タスク 7: マルチ解像度の検証 V1〜V3（**並行**。別ブランチでもよい）

`08` を **TypeScript の `src/core/multires.ts`** で実装する。C++ ではない。性能は問わない。

- `buildFrames(smoothMesh)`: 接空間フレーム。**必ず細分割で得た S(L) から**作る（`03` の 3.2）。参照接線は最小番号の隣接頂点へ向かうベクトルを法線に直交化したもの
- `subdivideWithDeltas(base, levels)`: `P(L) = Subdiv(P(L-1)) + T(L)·delta(L)`
- `captureDeltas(smoothMesh, editedMesh)`: 編集後のメッシュからデルタを逆算
- V1: 立方体を 3 レベル細分割し、既存の `subdivide` と頂点数・座標が一致
- V2: クリース 3 を 1 レベルごとに 1 ずつ減衰
- **V3（最重要）**: レベル 2 で頂点を法線方向に押し出してデルタを取り、レベル 0 を剛体変換（回転 + 平行移動）してから再構築したとき、押し出した形が**同じ剛体変換で移動しているだけ**であること（誤差 1e-5）。これが落ちたらデルタの表現が間違っている。**通るまでタスク 5・6 を止めてでも直す**
