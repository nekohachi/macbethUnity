## 0. 実機の声と、測った数字

> なんか重い気がする。これ以上軽くはならんの。Nomad とか結構軽く動くんやけど。

`33` の門（1 打ち 5.8ms、B6a 17ms）は**筆の重さ**を測っていた。それは通っている。
重いのは別の 2 つ。CI（ソフト GL）で 25 万四角形（458,880 三角形）を測った:

| 何 | ms（CI） | 中身 |
|---|---|---|
| **`refreshPositions`**（ペンを離すたび） | **764** | 面のジオメトリを丸ごと作り直す（1,376,640 頂点 + 法線）+ ワイヤー + 点 + BVH 全体の取り直し |
| 1 フレーム: シェード + ワイヤー（スカルプトの既定） | **631** | 面 1,376,640 頂点 + ワイヤー ≈ 920,000 頂点 |
| 1 フレーム: シェードだけ | 342 | ワイヤーを切ると **1.85 分の 1** |
| 1 フレーム: シェードだけ + 裏面を描かない | 220 | さらに **0.64 倍** |

CI の絶対値は意味がない（GPU が無い）が、**比は実機でも同じ向きに効く**。

### なぜ Nomad は軽いか

| | Nomad | いま |
|---|---|---|
| 面のジオメトリ | **インデックス付き**。頂点 1 つに位置 1 つ、法線 1 つ | **三角形ごとに頂点を複製**（コーナー数 = 三角形 × 3）。25 万四角形で **6 倍**の頂点 |
| 離したとき | 動いた頂点の法線だけ直す | **全部作り直す**（764ms） |
| 引いている間 | 法線も動く（陰影が付いてくる） | 法線は据え置き（離すまで陰影が古い） |
| ワイヤー | 既定で無し | 既定で有り（シェード + ワイヤー）。ワイヤーだけで 92 万頂点 |
| 裏面 | 描かない | 描く（`DoubleSide`） |

いまの複製形式は**モデリングのため**（ハードエッジ = 同じ頂点に違う法線）。
スカルプトの段（レベル 1 以上）は細分割の結果で**すべてスムース**なので、
複製する理由がない。

## T2. 離したときに全部作り直さない

### いま

`stroke.ts` の `end()` → `viewport.refreshPositions(o)`。面 / ワイヤー / 点の
ジオメトリを捨てて作り直し、BVH を全体で取り直す。25 万四角形で 764ms（CI）。

### 直し

`refreshMoved` はもう**動いた頂点の位置だけ**書き換えている（`29` の B-T6）。
離したときに足りないのは**法線**だけ。だから:

`viewport.refreshNormals(o, verts)`（新設）:

1. `verts`（ストロークで動いた頂点 = `Live.touched`）から、**動いた頂点を含む
   三角形**を集める。`buildVertexSlots` の `surfaceOffsets / surfaceSlots` が
   頂点 → コーナー番号を持っているので、コーナー番号 ÷ 3 が三角形。**新しい表は要らない**
2. 集めた三角形の面法線を作り直す（外積）
3. **それらの三角形の頂点すべて**（= 動いた頂点 + その 1 リング）の頂点法線を
   面法線の和から作り直す。1 リングの頂点は、動いていなくても隣の三角形が
   動いたので法線が変わる
4. スムージング角度は**レベル 1 以上なら無視して全部スムース**（細分割の結果は
   ハードエッジを持たない）。レベル 0 では `surfaceGeometry` と同じ角度判定
   （面法線どうしの内積 ≥ cosA）
5. 頂点法線を、その頂点のコーナーの `normal` 属性に書く（`surfaceSlots` の範囲）。
   `needsUpdate = true`

`end()` は `refreshPositions` の代わりに `refreshNormals(o, live.touched)` を呼ぶ。
BVH は `refreshMoved` が触った三角形だけ取り直している（`refitBvhPartial`）ので
そのままでよい。**`refreshPositions` はトポロジが変わったとき（段の上げ下げ、
モデリング）だけ**になる。

### 生成番号の控え

面法線は三角形ごとに 1 回だけ作る。三角形の集合は `Set` ではなく
**生成番号つきの控え**（`sculpt.ts` の `faceScratch` と同じ形）で重複を弾く。
頂点も同じ。`33` の T5 で `Map` / `Set` を消した理由と同じ。

### 極の表示・熱の表示

`display === "poles" / "heat"` は色の属性で、位置と独立。`refreshNormals` では
触らない。`polesStamp` もそのまま（トポロジは変わっていない）。

### テスト（`tests/` の app 側、`meshView` の単体）

- **`refreshNormals` の結果が `surfaceGeometry` の作り直しと一致**する
  （動いた頂点の周りで、法線の差が 1e-5 以下。動いていない所は触らない）
- 1 リングの外の頂点の法線は**書き換えない**（`needsUpdate` の範囲を見る必要は
  ないが、値が変わらないこと）
- レベル 0 でスムージング角度が効いている（立方体の角はハードのまま）

## T3. 引いている間も法線を直す

`flush()` で `refreshMoved` のあとに `refreshNormals(o, pending)` を呼ぶ。
T2 の関数そのまま。1 コマの動いた頂点は数千なので、数 ms で収まるはず。

**予算**: B6a（ストロークの 1 コマ）が **`38` の数字の 1.3 倍を超えたら**、
法線の更新を**コマを 1 つ飛ばし**にする（`flush` の偶数回だけ）。それでも
超えるなら T3 を外して T2 だけにする。**門は B6a ≤ 16ms（実機）**。

## T4. スカルプトの既定の表示

| 何 | 直し |
|---|---|
| 表示 | スカルプトに入ったら **`smooth`**（ワイヤー無し）。入る前の表示を `ui.displayBeforeSculpt` に控え、戻すときに戻す。スカルプト中に「表示」で変えたらそれを尊重（控えは入るときだけ書く） |
| 裏面 | スカルプトでは**既定で描かない**。`state.sculptCullBack`（既定 true）を足し、`applyDisplay` で `mode === "sculpt" ? sculptCullBack : cullBack` を見る。設定の「裏面を描かない」はモデリング用のまま。スカルプトの「表示」の長押しに「裏面を描かない」を足す（薄い板を彫る人のため） |
| 保存 | どちらも `localStorage`（`cullBack` と同じ道） |

ワイヤーは、スカルプトで見たい人が「表示」で `shadedWire` に戻せる。**極の
表示（`35`）はワイヤーが無くても色で分かる**ので困らない。

テスト（通し確認）: スカルプトに入ると `display === "smooth"`、戻すと元。
`?bench=1&size=25` の B4 の並びで B4c が一番小さい。

## T5. スカルプトの段はインデックス付きジオメトリ（T6 の結果次第）

### 考え

レベル 1 以上はすべてスムースなので、**頂点 1 つに位置 1 つ、法線 1 つ**で足りる。
`surfaceGeometry` に「インデックス付き」の道を足し、ワイヤーも**同じ位置属性を
共有**する `LineSegments`（`setIndex` で辺の 2 頂点）にする。three.js は
`BufferAttribute` を複数のジオメトリで共有できる。

| | いま | T5 |
|---|---|---|
| 面の頂点数（25 万四角形） | 1,376,640 | **≈ 230,000**（6 分の 1） |
| ワイヤーの頂点数 | ≈ 920,000 | **0**（面と共有。インデックスだけ） |
| `refreshMoved` の書き込み | 1 頂点 ≈ 6 スロット + ワイヤー ≈ 4 + 点 1 | **1** |
| GPU へ送る属性 | 位置 ×3（面 / ワイヤー / 点） | 位置 ×1 |

### 条件

- `activeLevel ≥ 1` のオブジェクトだけ（`viewport.meshOf(o)` が段の面を返しているとき）
- レベル 0 と、モデリングモードは**いままで通り**（ハードエッジが要る）
- `buildVertexSlots` は「スロット = 頂点番号そのもの」の退化した表になる。
  `refreshMoved` / `refreshNormals` の書き込み先を **`view.indexed` で分ける**
- UV（チェッカー）はコーナーごとなので共有できない。スカルプトの段でチェッカーを
  出すことは無いので、**インデックス付きでは `uv` を付けない**
- 極の色・マスクの色・熱の色は**頂点ごと**（いまはコーナーごと）。
  `applyPoles / applyMask / refreshMask / applyHeat` の書き込み先も分ける。
  熱は面ごとの色なので、インデックス付きでは出せない → スカルプトの段では
  熱の表示を断る（もともとモデリングの表示）

### 門との関係

**T4 までで 5 章の線を越えたら T5 はやらない**。T5 は `28` の S2-5（wasm と CSR）に
「描画のインデックス化」として送る。理由: T5 は `meshView` の全部の書き込み口を
2 系統にするので、`39` のブラシ直しと同時に触るとぶつかる。

## T6. 門

CI（25 万四角形、`?bench=1&size=25`）と、実機（MovinkPad、mini）の両方。

| 何 | 前（CI） | 門（CI） | 門（実機） |
|---|---|---|---|
| **B7a 離したとき** | 764ms | **≤ 30ms**（25 分の 1） | **≤ 16ms**（1 コマで消える） |
| B4 → B4c（ワイヤー無し + 裏面無し） | 631 → 220 | 0.4 倍以下 | 実機で B5（コマの間隔）が **≤ 16.7ms**（60fps） |
| B6a ストロークの 1 コマ | `38` の値 | **1.3 倍以内**（T3 の法線を含む） | ≤ 16ms |
| B7b | — | B6a + 法線 | ≤ 16ms |

**T5 をやるかの線: 実機の B5（スカルプトの既定表示、25 万）が 16.7ms を超えていたら
T5 をやる。** 超えていなければ S2-5 へ。実機の数字はユーザーに
`?bench=1&size=25` の JSON をもらう（`37` の 12 番と同じ）。

### 通し確認

- 彫って離しても `refreshPositions` を**通らない**（呼び出し回数を数える口を
  `viewport` に置く。`refreshPositionsCountForTest`）
- 離したあとの法線が作り直しと一致（T2 のテストを通し確認でも 1 回）
- スカルプトに入ると `smooth`、戻すと元
- 段の上げ下げは今まで通り `rebuildObject`（法線が正しい）

### 実機の確認項目（`37` の表に足す）

| # | 手順 | 期待 |
|---|---|---|
| 1 | 25 万で彫って**離す** | 引っかからない（前は離すたびに一瞬止まった） |
| 2 | 引いている間 | 陰影が付いてくる（前は離すまで平ら） |
| 3 | スカルプトに入る | ワイヤー無しのシェード。「表示」で戻せる |
| 4 | `?bench=1&size=25` | B4 / B4b / B4c / B5 / B6a / B7a の JSON |

## やらないこと

- wasm への移し替え、CSR（S2-5）
- 描画のインデックス化を**モデリング**にも広げる（ハードエッジの分け方を変えるので別）
- 頂点数を減らす（デシメーション）。段を下げれば軽い
- `estimateLevelBytes` の係数（S2-5）
