## 0. 実機の声

`38` を触ってもらった結果（2026-09-10）:

> フラットはいいがクレイはちょっと違うかも。
> ブラシは全体的に ZBrush を確認して違いをちゃんと直して。
> ムーブブラシも ALT キー中は減衰になるように。

`38` は「8 つ足す」ことを優先して、**それぞれの ZBrush での定義を一つずつは
裏取りしていなかった**。ここで全部を ZBrush のヘルプと突き合わせ、違う所を直す。

### 裏取りに使ったもの

| 何 | 出どころ |
|---|---|
| Standard は**筆の中心の法線 1 本**に沿って動かす。Inflate は**頂点ごとの法線**に沿う（だから Inflate は膨らみ、Standard は盛り上がる） | help.maxon.net「Sculpting Brushes」、thelasergirlsstudio「VERSUS: ZBrush Commands (Part II)」 |
| Clay は**平らな天面の層を盛る**。中心の高さより上には積まない。ClayBuildup は同じ考えで角ばったアルファ | help.maxon.net「Brush Types」、novedge「ClayBuildup tip」 |
| DamStandard は**既定で彫る**（ZSub）。ALT で盛る | novedge「DamStandard tip」、help.maxon.net |
| Move は**画面に平行な平面**の中で引く。**ALT を押すと法線に沿って**出し入れになる（引いた向きの画面上の成分で押す・引く）。Shift で表面に沿う（Move Topological 寄り） | help.maxon.net「Sculpting Brushes / Move」、polycount「ZBrush - Moving along the surface」 |
| Pinch は**接平面の中で**中心へ寄せる。法線方向には動かさない | help.maxon.net「Sculpting Brushes / Pinch」 |
| Flatten / Trim / Polish / Smooth は `38` の定義で ZBrush と合っている | 同上 |

## 1. 違いの一覧（読んで分かったもの）

| ブラシ | いま（`38`） | ZBrush | 直し |
|---|---|---|---|
| **ALT の反転** | `brush.invert` は `refresh()` でしか書かない。**ALT のボタンをタップ（`cycle`）しても反転しない**。物理 ALT を押しながら引いても、`refresh()` が挟まらなければ反転しない | ALT を押している間だけ反転 | **T1**。押した瞬間に読む |
| **Standard** | 頂点ごとの法線 | 中心の法線 1 本 | **T2** |
| **Inflate** | 頂点ごとの法線（Standard と同じ式。**違いが無い**） | 頂点ごとの法線 | そのまま（T2 で Standard と分かれる） |
| **Clay** | 平面より**内側だけ**を平面へ上げる。**平らな所に置いても何も起きない** | 平面の**上に厚み h の層**を盛る。h より上は積まない | **T3** |
| **ClayBuildup** | 頂点ごとの法線 | 層を盛る（Clay と同じ）。角ばったアルファで強い | **T3**（Clay と同じ式、減衰を角ばらせる） |
| **DamStandard** | 既定で盛る | **既定で彫る**。ALT で盛る | **T4** |
| **Move** | **表面の当たり点を追う**（指の下の面を滑る）。ALT で何も変わらない | 画面平面で引く。**ALT で法線に沿う** | **T5** |
| **Pinch** | 中心へ直線で寄せる（法線方向の成分も混じる） | 接平面の中で寄せる | **T6** |
| Flatten / Trim / Polish / Smooth | — | — | 変えない |

「ムーブも ALT で減衰になるように」の解釈: ZBrush の ALT + Move は**法線に沿った
出し入れ**で、表面の形を保ったまま押し込む・引き出す。「減衰」はこの「面に
沿って滑らず、中心から外へ減衰して持ち上がる」手触りのことだと読んだ。
**T5 で法線ムーブを入れ、実機で違えば聞く**（4 章の 5 番）。

## T1. ALT の直し

### いまの穴

`app.ts` の `buildCluster` の `cycle()` は `mods` を切り替えて `syncModButtons` と
`refreshStats` を呼ぶだけ。`brush.invert` は `refresh()`（≈5705 行）でしか書かない。
だから **ALT のボタンをタップしてから彫っても反転しない**（次に `refresh()` が
走るまで古い）。

### 直し

**押した瞬間に読む。** `stroke.ts` の `begin()` はもう `ctrl` / `shift` / `alt` を
`mods` から読んでいる（`34` の T3）。同じ場所で `invert` を決めて `Live` に置く。

```ts
// begin()
const alt = mods?.alt ?? this.state.modOn("alt");
...
this.live = { ..., invert: role === "sculpt" && alt, ... };
// stamp()
invert: live.invert,   // b.invert は読まない
```

- `state.brush.invert` と `refresh()` のその行は**消す**（読む所が無くなる）
- `app.ts` の pointerdown は `alt: this.state.modOn("alt") || e.altKey` を渡している
  （≈1317 行）。それで物理 ALT も拾える
- HUD の言い訳（`strokeHint`）は `state.modOn("alt")` を見ている。そのまま

### テスト

- `tests/brush.test.ts` か app 側の既存のテストに: `begin(p, 1, { alt: true })` で
  スタンダードを当てると、`{ alt: false }` と**逆向き**に動く
- 通し確認（`scripts/smoke.mjs`）: **ALT のボタンをタップ → 彫る → 引っ込む**。
  ボタンをもう一度タップ → 盛る。`refresh()` を挟まずに（タップの直後に
  pointerdown）

## T2. Standard は 1 本の法線

### 直し

`applyStroke` の Standard の枝で、頂点ごとの `normals[i]` ではなく
**範囲の法線を重みで足して 1 本にした向き**を使う。

```ts
// 範囲の平均法線（重み付き）。localPlane が同じものを作っているので、
// Standard も NEEDS_PLANE に入れて plane.normal を使えばよい
const [nx, ny, nz] = plane.normal;
p[v*3] += nx * w; ...
```

- `NEEDS_PLANE` に `"standard"` を足す。`localPlane` は法線の重み付き平均を
  正規化して持っている（`38` の T1）ので、**新しい関数は要らない**
- 裏面マスクは頂点ごとの法線で判定する（そのまま）
- Inflate は頂点ごとの法線のまま。**これで 2 つが違うものになる**

### なぜ

ZBrush の Standard は「中心の法線に沿って持ち上げる」ので、球の上で引くと
**盛った山の側面が中心の法線に平行**になる。頂点ごとの法線だと球は膨らむ
（それは Inflate）。

### テスト（`tests/sculpt.test.ts`）

- **球に Standard を 1 打ち: 動いたベクトルはすべて平行**（互いの外積の長さが 1e-3 以下）
- **球に Inflate を 1 打ち: 動いたベクトルは各頂点の位置ベクトルに平行**（半径方向）
- 既存の「真ん中がいちばん動き、半径の外は動かない」「invert で向きが反転する」は
  そのまま通ること

## T3. Clay は「層」を盛る

### いまの式

```ts
k = d < 0 ? -d * w * sign : 0;   // 平面より内側だけを平面へ
```

平面の内側（へこみ）を埋めるだけ。**平らな所では d = 0 で何も起きない**。
実機で「クレイはちょっと違う」と言われたのはこれ。

### ZBrush の Clay

平面の上に**厚み h の層**を盛る。層の天面より上にある頂点は動かさない。
へこみは天面まで埋まる（内側の頂点はより多く動く）。**重ねると層が積み上がる**
（次の打ちは、盛ったあとの表面から平面を取り直すので、天面がまた h 上がる）。

### 直し

```ts
const h = input.radius * DAB_DEPTH;         // 層の厚み。Standard の 1 打ちと同じ単位
// 盛る（既定）
//   天面 = 平面 + h。頂点が天面より下なら、天面へ向かって w の割合だけ上げる
//   k = w * max(0, h - d)
// 彫る（ALT）
//   底面 = 平面 - h。頂点が底面より上なら、底面へ向かって w の割合だけ下げる
//   k = -w * max(0, h + d)
```

- `d` は `signedTo(v)`（外が正）。平面はいまの `localPlane`（重み付き）のまま
- **天面より上の頂点（d ≥ h）は動かない**。これが「平らな天面」
- 平らな所では `k = w * h`。**Standard の 1 打ちと同じ深さ**（`DAB_DEPTH`）で
  盛るので、強さの手触りが揃う
- へこみ（d < 0）では `h - d > h` なので、**へこみのほうが多く上がる**（埋まる）

### ClayBuildup

同じ式で、**減衰を角ばらせる**（ZBrush のアルファ 39 に相当）:
`w = min(1, falloff(t) * 2) * strength` のように、中心の平らな領域を広げる。
頂点ごとの法線の枝からは外す（T2 のあと、Clay の枝に移す）。

### テスト

- **平らな板に Clay を 1 打ち: 中心が `strength * h` ほど上がる**（許容 20%）。
  `38` の「クレイは盛る」は残す
- **平らな板の上に高さ 2h の柱を立てておいて Clay: 柱の頂点は動かない**
- **へこみ（球状の穴）に Clay: 穴の底の上がる量 > 縁の上がる量**
- **ALT で符号が反転**（平らな板が下がる）
- **ClayBuildup は Clay より中心の平らな領域が広い**（中心から `0.4r` の点の
  動きが `0.9 × 中心` 以上）

## T5. Move: 画面平面で引き、ALT で法線に沿う

### いまの穴

`stroke.ts` の `move()` は `hitLocal(p)` で**表面の当たり点**を追っている。
指の下の面を滑るので:

- **模型の外へ引き出せない**（指がシルエットの外に出ると当たりが無くなり、止まる）
- 引いた向きは表面に沿う。鼻を前へ出したいのに、頬の上を滑る

ZBrush の Move は**押した点を通る画面に平行な平面**の上で引く。表面に沿わない。

### 直し（画面平面）

`begin()` でムーブなら、押した点（ワールド）を通り、カメラの前方を法線にした
平面を `Live.dragPlane` に置く。`move()` でムーブなら `hitLocal` を使わず、
**画面点 → その平面との交点**を取って差分を渡す（`app.ts` ≈1593 行、
`tools/transform.ts` の `Plane().setFromNormalAndCoplanarPoint` + `ray.intersectPlane`
と同じ道具）。オブジェクト空間へは `group.matrixWorld` の逆で。

- 指が模型の外に出ても引き続ける
- 動かす頂点は**押した瞬間の範囲**（`strokeFootprint` を押したときに 1 回だけ取り、
  `Live.moveFootprint` に持つ）。いまは毎回範囲を取り直しているので、
  引いている途中で範囲が滑って**別の頂点を掴み直す**。ZBrush は押した瞬間の
  頂点を最後まで掴む
- 重みも押した瞬間に 1 回計算して持つ（頂点が動いても重みは変えない）

### 直し（ALT で法線に沿う）

ALT のときは、押した点の範囲の**平均法線 1 本**（T2 の `plane.normal`）を
`Live.moveNormal` に持つ。動かす量は:

```
amount = 引いた差分（ワールド）· 法線の画面射影の向き
```

具体的には、法線を画面へ射影して単位ベクトル `s` を作り、画面上の指の差分
（px）を `s` に射影した長さを、押した点の奥行きでワールド単位へ直す。
法線が画面にほぼ垂直（射影の長さ < 0.2）なら**画面の上向き**を `s` にする
（ZBrush もこのときは上が「出す」）。頂点は `normal * amount * w` だけ動く。

- Shift（表面に沿う）は作らない。Shift はこのアプリでは「一時スムース」

### applyStroke 側

`move` の枝はそのまま（`input.move` をワールドの差分として使う）。**法線ムーブも
`input.move = normal * amount` を渡すだけ**なので core は変えない。
core を変えないぶん、`stroke.ts` の `Live` とムーブの `move()` の分岐が増える。

### テスト

- core: 変えない（既存の Move のテストが通ること）
- app（`tests/brush.test.ts` か通し確認）:
  - **ムーブで指を模型の外まで引くと、引いた分だけ頂点が動く**（止まらない）
  - **正面から見て、球の前面をムーブで右へ引くと、動いた頂点の変位はほぼ画面の右**
    （表面に沿わない。奥行き成分が変位の 10% 以下）
  - **ALT + ムーブで右へ引くと、動いた頂点は押した点の法線に平行に動く**
  - **押した瞬間の頂点を最後まで掴む**（引いている途中で動いた頂点の集合が増えない）

## T6. Pinch は接平面の中で寄せる

`applyStroke` の pinch の枝で、中心へ向かうベクトルから**頂点の法線成分を引く**。

```ts
const ex0 = cx - px, ...;
const dn = ex0*nx + ey0*ny + ez0*nz;   // 法線成分
ex = (ex0 - nx*dn) * w; ...
```

`NEEDS_NORMAL` に `"pinch"` を足す。

テスト: **球に Pinch を 1 打ち: 動いた頂点の変位はその頂点の法線に直交**
（内積の絶対値が変位の長さの 5% 以下）。既存の「中心へ寄せる」は接平面上の
距離で見るよう直す。
