## T1. 「レイヤー」→「アウトライナ」。常にドロワー、ビューポートは全幅

### 決め

- 名前を**アウトライナ**に戻す。`19` の 3.3 で Procreate のレイヤーに寄せたが、中身はオブジェクトの一覧であってレイヤー（描画の重なり）ではない。名前が実体に合っていないと、あとで本当のレイヤー（マテリアルのペイントレイヤー）が来たときに衝突する
- **画面の幅に関わらずドロワー**にする。今は 1200px 以上でドッキング（`placeLayers` の `isWide` 分岐）になっていて、その分ビューポートが 236px 狭い。ユーザー指示: 「スライドインするようになった分、描画領域を広げて」
- 右のドック列（`#dockColRight`）は**空になるので消す**（`hidden`）。ビューポートがそのぶん広がる。`Layout` のつまみ（`dockgrip`）は列が空なら自分で隠れるので触らなくてよい
- ドロワーの幅は 236px のまま。出し方も今のまま（上段のボタン / 右端から左へスワイプ / 外を触ると閉じる）。**Esc でも閉じる**（PC 用）
- ツール列のドッキング（`zones.tools`）は残す。`zones.outliner` は読まなくなる（保存されていても無視）

### app

- `web/index.html`: `btnPanels` の文字を「アウトライナ」。アイコンはそのまま（層の絵で構わない。行の並びを表す）
- `app.ts`: `buildPanels` の `panelShell("layers", "アウトライナ")`。`placeLayers` の `isWide` 分岐を消して常にドロワーへ。`toggleLayers` の `isWide` 分岐も消す（`state.panelsHidden` はもう使わない）。`syncLayersButton` はドロワーの開閉だけを見る。`bindLayerSwipe` はそのまま
- `#dockColRight` を `hidden` に（`buildPanels` で）。`viewport.resize()` を呼ぶ
- 名前の付いた関数名（`placeLayers` / `toggleLayers` / `renderLayers` / `.lyrow` など）は**変えなくてよい**。見た目の文字だけ直す。HUD のトースト・`docs` の言い回しは「アウトライナ」
- `Layout.isWide` は残してよいが、呼ぶところが無くなるなら消す

### 通し確認（既存 1 項目を書き換え）

「レイヤー: 狭い画面は右からのドロワー、広い画面はドッキング」→ **「アウトライナ: どの幅でもドロワー、ビューポートは全幅」**: 1280px でボタンを押す → `.drawer.open` がある → `#gl` の幅が `#vp` の幅と同じ（ドロワーが乗っているだけで縮んでいない）→ 外を触って閉じる → `#dockColRight` が `hidden`。

## T2. アウトライナの長押しサークルメニューと、なぞりの複数選択

### 何が起きているか

`attachOutlinerRow` は「420ms 押すと**並び替え待ち**になり、動かさずに離すとメニュー」という作りになっている。指で押すと離すまでに数 px 動くことが多く、それが並び替えに取られてメニューまで届かない。長押しと並び替えを同じ指に載せたのが原因。

### 決め

| 操作 | 何が起きるか |
|---|---|
| タップ | その行だけを選ぶ（今のまま） |
| ダブルタップ | 名前の変更（今のまま） |
| **長押し（420ms、動かさない）** | **その場にサークルメニュー**。指を離さずに方位へ引いて選べる（ツール列の `attachRadialButton` と同じ作法）。メニューが出たあとの動きは並び替えにしない |
| **並び替え** | 行の**右端のつまみ（⋮⋮）をドラッグ**。つまみ以外を押しても並び替えは始まらない。つまみは `Docking` の `grip` と同じ絵 |
| **SHF + タップ** | その行を追加 / 外す（`state.addObject`）。3D の Shift + クリックと同じ |
| **F を押しながら行をなぞる** | 押し始めた行から今の行までを**まとめて選ぶ**（3D の「F を押しながらドラッグで矩形選択」と同じ規則）。離した行が `selected`、残りは `also` |
| 縦にドラッグ（F なし） | **一覧がスクロールする**。今は `.lyrow` に `touch-action:none` が付いていて指でスクロールできない。`pan-y` に直す |

サークルメニューの中身（8 方位）:

| 方位 | 項目 | 何をするか |
|---|---|---|
| 北 | 名前変更 | `startRename` を呼ぶ（今の「ダブルタップでも」のトーストではなく、その場で入力にする） |
| 北東 | 複製 | `doDuplicate` |
| 東 | 結合 | `doCombine`（2 つ以上選んでいないと「2 つ以上選んでください」） |
| 南東 | 分離 | `doSeparate` |
| 南 | 削除 | `doDelete` |
| 南西 | フレーム | `frameSelected` |
| 西 | 中心にピボット | `doCenterPivot` |
| 北西 | アトリビュートの転送… | T6 のカットインを開く。T6 まではトースト「T6 で入ります」 |

メニューを開いた行が `selected` に入っていなければ、まずその行を選んでから（今の `this.state.select(o)` の前置きと同じ）。**入っていれば選択は変えない**（複数選んで結合したいので）。

### app

- `panels.ts` の `attachOutlinerRow`: 長押しは `openRadial` を**押している最中に**出す。`app.ts` の `attachRadialButton` と同じ骨格（`pointerdown` → タイマー → 出す → `pointermove` で方位 → `pointerup` で実行）。`host.onOutlinerMenu(o, x, y)` は「メニューの定義を返す」形に変えてよい（`onOutlinerMenu(o): RadialMenu`）
- つまみ（`.lygrip`）を行の右端、「>」の左に置く。ドラッグの処理は今の `holding` の中身をそこへ移す
- なぞり: `host.frameHeld(): boolean`（クラスターの F が押されているか。3D の矩形と同じ状態を見る）。押されていれば `pointermove` で行の範囲を更新し、`host.onSelectRange(from, to)` を呼ぶ
- 行の見た目: `also` に入っている行も `aria-selected="true"`。`selected` の行には `data-primary="true"` を足して、少し濃く（`shell.css`）
- `renderLayers` に `also: Set<SceneObject>` を渡す

### 通し確認（2 項目）

1. 「アウトライナの長押しでサークルメニュー」: 行を `pointerdown` → 450ms → `.radial` がある → 北へ引いて離す → 名前の入力（`.olinput`）が出ている。つまみ以外を 20px 動かしても並びが変わらない
2. 「アウトライナで複数選択できる」: 立方体 3 つ → SHF をオンにして 2 行目をタップ → `state.also.size === 1` → SHF を切って F を押しながら 1 行目から 3 行目までなぞる → `selectedObjects().length === 3`、`aria-selected` の行が 3 つ → 長押しメニューの東（結合）→ オブジェクトが 1 つに

## T3. 左レールの第 2 ゲージ: 「範囲」と「拡張」の切り替え

### ユーザーの質問への答え

> ソフト選択は強度だけで大抵事足りるので、第 2 ゲージ（範囲）を「選択の拡大縮小」のスライダーに置き換えたい。それか、ソフト選択のオン / オフで UI が切り替わる形はできないか。

**後者にする。強度が 0（ソフト選択オフ）のとき第 2 ゲージは「拡張」、0 より大きいとき「範囲」。**

理由:

- 範囲は「効いているときだけ意味がある」値。ソフト選択がオフのときの範囲ゲージは、今も薄く表示しているだけの死んだ場所。そこに拡張を置けば、ゲージを増やさずに済む
- ソフト選択がオンのときに拡張を使うことは少ない（Maya でも、ソフト選択中はもっぱら範囲を触る）。逆に範囲をカットインの奥へ追いやると、ソフト選択で頂点を引くたびにカットインを開くことになる
- 強度ゲージがすぐ上にあるので、切り替えは指 1 本分。「強度を 0 に戻すと拡張が現れる」は 1 回触れば覚えられる
- レールの役割「強度と範囲 / サイズ」（`09`）は崩さない。スカルプトとマテリアルのレールは今のまま

### 「拡張」ゲージの動き（バネ式）

普通のゲージは絶対値だが、拡張は**相対値**（今の選択から何段広げる / 狭めるか）なので、**離すと中央に戻るバネ式**にする。

| | |
|---|---|
| 目盛り | 中央が 0。上へ +1 … +8、下へ −1 … −8（整数） |
| 押した瞬間 | 今の選択を `base` として控える |
| 引いている間 | 中央からの距離を段数 n に丸める。n > 0 なら `base` から `grow` を n 回、n < 0 なら `shrink` を |n| 回。**毎回 `base` から計算し直す**（行って戻ったときに元の選択に戻るように） |
| 離したとき | 選択はそのまま。ゲージは中央（0）へ戻る。`base` は捨てる |
| 表示 | 値は「+3」「−1」「0」。塗りは中央から上または下へ伸びる |
| 効かないとき | オブジェクトモード、選択が空。薄く表示（`data-off`）してタップでトースト「コンポーネントを選んでください」 |

指 3 本のつまみ（今の拡大縮小）は残す。両方あって困らない。

### app

- `state.ts`: `GAUGES.model.g2` を 1 つの定義ではなく**関数**にする。`gauge(which)` が `which === "g2" && mode === "model"` のとき `soft.strength > 0 ? RANGE : GROW` を返す。`GaugeDef` に `kind: "absolute" | "spring"` を足す。`spring` の定義は `get` / `set` の代わりに `onDrag(state, n)` と `onRelease(state)` を持つ
- `gauges.ts`: `spring` のときの描画（中央から）と、`pointerdown` で `base` を控える処理。`n` は `Math.round((t - 0.5) * 2 * 8)`。`base` からの再計算は `selector.growOrShrinkFrom(base, n)` を `select.ts` に足す（今の `growOrShrink` を 1 段 = n 回の繰り返しに一般化）
- 強度ゲージを動かしたとき（`onInput`）に**第 2 ゲージも `paint()`**する。0 と 0 以外を跨いだ瞬間に見出しが「範囲」⇄「拡張」に変わる
- 「選択」のカットイン（`softSelectSection`）: 強度 / 範囲のスライダーはそのまま。**「拡張」の横向きバネ式スライダー**を足す（同じ `spring` の部品を横にしたもの。`paramRow` とは別に `springRow` を作る）。ユーザー指示: 「オプションには範囲、強度、拡張すべてのスライダーがある」

### 通し確認（1 項目）

「レールの第 2 ゲージが範囲と拡張で切り替わる」: 強度 0 で `#g2lbl` が「拡張」→ 球の面を 1 つ選んで第 2 ゲージの上のほうを押す → 面が増える（`comp.size > 1`）→ 押したまま中央へ戻す → 1 に戻る → 離す → ゲージの値が「0」→ 強度を 0.5 にする → `#g2lbl` が「範囲」。

### 左利き（鏡映し）

`document.documentElement.dataset.hand = "left"` を立てて、**CSS だけ**で裏返す。JS で位置を計算しているところだけ手を入れる。

| 場所 | 右利き（今） | 左利き |
|---|---|---|
| `.stage` | レール / ツール列 / ビューポート | `flex-direction: row-reverse`。縦持ち（`grid`）は列の順を入れ替える |
| クラスター（SHF / F / CTL / ALT） | 左下 | 右下（`left` → `right`） |
| ヒント（`.hud-hint`） | 左 150px から | 右 150px から |
| ポリゴンカウント（`.hud-stats`） | 左上 | 右上 |
| モード表示（`.hud-mode`） | 右上 | 左上 |
| アウトライナのドロワー | 右から | **左から**（`transform: translateX(-100%)`、`bindLayerSwipe` は左端から右へ） |
| カットイン | ボタンの右に開く | ボタンの**左**に開く（`openToolOptions` で `data-hand` を見て `left` / `right` を入れ替える） |
| 上段 | そのまま | そのまま（読む順は変えない） |
| サークルメニュー / マニピュレータ | そのまま | そのまま（指の位置に出るので） |

- `web/index.html`: `viewBtn` を足す。`app.ts`: `openViewMenu(anchor)`（`openModeMenu` を写す）。行は `checkbox` を流用
- `hud.ts`: `defaultHint` が `state.ui.hints` を見る。`refreshStats` が `state.ui.stats` で `#hudStats` の `hidden` を切り替える
- `shell.css`: `:root[data-hand="left"]` の下に上の表。**両方の向きで同じ見た目になることを PNG で確かめる**（`24-t4-left.png`）
- `openToolOptions` / `openGroupOptions` の位置計算に `hand` を足す

## T5. UV のツール列の整理

### 5.1 チェッカーの細かさをスライダーに

- `checkerSection` の細かさ: 4 / 8 / 16 / 32 / 64 の segmented を**スライダー（2〜64、刻み 1）**に。数字はそのまま出す。模様（市松 / カラーグリッド）の segmented はそのまま
- スライダーを動かしている最中にテクスチャを作り直すと重いので、**`change`（離したとき）で作り直し、`input` の間は数字だけ**動かす
- `state.checker.cells` は整数のまま。`localStorage` の読み戻しは 2〜64 の範囲に丸める（今の `[4, 8, 16, 32, 64].includes` を範囲チェックに）

### 5.2 「UV オプション」のツールアイコン

今は「展開」の長押しの西「オプション…」の奥にある。**毎回そこから開くのは遠い**ので、ツール列の UV 区画に**ボタンを 1 つ足す**。

| | |
|---|---|
| id | `uvopts` |
| アイコン | `ICONS.options`（新。横線 3 本につまみ = スライダーの絵） |
| タップ | 今の `uvUnfoldOptions()` がカットイン（歪み / チェッカー / パッキング / 詳細 / UV スナップ） |
| 長押し | 無し |
| 位置 | UV 区画の**最後**（展開 / カット・ソー / フレーム / **UV オプション**） |

「展開」の長押しから西「オプション…」を**外す**。残りは 北 展開 / 東 自動 UV / 南 整列 / 南西 歪みを色で。

### 5.3 カットとソーを 1 グループに

`21` の規則（1 ボタン = 1 グループ、長押しで中身、アイコンは最後に使ったもの）を UV 列にも当てる。

| | |
|---|---|
| id | `cutsew`（`cut` と `sew` のボタンを消してこれ 1 つに） |
| 中身（長押し） | **北 カット** / **東 移動して縫う**（Move and Sew） / **南 その場で縫う**（Sew。動かさずに切れ目を消す）。西は空き |
| アイコン | 最後に使ったもの（`state.lastUvCut: "cut" \| "moveSew" \| "sew"`。既定 `cut`。`localStorage`） |
| タップ | **最後に使ったものを実行する**。`21` の「編集」グループはコマンドのタップでオプションを出すが、カット / ソーは毎回使うコマンドで、オプションも無いので**実行にする**（今のカットボタンと同じ）。この違いは `21` の 1.1 に追記しておく |
| 頂点単位のとき | 「移動して縫う」は「その場で縫う」と同じ動き（今の `uv.unit === "vertex" ? cutOrSew(false) : moveAndSew()` のまま） |

マーキングメニュー（`uvSelectMenu` の南東 / 南西、`uvEditMenu` の北東 / 東）は今のまま。

### 通し確認（2 項目）

1. 「チェッカーの細かさはスライダー」: 展開のカットイン（`uvopts` をタップ）に `input[type=range]` の細かさがある → 24 にして `change` → `state.checker.cells === 24`、2D の下地が作り直されている
2. 「カットとソーは 1 つのボタン」: UV 列に `cut` / `sew` のボタンが無く `cutsew` がある → 長押し → 北 / 東 / 南 の 3 つ → 東（移動して縫う）を選ぶ → アイコンが変わり `state.lastUvCut === "moveSew"` → 球の赤道を切ってから `cutsew` をタップ → 島が 1 つに戻る（既存の手順 C と同じ結果）

## T6. アトリビュートの転送（Maya の Transfer Attributes）

### 何をするか

あるオブジェクトの**頂点の位置**や **UV** を、別のオブジェクトへ写す。使いどころ:

- 分割数を変えて作り直したプリミティブに、前に展開した UV を戻す（**ワールド**）
- 同じトポロジの複製どうしで UV を揃える（**コンポーネント**）
- 荒いメッシュを、細かいメッシュの形に吸い付かせる（位置の**ワールド**転送 = シュリンクラップ）

### 決め

| 項目 | 決め |
|---|---|
| 元と先 | **先（target）= `state.selected`（最後に選んだもの）、元（source）= `also` の 1 つ**。Maya も「先に元、最後に先」。`also` が 2 つ以上なら「元は 1 つだけ選んでください」 |
| 転送するもの | **位置** / **UV**（チェック。既定は UV だけオン） |
| サンプル空間 | **コンポーネント**（番号で写す。トポロジが同じときだけ）/ **ワールド**（先の頂点ごとに、元の面のいちばん近い点を取る）/ **ローカル**（同じことをそれぞれのローカル座標で）。既定はワールド。**UV 空間は今回やらない**（下） |
| UV の写し方 | ワールド / ローカル: 近い点を含む三角形の 3 コーナーの UV を重心座標で混ぜる。**先の頂点の全コーナーに同じ UV**を入れる（切れ目は失われる。元の切れ目をまたぐ頂点は片側の UV になる。Maya も同じ） |
| 先の UV レシピ | 写したあと `target.uv = recipeFromMesh(target.mesh)`（方式 `none`、切れ目は UV から取り直す）。`uvHeat = null` |
| 位置の写し方 | ワールド: 近い点（ワールド）を先のローカルに戻して `positions` に書く。ローカル: 変換無しで同じ |
| 先にマルチレゾやスカルプトレイヤーがあるとき | 「先のマルチレゾを捨ててから実行してください」で止める（対応関係が壊れるため。`markTopologyChanged` は使わない） |
| 履歴 | 「アトリビュートの転送」1 段 |
| 入口 | アウトライナの長押しメニュー北西（T2）。オブジェクトモードのマーキングメニューは 8 方位が埋まっているので**入れない** |

### core

`core/transfer.ts`（新）:

```ts
export type SampleSpace = "component" | "world" | "local";

export interface TransferOptions {
  positions: boolean;
  uvs: boolean;
  space: SampleSpace;
}

export interface TransferSource {
  mesh: Mesh;
  transform: Transform;
}

export interface TransferResult {
  /** 先の頂点ごとの新しい位置（先のローカル座標）。`positions: false` なら無し。 */
  positions?: Float32Array;
  /** 先のコーナーごとの新しい UV。`uvs: false` か元に UV が無ければ無し。 */
  uv?: Float32Array;
  /** 対応が取れた先の頂点の数。 */
  matched: number;
}

/**
 * 元のメッシュの位置 / UV を、先のメッシュへ写す。先は変えず、結果だけ返す。
 * コンポーネント空間でトポロジが合わないときは null。
 */
export function transferAttributes(
  source: TransferSource,
  target: TransferSource,
  options: TransferOptions,
): TransferResult | null;
```

手順:

1. **コンポーネント**: `vertexCount` / `faceCount` / 面ごとの `faceSize` がすべて一致することを確かめる。合わなければ null。位置は頂点番号で、UV はコーナー番号でそのまま写す
2. **ワールド / ローカル**: 元を `triangulate()` して、三角形ごとに 3 点の座標（ワールドなら `transform` を掛けたもの）を並べる。先の頂点ごとに**いちばん近い三角形上の点**（点と三角形の最近点。辺・頂点に落ちる場合も含む）を求め、重心座標 `(w0, w1, w2)` を出す
3. 位置: 最近点を先のローカル座標に戻す（ワールドのとき）。UV: 三角形の 3 コーナーの UV を `w` で混ぜる。三角形は面ごとの扇なので、コーナーは `faceOffsets[f] + [0, i+1, i+2]`（`meshView.ts` の `surfaceGeometry` と同じ読み方）
4. 三角形が多いときの当たりの取り方: **まず総当たり**で作り、`tests` で 3000 頂点 × 2000 三角形の時間を測る。100ms を超えるなら、元の三角形を**一様グリッド**（1 辺を 32 分割、三角形の AABB で登録）に入れて、先の頂点の近くのセルから探す。最初から凝らない

### app

- `app.ts`: `openTransferOptions()`。カットイン（`.cutin`）の中身は `transferSection(state, host)`（`panels.ts`）:
  - 見出しに「**Sphere1 → Cube2**」（元 → 先）。横の **⇄** ボタンで入れ替え（`selected` と `also` の 1 つを入れ替える）
  - チェック: 位置 / UV
  - segmented: コンポーネント / ワールド / ローカル
  - ボタン「実行」
  - 元が 1 つに決まらないときは見出しに「元を 1 つ選んでください」でボタンを無効に
- `state.transfer = { positions: false, uvs: true, space: "world" }`。`localStorage`
- 実行: `history.push("アトリビュートの転送")` → `transferAttributes` → null なら「トポロジが違います（コンポーネント空間は同じ分割のときだけ）」→ 位置を書いたら `viewport.rebuildObject`、UV を書いたら `recipeFromMesh` と `uv?.rebuild()` → トースト「転送 — 頂点 N / 一致 M」

### vitest（`tests/transfer.test.ts`、4 件）

1. **コンポーネント**: 立方体を 2 つ。元の UV を全部 ×0.5 にしてから `uvs: true, space: "component"` → 先の `uv` が元と一致（`1e-6`）。位置は変わっていない
2. **ワールドで UV**: 平面 2×2（元、UV 0〜1）と平面 4×4（先、同じ大きさ）→ `space: "world"` → 先の各コーナーの UV が、その頂点の (x, z) から期待する値（`x + 0.5`, `z + 0.5` の形）と `1e-3` で一致
3. **ワールドで位置**: 球（元）と、同じ球の頂点を法線方向に ±0.1 ずらしたもの（先）→ `positions: true` → 先の全頂点の原点からの距離が `1 ± 1e-3`（元の半径に戻る）
4. **トポロジ違いのコンポーネント**: 立方体 → 球で `space: "component"` → null

### 通し確認（1 項目）

「アトリビュートの転送」: 立方体 2 つ → 元の UV を UV モードで ×0.5 に（`uv.transformSelection` か `map1` を直に）→ モデリングへ戻り、元 → 先の順に選ぶ（`state.select(source)` → `state.addObject(target)` … `selected` が先になるように）→ アウトライナの長押し北西 → カットインに「Cube1 → Cube2」→ コンポーネントで実行 → 先の `map1` が元と一致 → 取り消しで戻る。**PNG は 2 枚**（転送前 / 後をチェッカー表示で）。

## 決めてあること（追加分）

- **アウトライナはどの幅でもドロワー。** PC の「出しっぱなし」は捨てる。理由: ビューポートを広く使うほうが価値が高い。PC でもボタン 1 つで出る
- **並び替えはつまみ。** 長押しはメニューに専念させる。Procreate の「長押しで持ち上げ」より、つまみのほうが誤操作が無い
- **拡張ゲージはバネ式。** 絶対値のゲージにすると「何に対しての段数か」が決まらない
- **左利きは CSS の鏡映し。** JS で位置を計算しているのはカットインとスワイプの 2 か所だけ
- **カット / ソーのタップは実行。** `21` の「コマンドのタップはオプション」の例外。オプションを持たない、毎回使うコマンドだから
- **転送の元は `also`、先は `selected`。** Maya と同じ「先に元、最後に先」

## やらないこと

- 転送の **UV 空間**（先の UV の位置で元の位置を引く。ラップに使う）。位置と UV のワールド転送が先
- 転送の**法線 / 頂点カラー**（データが無い）
- アウトライナの**階層 / グループ**（`19` の 3.4 のまま）
- レイヤーという名前の**本当のレイヤー**（マテリアルモードのペイントレイヤー）。名前をここで空けておく
- 左利きでの**上段の並び替え**

### 設計と変えたところ

- **`frameSelected` を直した（指示書に無い。T1 の巻き添え）。** ビューポートが 236px 広がったことで、パースの**縦の画角が狭くなった**（three.js は焦点距離とフィルムゲージから縦の画角を出すので、横長になるほど縦が狭い）。今までの `size * 2.4` では立方体の角が画面の外に出てしまい、通し確認の「カメラベース選択」が 7 点 → 6 点に落ちた。選択を包む球が入る距離（`radius / sin(半画角)` に 1.1 の余白）を下限に足した。今までの画角では値が変わらないので、既存の見え方は動いていない

- **アウトライナに閉じるボタン（×）を足した（指示書に無い）。** 外を触っても閉じるが、それだと 3D の選択も動く。選択を変えずに閉じる手がいる
- **ドッキングの掴み手をアウトライナから外した。** ドロワー専用なので、掴めるとドックへ落ちて行方不明になる。ツール列のドッキングは今までどおり
- **`onOutlinerMenu(o, x, y)` を `outlinerMenu(o): RadialMenu` に変えた**（指示書どおり）。開く場所は行の側が決める
- **`onSelectRange` は id の並びで受ける**（指示書は `from` / `to` の番号）。一覧は追加の逆順で出しているので、番号だと上下がひっくり返って読みにくい
- **`setPointerCapture` を try / catch で囲んだ。** 合成した入力では捕まえられずに例外になる（通し確認で踏んだ）

1. **アウトライナは PC でもドロワー**（指示書どおり）。出しっぱなしにしたいなら戻せます
