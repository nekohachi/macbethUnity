
# 04. 入力・ジェスチャ・UI 設計

## 4.1 大原則: ペンとタッチの役割を分ける

ご要望の操作系を成立させる最重要の決定がこれです。

> **ペン ＝ ツール（スカルプト、選択、描画） / 指 ＝ カメラ操作**

この分離により、モード判定の曖昧さがほぼ消滅します。ZBrush for iPad、Nomad Sculpt、Forger がすべてこの方式を採るのは、これが実質的な正解だからです。

補足すると、**指でもツールが使えるべき場面はあります**（ペンを持っていないとき、UI パネル操作時）。そこで次の設定を用意します。

- 「ペンのみツール」モード（既定、ペン所持時）
- 「指でもツール」モード（1本指＝ツール、2本指＝カメラ。ペン非所持時の既定）

パネルや UI 上では常に指もペンも同じように操作できます（ご要望どおり）。

## 4.2 カメラ操作の仕様

ご指定の内容を仕様化しました。

| ジェスチャ | 動作 |
|---|---|
| 2本指ピンチ | ズームイン／ズームアウト（ドリー） |
| 2本指スワイプ | 平行移動（パン） |
| 1本指スワイプ | タンブル（回転） |
| 2本指回転（ひねり） | ビューのロール ※既定はオフ推奨 |
| 2本指タップ | 1つ戻る（Undo）※ Nomad 互換、任意 |
| 3本指タップ | 1つ進む（Redo）※任意 |

**2本指ロールは既定でオフを推奨します。** パンやピンチの最中に意図せずロールが混入し、水平が狂ったという苦情が非常に多い機能です。設定で有効化できるようにします。

### タンブルの回転中心（ピボット）

ここが操作感を左右します。優先順位で決定します。

1. 頂点や範囲を選択中 → **選択範囲のバウンディングボックス中心**（ご要望どおり）
2. 選択なし、指の下にモデルがある → **指の下のサーフェス上の点**をレイキャストで取得
3. 指の下が何もない（オブジェクト外） → **オブジェクトのバウンディングボックス中心**
4. オブジェクトなし → ワールド原点

2 番目の「指の下の点をピボットにする」が体感的に最も自然です。ZBrush と Nomad がこれを採用しています。ピボットはジェスチャ開始時に一度だけ確定し、ドラッグ中は固定してください（毎フレーム更新すると滑ります）。

### ジェスチャ調停（アービトレーション）

1本指と2本指の判定には遷移の猶予が必要です。1本指で動き始めた直後に2本目が着いた場合、パンに切り替えるのが自然です。

```
接触開始
  → 80ms の判定ウィンドウ内に 2 本目が着いたら 2 本指ジェスチャとして開始
  → 1 本指ジェスチャ開始後でも、移動量 20px 未満なら 2 本指へ昇格を許可
  → それ以降は 2 本目が着いてもタンブルを継続（誤爆防止）
```

## 4.3 プラットフォーム固有の入力（ネイティブプラグインが必須）

ネイティブ C++ を選択したため、以下の API に**ブリッジを挟まず直接到達できます**。これがネイティブ路線の最大の恩恵の一つです（`02-architecture.md` 2.8）。

### iOS（Objective-C / Swift）

`UITouch` から以下を取得します。

| 情報 | API | 用途 |
|---|---|---|
| ペンか指か | `UITouch.type == .pencil` | 役割分離の判定そのもの |
| 筆圧 | `force` / `maximumPossibleForce` | ブラシ強度・半径 |
| 傾き | `altitudeAngle` | ブラシの傾き対応 |
| 方位 | `azimuthAngle(in:)` | アルファのスタンプ回転 |
| ホバー | `UIHoverGestureRecognizer` | Pencil 2以降のカーソル予告表示 |
| ダブルタップ | `UIPencilInteraction` | ブラシ／消しゴム切り替え |
| スクイーズ | `UIPencilInteraction`（Pencil Pro） | サークルメニュー呼び出しに最適 |

**さらに重要なのが次の2つです。**

- `coalescedTouches(for:)` — 描画フレーム間に発生した入力サンプルをすべて取得できます。60fps で描くと入力が間引かれてストロークがカクつきますが、これを使うと全サンプルが拾えて線が滑らかになります。
- `predictedTouches(for:)` — 数フレーム先の入力を予測して先行描画します。**体感遅延がはっきり減ります。**

この 2 つは、ゲームエンジン経由では到達できないかブリッジの自作が必要になる部分です。Objective-C++ で `UIResponder` を直接実装すれば、そのまま使えます。「快適な操作」を実現するうえで最も費用対効果が高い実装なので、優先度を高くしてください。

### Android（Java / Kotlin）

`MotionEvent` から取得します。

| 情報 | API |
|---|---|
| ペンか指か | `getToolType()` が `TOOL_TYPE_STYLUS` か `TOOL_TYPE_FINGER` |
| 筆圧 | `getPressure()` |
| 傾き | `getAxisValue(AXIS_TILT)` |
| 方位 | `getAxisValue(AXIS_ORIENTATION)` |
| S Pen ボタン | `getButtonState()` の `BUTTON_STYLUS_PRIMARY` |
| 中間サンプル | `getHistorySize()` / `getHistoricalX()` ※ iOS の coalesced 相当 |

Android には予測 API の標準はありませんが、Android 13 以降に `MotionPredictor` があります。利用可能なら使い、なければ自前で線形／二次予測を実装します。

### PC

- Maya 準拠のカメラ操作: `Alt+左ドラッグ`＝タンブル、`Alt+中ドラッグ`＝パン、`Alt+右ドラッグ`＝ドリー
- ペンタブレット: Windows は Windows Ink（`WM_POINTER`）、macOS は `NSEvent` の `pressure`／`tilt`
- キーボードショートカットは Maya 配列を既定に（`Q`選択 `W`移動 `E`回転 `R`スケール、`1`〜`3`でスムースプレビュー切り替え）

## 4.4 長押しサークルメニュー（マーキングメニュー）

ご要望の「長押し → 方向で仮選択 → 離して決定」を仕様化します。Maya のマーキングメニューと同じ思想です。

### 動作仕様

```
押下
  ├ 200ms 保持（移動 12px 以内）→ サークルメニュー表示
  │    ├ 中心から 28px 以内 = デッドゾーン（キャンセル扱い）
  │    ├ 28px 超えた方向の項目を「仮選択」してハイライト＋触覚フィードバック
  │    └ 離す → 仮選択中の項目を確定
  └ 200ms 以内に 12px 超えて移動 → 通常のドラッグ操作として扱う
```

### 設計上の注意

- **項目数は 8 個まで、理想は 4〜6 個。** それ以上は方向の識別が困難になります。
- **入れ子は 1 段まで。** 外周リングにサブメニューを出す方式にし、それ以上は深くしない。
- **メニュー非表示のフリック操作を許可してください。** 200ms 待たずに素早く方向にフリックした場合、メニューを描画せずに即確定します。これは Maya の熟練者が最も多用する操作で、慣れると劇的に速くなります。
- **画面端でのはみ出し対策。** メニュー中心が端に近い場合、円を画面内に収まる位置へずらすか、扇形に配置し直します。
- **左利き対応。** 項目配置を左右反転できる設定を用意します。
- 触覚フィードバックは仮選択が切り替わった瞬間に軽く（iOS は `UIImpactFeedbackGenerator` の light）。これがあるかないかで操作の確かさが体感で大きく変わります。

### 割り当て候補

| 呼び出し元 | 項目 |
|---|---|
| ビューポート長押し（スカルプト） | ブラシ切り替え（Standard / Clay / Move / Smooth / Pinch / Inflate） |
| ビューポート長押し（モデリング） | 選択モード（頂点 / エッジ / 面 / オブジェクト）＋よく使う編集 |
| ツールバーの各アイコン長押し | そのカテゴリ内のツール群 |
| Pencil Pro スクイーズ | コンテキストに応じたメニュー |

## 4.5 常時表示の左側コントロール

ご要望の「Shift / Alt / Ctrl のオンオフボタン」「一つ進む・一つ戻る」を左端に固定します。

### 修飾キーの挙動

物理キーのシミュレートではなく、**アプリ内部の状態（スティッキー修飾）として持ってください**。OS のキーイベントを偽装する実装は、プラットフォーム間で必ず破綻します。

各ボタンは 3 状態を持ちます。

- **オフ**
- **ラッチ（1回タップ）** — 次の 1 操作だけ有効。操作完了で自動解除
- **ロック（ダブルタップまたは長押し）** — 明示的に解除するまで有効。見た目を明確に変える

各モードでの意味は Maya / ZBrush の慣習に合わせます。

| 修飾 | モデリング | スカルプト |
|---|---|---|
| Shift | 選択に追加 | スムースブラシに一時切り替え |
| Ctrl | 選択から除外 | マスク描画 |
| Alt | （カメラ操作、PC のみ） | 反転動作（Ctrl+Alt でマスク解除など） |

### レイアウト

- タッチターゲットは **iOS 44pt / Android 48dp 以上**。これを下回ると押しにくさが致命的になります
- 縦持ち・横持ちの両方でレイアウトを定義
- 左手の親指が自然に届く範囲（画面左端から 40% 以内、縦方向は中央〜下寄り）に主要ボタンを配置

## 4.6 パネルとドッキング

ご要望どおり「既定は左、どこにでもドッキング可能」を実装します。

- ドッキング先: 左 / 右 / 上 / 下 / フローティング
- パネルのタイトルバーをドラッグするとドロップゾーンがハイライト表示される
- **レイアウトはモードごとに独立して保存**（モデリングとスカルプトで欲しいパネルは違うため）
- レイアウトは JSON で保存し、プリセットとして書き出し・読み込みできるようにする
- 「一時的に全パネルを隠す」ボタンを必ず用意する。タブレットは画面が狭く、これが実用上とても重要です

### UI フレームワーク

C++ にはタブレット向けの production レベルな UI ツールキットが存在しないため、**全面自作になります**。ネイティブ路線で最も工数を食う部分です。選定と分担は `02-architecture.md` 2.7 を参照してください。

- パネル、インスペクタ、サークルメニュー、ギズモ、スライダー = レンダラ上に自前構築
- テキスト入力、ファイル選択、共有シート = プラットフォームのネイティブ UI
- 日本語テキスト描画は HarfBuzz + FreeType
- デバッグ表示は Dear ImGui（製品ビルドから除外）

### タッチ向けスライダーの必須要件

タブレットで数値を細かく調整するのは本質的に難しいので、以下を必ず入れてください。

- **精度調整ドラッグ** — スライダーを掴んだまま指を上下（スライダーから離れる方向）に動かすと、感度が 1/10、1/100 に下がる。ペンでの微調整には必須
- **数値の直接入力** — 数値部分をタップでキーボード入力
- **ダブルタップで既定値に戻す**
- **ドラッグ中は指の下に大きく現在値を表示**（指で隠れるため）
