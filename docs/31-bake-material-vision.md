# 31. ベイクとマテリアルの往復を「優しく」する設計メモ

作成: 設計担当（Fable）。2026-09-09。ユーザーのビジョン共有への答え。指示書ではなく、`28` の S2 以降の作り方を縛る**方針**。

---

## ユーザーのビジョン（原文の要点）

> スカルプトからマテリアルの作業に移るとき、ハイモデルとローモデルのベイクをする。マテリアル・ローモデル・ハイモデルを調整で往復するとき、タブを切り替えるごとにリベイクしている。そこを**ボタン 1 つ、もしくはオート**で簡単にリベイクして、**UV やメッシュ割りをいじってもマテリアルを非破壊で再計算**できるような優しい作りにしたい。調整作業がとにかくしやすいアプリを目指している。

## 一言でいうと

**「作り方」を保存して、必要なところだけ作り直す。** UV で既にやっていること（`15` の `UvRecipe`。切れ目・ピン・手の差分を「島の指紋」で持ち、トポロジが変わっても合うところは残す）を、**ベイクとマテリアルにも同じ形で広げる**。ユーザーは「調整する」だけで、作り直しはアプリの仕事。

このアプリは既にそのための土台を 2 つ持っている。

1. **ハイもローも同じオブジェクトの中にある**（`03` / `11`）。ロー = レベル 0、ハイ = マルチ解像度の上のレベル。別ファイルではない。だから**ハイとローの対応は最初から分かっている**（同じ面の細分割）
2. **レシピと指紋**（`15`）。「何をどう作ったか」を保存し、元が変わったら合う分だけ引き継ぐ

---

## 1. データの形: 全部「レベル 0 の上のレシピ」

```
Object
├ Base（レベル 0）            ← 破壊編集 + 履歴。唯一の「手で作るもの」
├ Multires（レベル 1..N）      ← 接空間デルタ。ハイモデルはここ
├ UvRecipe                    ← 切れ目・ピン・方式・手の差分（済）
├ BakeRecipe                  ← 何を焼くか（法線 / AO / 曲率 / 厚み / ID / 高さ）、解像度、
│                                元（自分のレベル N か、別オブジェクト + ケージ）
├ MaterialStack               ← レイヤー（塗り / 生成 / ペイント）、マスク、ブレンド
└ Caches                      ← ベイク結果とレイヤー合成の結果。**いつでも捨てて作り直せる**
```

**Caches 以外は全部小さい。** `.mbz` に入れるのはレシピで、キャッシュは入れても入れなくてもよい（入れると開くのが速い。無ければ作り直す）。

## 2. 「古い」を知る仕組み: スタンプ

各段が**入力の指紋**を持つ。

| 段 | 指紋の元 |
|---|---|
| トポロジ | `topologyHash`（済。`io/hash.ts`） |
| レベル 0 の形 | 頂点座標のハッシュ。**B-T4 の差分履歴があれば「どの頂点が動いたか」も分かる** |
| ハイの形 | レベル N のデルタのハッシュ |
| UV | `UvRecipe` の指紋（済）+ `map1` のハッシュ |
| ベイク | 上 4 つ + `BakeRecipe` |
| マテリアル | ベイク + `MaterialStack` |

キャッシュは「作ったときの指紋」を覚えていて、今の指紋と違えば**古い**。マテリアルのタブに `古い` の印が出る。これだけで「タブを切り替えるごとに手でリベイク」は要らなくなる。

## 3. リベイクは「ボタン 1 つ」と「オート」の両方

| | いつ | 何を |
|---|---|---|
| **オート（既定）** | マテリアルのタブに入ったとき、古ければ | 古い段から下だけ作り直す。ワーカーで裏で走り、終わるまでは古い絵のまま + 印 |
| **オート（スカルプト中）** | マテリアルの表示をオンにしたままスカルプトすると | **動いた面が触るタイルだけ**焼き直す（下の 4） |
| **ボタン** | 「更新」を押したとき | 全部作り直す（疑ったときの保険） |

## 4. 速くする鍵: 「自分のハイ」は光線を飛ばさずに焼ける

Substance Painter のベイクは別ファイルのハイに向けて**光線を飛ばす**（ケージ、距離、貫通のノイズ）。ここでは**ハイがローの細分割そのもの**なので、ローの UV の各テクセルが**ハイのどの点か**は計算で決まる（面 → 細分割の面 → 重心座標）。

- **法線 / 高さ / 曲率 / 位置**は、テクセルごとにハイの面を評価するだけ。光線もケージも無い。**継ぎ目の割れも貫通も起きない**
- **AO / 厚み**だけ光線が要る（これは B-T5 の BVH をそのまま使う）
- **タイル分け**（256px の升目）で、**動いた頂点が触る升目だけ**焼き直す。B-T4 の差分履歴が「動いた頂点」を持っているので、そこから升目が分かる。1 ストロークで数升目 → 数十 ms

別オブジェクトをハイにする（読み込んだスキャンなど）は**第 2 の経路**として後で足す。そちらはケージ + 光線。

## 5. UV やメッシュ割りを変えたときにマテリアルが生き残るには

ここがいちばん難しいところ。レイヤーの種類で分ける。

| レイヤー | 変えたときどうなるか |
|---|---|
| **塗り（単色 / 手続き）** | レシピなので**そのまま作り直せる**。何も失わない |
| **生成マスク**（曲率 / AO / 位置から） | ベイクを作り直せば**そのまま作り直せる** |
| **ペイント（ラスタ）** | **ストロークを 3D で記録**する（面 + 重心座標の経路、ブラシの設定、筆圧）。UV が変わったら**新しい UV に再描画**する。ラスタは「ストロークを再生したキャッシュ」に過ぎない |
| ペイント（再生できない古いもの・読み込んだ画像） | **面の対応で写す**（`24` の T6 の転送と同じ「いちばん近い点」。テクセルごとに旧 UV を引いて旧画像を読む）。継ぎ目のまわりは少しにじむ。**印を付けて、ユーザーに「写した」と分かるようにする** |

**推奨する作り方をアプリが導く**: 塗り + マスクの構成（Substance のスマートマテリアル型）を既定にし、ペイントは「上に少し足す」位置づけにする。**そうすると何を変えても失うものが無い**。

トポロジを変えたときは `03` の 3.4 のとおり上位レベル（ハイ）は捨てる。これは変えない（捨てないと形が壊れる）。**ただし「捨てる前のハイの形」を 1 つキャッシュに残し**、新しいローから**再投影**（ローの各頂点を旧ハイの面へ寄せる = 転送の位置）して**ハイを作り直す入口**を置く。ZBrush の「Project All」にあたる。これがあれば「ローの割りを変えたらスカルプトが消えた」にならない。

## 6. 画面

- マテリアルのタブに **`古い` / `計算中` / `済`** の小さな印。古ければタブに入った瞬間に裏で走る
- 「更新」ボタンはツール列（マテリアル列）に 1 つ。長押しで「全部」「ベイクだけ」「合成だけ」
- スカルプト中に**マテリアルの表示を重ねられる**（シェードの中身に「マテリアル」を足す）。オンにするとタイル単位で焼き直しながら見える
- 変えたら消えるものは**変える前に言う**（「ハイのレベル 3 を捨てます。捨てる前の形は残すので、あとで写し直せます」）

## 7. ロードマップへの影響（`28` の直し）

| 段 | 足すもの |
|---|---|
| **S1（今の `29` の B）** | そのまま。B-T4 の差分履歴と B-T5 の BVH が、そのまま「動いた升目」と AO の光線に使える |
| **S2（スカルプト）** | `SceneObject` に**スタンプ**（上の 2）を入れる。安いので最初から。「捨てる前のハイ」のキャッシュと**再投影の入口**（5 の最後）は S2-4 に |
| **S3（新設）: ベイク** | `BakeRecipe`、テクセル → ハイの面の対応、法線 / 高さ / 曲率 / 位置 / AO / 厚み / ID、タイル分けと差分焼き、`古い` の印と「更新」。**マテリアルより先。** これだけでも「スカルプト → 書き出し → Substance」が回る |
| **v2.0 マテリアル** | `MaterialStack`、塗り / 生成 / ペイント、ストロークの 3D 記録と再生、面の対応で写す |

## 8. 判断してほしいこと

1. **ハイは「自分のマルチ解像度」を第 1 の経路にしてよいか。** 別オブジェクトのハイ（スキャンなど）は第 2 の経路として後回し
2. **ペイントは「ストロークを 3D で記録して再生」でよいか。** ラスタをそのまま持つより手間がかかるが、UV を変えても失わない唯一の方法。再生の時間はストローク数に比例する（数千ストロークで数秒）
3. **ベイクの解像度の既定は 2K、上限 4K**（`05` の 5.4）でよいか。タイル分けで差分焼きするので、4K でも触っている升目だけなら速い
4. S3（ベイク）を**マテリアルより先、スカルプトの直後**に置いてよいか

## やらないこと

- Substance のファイル（`.sbsar` / `.spp`）の読み込み（`06`）
- 光線ベイクのケージの手編集（第 2 の経路のときに考える）
- ペイントのレイヤーの無限の履歴（ストロークの記録があるので、履歴は「ストロークを消す」で足りる）
