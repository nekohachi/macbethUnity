
# 03. マルチ解像度編集（本アプリの中核）

ご要望の以下の機能について、実現方法と制約を具体的に整理します。

> モデリングで作ったローモデルをスカルプトタブに切り替えて、クリース、ディバイド、スムースでハイメッシュ化できる。ディバイドスライダーを下げてモデリングモードに切り替え、頂点編集すると、ハイモデルの形状を保ったままローモデル調整ができる。

**結論から言うと、実現可能です。ただし一つ重大な制約があります**（3.4 節）。ここを最初に理解しておくことが極めて重要です。

## 3.1 仕組み

ZBrush のサブディビジョンレベルと同じ原理です。各レベルの頂点座標をそのまま持つのではなく、**「細分割で得られる滑らかな面」からのズレ（デルタ）を接空間で持ちます**。

レベル L の頂点座標を次のように表します。

```
P(L) = Subdiv(P(L-1)) + [ T(L) · delta(L) ]
```

- `Subdiv()` — Catmull-Clark 細分割（クリース値を考慮）
- `T(L)` — その頂点における接空間の基底（法線・接線・従法線からなる 3x3 行列）
- `delta(L)` — 接空間で表現されたスカルプトのディテール

**接空間で持つことが決定的に重要です。** ワールド座標の差分で持つと、ローモデルを回したり曲げたりしたときにディテールが取り残されて破綻します。接空間なら、下位レベルの形が変わると法線と接線が変わり、ディテールが表面に張り付いたまま追従します。

### ローモデルを編集したときの処理フロー

1. レベル 0 の頂点を移動する
2. レベル 1 の `Subdiv(P(0))` を再計算する
3. レベル 1 の各頂点で接空間 `T(1)` を再計算する
4. 保存しておいた `delta(1)` を新しい接空間に適用して `P(1)` を得る
5. レベル 2 以降について 2〜4 を繰り返す

再計算はレベルごとに頂点数が約 4 倍になるので、レベル 6（レベル0が1000ポリなら約 400 万ポリ）まであると全体再計算は重くなります。**移動した頂点の影響範囲だけを再計算する差分更新**が必須です。細分割の影響は局所的なので、これは実装できます。

## 3.2 細分割ライブラリ: OpenSubdiv を使ってください

Catmull-Clark をゼロから実装しないでください。特にクリース（semi-sharp crease）の扱いは仕様が細かく、自前実装は Maya と結果が合わなくなります。

**Pixar OpenSubdiv（修正 Apache 2.0 ライセンス）を組み込むことを強く推奨します。**

- Maya が内部で使っているのが OpenSubdiv です。つまり**結果が Maya と一致します**。これは互換性の観点で非常に大きい。
- ライセンスは商用利用可。
- モバイルでは GPU 評価器のサポートが限定的ですが、**本アプリが必要とするのは「一様細分割（uniform refinement）」であり、これは CPU 評価器でモバイルでも問題なく動きます**。パッチ描画の GPU テッセレーションは使いません。
- C++ ライブラリなので、Unity からはネイティブプラグインとして呼びます。iOS は静的ライブラリ、Android は `.so` としてビルドします。

自前実装する場合の代替として、クリースの重みは OpenSubdiv の semi-sharp crease のセマンティクス（0〜10 の実数、整数部が完全鋭角の細分割回数、小数部が補間）に合わせてください。USD もこの表現を採用しています。

## 3.3 ディバイドスライダーの挙動

ZBrush の SDiv スライダーと同じ挙動にします。

- スライダーを下げる → 表示と編集対象が低レベルになる。上位レベルのデルタはメモリに保持されたまま
- スライダーを上げる → 保持していたデルタを再適用して復元
- 「Delete Higher」→ 上位レベルを破棄してメモリ解放
- 「Delete Lower」→ 現在レベルをレベル 0 として焼き込む

**メモリ表示を必ず UI に出してください。** レベルを 1 つ上げるとメモリが 4 倍になります。ユーザーが無自覚に上げてアプリが落ちるのが、この種のアプリで最も多いクラッシュです。レベルごとの推定メモリを事前に表示し、予算を超える操作はブロックします。

## 3.4 【重要な制約】トポロジを変えると上位レベルは維持できない

これが避けられない本質的な制約です。

デルタは「レベル L-1 の頂点からレベル L の頂点への対応関係」に依存しています。エッジループを挿入したりベベルをかけたりすると、レベル 0 の頂点数と面の構成が変わり、**上位レベルとの対応関係が消滅します**。ZBrush が「トポロジを変更するとサブディビジョンレベルが削除される」と警告するのはこのためです。

したがって、モデリングモードのツールを 2 種類に分類してください。

### レベル維持可能（トポロジ非変更）

- 頂点・エッジ・面の移動、回転、スケール
- ソフト選択による変形
- スムース／リラックス（頂点位置のみ変更）
- クリース値の変更
- 対称化（トポロジが対称な場合）

**この分類のツールだけが、ハイモデルを保ったままローモデルを編集できます。** ご要望の中心はここなので、v1 ではこの範囲を確実に動かすことを目標にしてください。

### レベル破棄が必要（トポロジ変更）

- エッジループ挿入、マルチカット
- ベベル、押し出し、ブリッジ
- 頂点・エッジの削除、マージ、ウェルド
- 面の分割、結合

これらを実行しようとしたときの UI は 3 択にします。

1. **上位レベルを破棄して続行** — 最も単純
2. **キャンセル**
3. **リプロジェクト（再投影）** — 上位レベルの形状を空間分割構造に焼き込み、トポロジ変更後に改めて低レベルから細分割して、その表面に投影し直してデルタを再生成する

3 番は ZBrush の「Project All」に相当します。**完全ではありません**（薄い部分や入り組んだ部分でディテールが崩れます）が、リトポロジーのワークフローには必須です。v1.5 以降の目標としてください。

## 3.5 検証を最優先で行ってください

この機能は本アプリの存在意義そのものです。UI を作る前に、以下を確認するプロトタイプを最初に作ることを強く勧めます。

1. 立方体（レベル 0、6面）をレベル 5 まで細分割する
2. 高レベルでスカルプトしてディテールを入れる
3. レベル 0 に戻り、頂点を大きく動かす
4. レベル 5 に戻したとき、ディテールが**歪まずに追従している**ことを確認する
5. レベル 0 でクリースを設定し、上位レベルに正しく伝播することを確認する
6. 上記が 100 万ポリ規模で対話的な速度（レベル切り替えが 200ms 以内）で動くことを確認する

ここが通らなければ、以降の設計を全部見直す必要があります。**最初の 2〜4 週間はこの検証だけに使ってください。**
