## 1. 修正（すぐ直す）

### 1.1 展開した島が斜めになる

**原因。** LSCM は形を決めるだけで向きを決めない。今は「縁の輪で向かい合う 2 点」を (0,0) と (1,0) に固定しているので、島の向きは**その 2 点の並びで決まる**。立方体の面なら、対角に近い 2 点が選ばれて 45° 傾く。

**決め。** 解いたあとで**島ごとに回して立てる**。基準は 3D のワールド Y。

1. 島の各三角形について、3D の上向き (0, 1, 0) を三角形の面に落とし、それを UV に写した向きを取る（ヤコビアンは `distortion.ts` で出しているものと同じ）
2. 面積で重み付けした平均を「その島の上向き」とし、それが +V を向くよう島全体を回す
3. 上向きが面にほぼ乗らない島（天面・底面。落とした長さが 0.2 未満）は、ワールド X を +U に向ける
4. 回す基点は島の中心。回したあとで境界箱を取り直してからパッキングへ

これで立方体の面はまっすぐ、円柱の側面は縦、球の島は極が上になる。**Maya の Unfold3D が元の向きを保つのと同じ見え方**になる。

置き場所: `core/uv/orient.ts` に `uprightChart(positions, tri, uv): void`。`recompute` で LSCM / 投影の直後、`measure` の前に呼ぶ。テスト: 立方体を全部切って展開 → 6 島すべての辺が U 軸か V 軸に平行（1e-4）。円柱の側面 → 縦の辺が V に平行。

### 1.2 島と島の間を最低 5px 空ける

**決め。** 余白は **テクセル**で持つ。UV の比率で持つと、テクスチャの大きさで意味が変わる。

- `packing.margin` を **`packing.marginTexels`（既定 8）** と **`packing.textureSize`（既定 1024）** に分ける。UV の余白 = marginTexels / textureSize。8 texels なら 1024 で 8px、512 でも 4px … 5px を割るので、**512 のときは 10 texels に上げる**（最低 5px を守る規則: `max(marginTexels, ceil(5 × 1024 / textureSize))`）
- 0〜1 の外周にも同じ余白（今は margin をそのまま使っている。合わせる）
- パッキングは境界箱どうしを余白ぶん離す（今の棚詰めのまま）。**島を 90° 回して詰める `allowRotate` は既定を false に**する。1.1 で立てた向きを崩さないため
- `.mbz` は古い `margin` を読んだら `marginTexels = round(margin × 1024)` に直す

オプションパネル「パッキング」区画: 余白（texels）、テクスチャの大きさ（512 / 1024 / 2048 / 4096）、90° 回転を許す。

### 1.3 UV の取り消し / やり直しが効かない

**原因（確認済み）。** `history.ts` のスナップショットに **`SceneObject.uv`（レシピ）が入っていない**。戻すとメッシュ（`map1` を含む）は戻るが、切れ目・ピン・土台・差分は戻らない。さらに `afterHistory()` が 2D ビューを作り直していないので、画面も古いまま。指 2 本のダブルタップは `doUndo()` を呼んでいるので、入口は合っている。

**決め。**
- `ObjectSnapshot` に `uv: UvRecipe | null` を足し、`cloneRecipe` で深く複製する（`base` の Float32Array も複製）。戻すときは `o.uv = cloneRecipe(snap.uv)`
- `afterHistory()` で、UV モードなら `uv.rebuild()` と選択の同期（`pushSelectionToUv`）を呼ぶ
- 2D の操作はすべて `host.commit` を通っているので、そこは変えない。**指 2 本ダブルタップ = 戻る、3 本 = 進むが 2D で効く**ことを通し確認に足す（島を動かす → 2 本ダブルタップ → UV が戻る → 3 本ダブルタップ → 進む）

## 2. 相談 1: UV の進め方

### 2.1 何が起きていたか（率直に）

指示が悪かったのではない。**順番が悪かった**。それは設計側（私）の判断。

C1 の時点で「レシピ・LSCM・差分」という非破壊の仕組みを先に作り、編集器としての当たり前（今の UV が見える、島が枠に収まる、選択が 3D と共通、戻せる）を後回しにした。結果、ユーザーが触った最初の 5 分で当たるものが全部「基礎の穴」だった:

| 症状 | 実際の原因 | UV の設計と関係あるか |
|---|---|---|
| UV が何も表示されない | プリミティブの 6 面が同じ 0〜1 に重なっていた。枠が横にはみ出していた | ない（プリミティブと表示の穴） |
| 伸び ×4.00 | 縮尺を歪みとして数えていた | 数値の定義 |
| エッジの区間選択が効かない | 円柱・球の継ぎ目が -0 の丸めで割れていた | ない（メッシュの穴。B4 で誤診していた） |
| 島が畳まれる | LSCM の固定点の選び方と収束 | ソルバー |
| 戻せない | 履歴にレシピが入っていない | 非破壊の層と履歴の繋ぎ忘れ |

非破壊そのものは正しく動いている（差分は残る、切れ目を変えても他の島は保たれる、トポロジが変わっても土台を取り直す）。**問題は「非破壊を先に作ったこと」ではなく「編集器の骨格を通し確認していなかったこと」**。通し確認は「値が合うか」ばかり見ていて、「触って分かるか」を見ていなかった。

### 2.2 提案: Maya ベースで作りきる → タブレットへ寄せる → 自動と非破壊を足す

**賛成。** ただし「非破壊のコードを捨てる」のではない。今ある層はそのまま下に置き、**上に乗せる編集器を Maya の UV エディタとして作りきる**。順番を変えるだけ。

やること（次の指示書 `20`）:

1. **1 つの作業を最初から最後まで通す**。立方体 → 円柱 → 球の 3 つで「切る → 縫う → 展開 → 整列 → 動かす・回す・拡縮 → 3D で確かめる」を、Maya の UV エディタと同じ手順で。通し確認もこの手順そのもの（値ではなく手順）
2. Maya の UV エディタにあって無いものを埋める: **UV のループ / リング選択、シェル選択の伝播（3D で 1 面 → 2D で島）、Move and Sew、境界の直線化、格子化、UV の対称、ピン留めの見た目**。C3 の ops はもうあるので、繋ぎと見た目
3. **自動 UV と「取り込んだまま / LSCM / 投影」の切替は、オプションの奥に下げる**。既定の入口は Maya と同じ「カット → 展開」。自動はボタン 1 つ残す
4. その上でユーザーがタブレットで触り、フィードバックを 1 回まとめて受ける
5. その後で非破壊の見せ方（差分が残ること、切れ目を変えたときの挙動）を表に出す

**変えない決め:** レシピから再計算する構造、島の指紋による差分、`base` の取り込み。これらは動いている。

### 2.3 私が変えること

- 指示書に**「触って分かること」の受け入れ条件**を書く。数値だけの合格条件は残すが、それだけで済ませない
- 1 タスク = 1 つの手順（「立方体を切って開いて整列して 3D で見る」）。機能単位で切らない
- 実装の報告に**画面の絵**を付ける（今回のように、絵で見て初めて分かった穴が多い）

## 3. 相談 2: アウトライナとオプションの置き場所

### 3.1 結論

**どちらも常時表示にしない。** どちらも「1 タップで出て、外を触ると消える」にする。片方が必須ならもう片方も、という考えは正しくて、その答えは「どちらも必須ではない」。

Maya のパネルは机の上の 27 インチ向けで、11 インチの板で常時出すと描画領域が 2/3 になる。今の画面がそれ。

### 3.2 オプション → ツールのカットイン

ユーザーの案どおり。マニピュレータの大きさで作ったカットイン（ツール列のボタンから横に出る）を、**すべてのツールに広げる**。

| 操作 | 出るもの |
|---|---|
| ツール列のボタンをタップ | そのツールになる（今のまま） |
| **今のツールのボタンをもう一度タップ** | そのツールのオプションが横からカットイン（マルチカットのステップ・エッジフロー、ベベルの幅・分割、押し出しの距離、スナップの刻み、ソフト選択…） |
| 外を触る / 同じボタン | 閉じる |

Maya の「ツール設定」と同じ関係（ツールのアイコンをダブルクリックで設定が出る）。**右の「オプション」パネルは無くす。** トランスフォームの数値入力とプリミティブのパラメータは、次の「レイヤー」の中に置く（3.3）。

### 3.3 アウトライナ → Procreate のレイヤー

賛成。Procreate のレイヤーパネルは、タブレットで「一覧を出して閉じる」の最良の型で、ユーザーの手に馴染んでいる。

| 項目 | 決め |
|---|---|
| 出し方 | 上段の「レイヤー」ボタン（Procreate と同じ右上）。もう一度で閉じる。**右端から左へスワイプでも出る** |
| 見た目 | 右から被さるドロワー。幅は今のパネルと同じ 236px。描画領域は縮まない（上に乗るだけ） |
| 1 行 | サムネイル（そのオブジェクトだけを小さく描いたもの）、名前、目のアイコン（表示）、ロック |
| 操作 | タップで選択、長押しでメニュー（改名 / 複製 / 削除 / 結合 / 分離 / 中心にピボット）、**行の長押しドラッグで並び替え**、SHF + タップで複数選択（結合のため） |
| 行を開く | 行の右端の「>」で、そのオブジェクトの**プロパティ**が下に展開（トランスフォームの数値、プリミティブのパラメータ、スムージング角度）。ここが今のオプションパネルの「オブジェクト側」の受け皿 |
| 閉じるとき | 外を触る、ボタン、右へスワイプ |

**PC（幅 1200px 以上）では今のドッキングのまま**でよい。画面に余裕があるので出しっぱなしが速い。判定は幅だけ（`layout.ts` の縦持ち判定と同じところ）。

### 3.4 やらないこと

- グループ / 階層（Procreate のグループにあたるもの）。今はオブジェクトの平らな一覧
- サムネイルの逐次更新。開いたときに描く
