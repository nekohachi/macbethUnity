## 1. 光線を飛ばさない

`31` の 4 のとおり、**ハイはローの細分割そのもの**。しかも `assembleQuads` は
**UV も一緒に細分割している**（コーナーの UV → 中点と面の平均）。つまり

> **ハイの UV の島は、ローの UV の島とぴったり同じ場所を覆う。**

だから「テクセル → ハイの点」は、**ハイをそのまま UV へラスタライズするだけ**で出る。
ケージも距離も貫通の判定も要らない。継ぎ目も割れない。

```
テクセル ← ローをラスタライズ → P_low, N_low, T_low, B_low
テクセル ← ハイをラスタライズ → P_high, N_high
法線マップ = N_high をローの接空間で表したもの
高さマップ = (P_high − P_low) · N_low
```

## T1. ラスタライズと接空間（core）

`src/core/bake.ts` を作る。

### 決め

- **`map1` の UV を使う**（無ければ焼けない。呼ぶ側が断る）
- 面は**頂点 0 からの扇**で三角形に割る（`mesh.triangulate` と同じ割り方。
  UV も同じ扇で割れば辻褄が合う）
- ラスタライズは**テクセルの中心**で判定。三角形の外接する升目を回り、
  重心座標が全部 0 以上なら中に居る
- **接空間はローの頂点ごと**に作る。法線は面の面積で重みを付けた平均、
  接線は UV の微分（`dP/du`）を足してから正規化。従法線は外積。
  テクセルごとに補間して、その場でもう一度直交化する（Gram-Schmidt）。
  **これは glTF と Substance が期待する形**（`05` の 5.4）
- ハイの法線は**頂点ごとの平均**（細分割した面はすべて滑らかなので、角度で分けない）
- **島の外は埋める**（dilate）。既定 4 テクセル。埋めないと、ミップマップや
  双線形補間で継ぎ目に黒が滲む

### 出すもの

```ts
export interface BakeResult {
  size: number;
  /** 接空間法線（RGBA8。+Z が外向き、A は 255）。 */
  normal: Uint8Array;
  /** 高さ（ローの法線方向の差。ワールド単位）。 */
  height: Float32Array;
  /** 島の中か（0 / 1）。埋めたぶんは 2。 */
  coverage: Uint8Array;
  /** 高さの min / max。書き出すときの正規化に使う。 */
  heightRange: [number, number];
  /** 島が覆ったテクセルの数。 */
  covered: number;
}
```

### テスト

- **平らな板**（ロー = ハイ）: 法線がぜんぶ (128, 128, 255)、高さが 0
- **段 1 に膨らみを彫った板**: 高さが正、法線が傾く。傾く向きが膨らみの向きと合う
- 島の外は `coverage` が 0 のまま（埋める前）。埋めると縁の外まで色が付く
- **UV を動かしても結果が付いてくる**（UV を 0.5 ずらすと、焼いた絵も 0.5 ずれる）

## 報告（2026-09-10。T1〜T3 済）

### T1: ラスタライズと接空間（`src/core/bake.ts`）

指示のとおり **光線を飛ばしていない**。ローとハイを**同じ升目**へラスタライズして、
テクセルごとに引き算するだけ。

```
テクセル ← ローをラスタライズ → P_low, N_low, T_low, B_low, 覆った印
テクセル ← ハイをラスタライズ → その場で接空間へ落として書く
法線マップ = N_high をローの接空間で表したもの（RGBA8）
高さマップ = (P_high − P_low) · N_low（f32。書き出すときに 8 ビットへ）
```

- 面は**頂点 0 からの扇**で三角形に割る（`mesh.triangulate` と同じ割り方。UV も同じ扇）
- 判定は**テクセルの中心**。三角形の外接する升目を回り、重心座標が全部 0 以上なら中
- 接空間はローの**頂点ごと**。法線は面の外積をそのまま足す（＝面積の重み）、
  接線は三角形ごとの `dP/du` を足して正規化。テクセルごとにもう一度直交化する
- **島の外は埋める**（既定 4 テクセル）。埋めたテクセルは `coverage` が 2

#### 指示書に無かった直し: **従法線の向き（`TANGENT.w`）**

`B = N × T` と決め打ちにすると、**UV が裏返っている島で緑が逆さに焼ける**。
このアプリのプレーンがまさにそれで、`dP/du × dP/dv` が面の法線と逆を向く。
`dP/dv` も一緒に足して `w = sign((N × T) · dP/dv)` を持ち、`B = w × (N × T)` にした。
glTF の `TANGENT.w` と MikkTSpace の決まりと同じで、**Substance と Blender が
期待する形**（`05` の 5.4）。テストの「緑が北で上がり南で下がる」がこれを見ている。

#### メモリ

ハイのぶんをテクセルごとに溜めると 2K で 100MB 余計に要る。
**ハイは 1 回なめて、その場で書く**（`P_high` も `N_high` も持たない）。
2K で 49B/テクセル ＝ **約 205MB**。4K はその 4 倍なので、実機で試してもらう
（`37` の表の 34）。

- タップで焼く。長押しで「法線を書き出し」「高さを書き出し」「1K / 2K / 4K」
- バッジは **`済`**（指紋が合っている）と **`古`**（合っていない）。
  1 文字にしたのはボタンの隅に出る印なので（「古い」は入らない）
- 焼くのはローが**レベル 0**、ハイが**いちばん上の段**
- 高さの書き出しは **min / max の絶対値が大きい方**で正規化して、**平らが 128**。
  0 が中央に来ないと、彫った所と掘った所の区別が付かなくなる
- 絵は上から下、UV は下から上なので、PNG にするとき**縦をひっくり返す**

#### 指紋は間引いて拾う

`bakeStamp` は**ボタンを描くたびに**呼ばれる。25 万四角形（コーナー 100 万・
デルタ 300 万）を丸ごと舐めるわけにはいかないので、コーナーも座標もデルタも
**4096 点ほどに間引いて**混ぜている。**1 テクセルぶんの彫りでは変わらないことがある**。
印は「焼き直したほうがいい」の目安であって、正しさの保証ではない（そう書いてある）。
