# 10. 次のフェーズに必要なもの

作成: 設計担当（Fable）。実装担当（Opus）への次フェーズの依頼書。`09` の判断を前提にする。

## 現在地

- v1.0 はモデリング特化、Web 基盤で確定
- プロトタイプは iPad mini と MovinkPad で動作確認済み。操作の骨格（マーキングメニュー、F 修飾、ユニバーサルマニピュレータ、選択即編集、対称、OBJ、自動保存）まで入った
- 単一 HTML 約 3,000 行。機能追加のたびにリスクが増える段階に来ている

## 必要なもの（優先順）

### 1. 土台の作り直し（最初にやる。機能追加はこの後）

| 項目 | 内容 | 理由 |
|---|---|---|
| **TypeScript + Vite** | 単一 HTML をモジュールに分割。`core/`（メッシュ、プリミティブ、トポロジ編集、選択走査、Catmull-Clark。DOM も Three.js も参照しない）と `app/`（描画、入力、UI、ファイル） | 今の構造では変更の影響範囲が追えない。`core/` の分離は、v1.5 で C++ → wasm に差し替えるための境界でもある |
| **vitest** | `core/` に単体テスト。今 Node で手動実行している検証（立方体のスムース、エッジループ、OBJ 解析）を自動化 | 幾何のバグはこの環境では 3D を見て確かめられない。テストだけが検証手段 |
| **GitHub Actions** | push でテスト → ビルド → GitHub Pages へ自動デプロイ | `make-pages.sh` の手動運用をやめる。タブレットで常に最新が開ける |
| **PWA** | manifest、アイコン、Service Worker（オフライン起動） | ホーム画面から全画面で起動。電波がなくても開く |
| **プロジェクト形式** | `.mbz`（zip + JSON + バイナリ）の保存と読み込み、自動保存を IndexedDB へ、最近のプロジェクト一覧。**仕様は `11-data-architecture.md`** | 端末をまたぐ、バックアップする、Maya へ渡す前の作業単位を持つ |
| **メッシュ構造の拡張** | `core/` のメッシュにクリース、ポリグループ、マテリアル ID、UV セットの欄を最初から持たせる。トポロジ操作は UV を補間して保持する | 後から足すと全操作を書き直すことになる（`11` の 4 章） |

### 2. 選択操作の Maya 互換（着手済み）

| 項目 | 状態 |
|---|---|
| エッジのダブルクリック = エッジループ | **実装済み** |
| Shift + ダブルクリック = 部分ループ / 部分リング / フェースループ / 頂点列 | **実装済み** |
| フェース・頂点のダブルクリック = シェル | **実装済み** |
| 選択の拡張 / 縮小（Grow / Shrink） | 未。Ctrl + `>` `<` 相当。マーキングメニューに置く |
| 境界エッジの選択、UV シームの選択 | 未 |
| 選択の鏡映（対称編集時に反対側も選ぶ） | 未。実機で必要性を判断 |
| ペンのホバーでプリセレクションハイライト | 未。ペンだけ可能。細かい頂点を狙うときに効く |

### 3. モデリング機能の残り（v1.0 の必須分）

優先順。上から順に着手する。

| 機能 | 難度 | 備考 |
|---|---|---|
| **ベベル**（エッジ、セグメント数、幅） | 高 | 最も使われる未実装機能。四角形メッシュ限定で始める |
| **ブリッジ**（2 つのエッジ列 / 面を繋ぐ） | 中 | エッジ列の対応付けが要る |
| **ターゲットウェルド**（頂点を頂点へドラッグして統合） | 中 | タブレットと相性が良い。ツイークの延長で実装できる |
| **マージ（距離指定）** | 低 | `weldVerts` で済む |
| **頂点の削除（周囲の面を 1 枚に）** | 中 | エッジ削除の頂点版 |
| **接続（Connect）** | 中 | 選んだ頂点 / エッジの間に辺を通す |
| **スナップ**（グリッド、頂点、エッジ） | 中 | CTL ラッチをスナップに割り当てる案。Maya は X / V / C |
| **面の複製 / 抽出、結合 / 分離** | 低〜中 | オブジェクトの編集メニューに空きがある |
| **ミラー（ジオメトリ）** | 低 | 対称編集とは別。片側を反転コピーして縫う |
| **頂点の押し出し** | 低 | 現状「未対応」と出す箇所 |
| **数値入力**（トランスフォームの値を打つ） | 低 | オプションパネルの表示だけを入力可能にする |

### 4. ファイル形式（v1.0 の範囲）

| 形式 | 状態 |
|---|---|
| OBJ 読み書き | **済み**。ポリグループ（`g`）の保持を追加する |
| **FBX 読み込み** | ufbx を wasm にビルドして組み込む。Maya との往復に必須 |
| FBX 書き出し | 自前実装。7.4 バイナリ。メッシュ・階層・法線に絞る |
| USD 書き出し | クリースを持てる唯一の形式。ただしクリース編集を入れてから |
| PNG スクリーンショット | 共有用。キャンバスから 1 行 |

### 5. マルチ解像度の検証（並行して、JS で）

`08` の指示書をそのまま `core/` の中で実装し、vitest で V1〜V6 を通す。v1.5 の差別化の核なので、v1.0 の機能追加と**並行**して進める。順序を後ろにしない。

### 6. タブレット固有の詰め

| 項目 | 内容 |
|---|---|
| 縦持ちレイアウト | iPad mini の縦持ちで右パネルを折りたたむ、または下に移す |
| パネルの幅変更 | ドラッグで右パネルの幅を変える |
| 触覚フィードバック | マーキングメニューの仮選択とスナップ時に `navigator.vibrate`（Android）。iOS は不可 |
| Apple Pencil のダブルタップ | Safari では取れない。PWA でも不可。Capacitor 化のときにネイティブで拾う |

### 7. 配布

1. PWA（今のまま。Mac 不要）
2. Android: Capacitor で包み、Windows からビルドして Play Store
3. iOS: Capacitor + GitHub Actions の macOS ランナーでビルドして App Store（Mac 不要だが Apple Developer 登録は必要）

## 着手順

1 の土台 → 2 の残り → 3 のベベル・ターゲットウェルド → 5（並行）→ 4 の FBX 読み込み → 3 の残り → 6 → 7。

**1 を飛ばして 3 に進まないこと。** 今の単一ファイルにベベルを足すのは、テストなしで一番壊れやすい処理を一番読みにくい場所に置くことになる。
