作成: 設計担当。実装担当（Opus）向け。2026-09-10。

## 0. 決めたこと

**カメラの切り替え（ZBrush 式 / Maya 式）は作らない。** 完全な 2 系統にすると
ジェスチャを 1 つ足すたびに 2 回設計して 2 回確かめることになる。しかも実際に
ぶつかるのは「Alt の意味」と「右ドラッグ」の 2 つだけで、どちらも Maya 側を残す
価値のほうが高い（右クリックのマーキングメニューはこのアプリの柱。`04` の 4.4）。

タブレットは**すでに ZBrush 式**である（指 1 本はメッシュの上なら彫る・外なら
タンブル。`04` の 4.1。ZBrush for iPad も Nomad も同じ）。違うのは PC だけ。

| 操作 | うち（Maya） | ZBrush |
|---|---|---|
| 何も無い所を左ドラッグ | モデリング: 矩形選択 / **スカルプト: 何もせずトースト** | 回転 |
| Alt + 左ドラッグ | タンブル | パン |
| 右ドラッグ | マーキングメニュー | 回転 |

困るのは 1 行目。**スカルプト中に何も無い所をペンやマウスで引くと、今は何も
起きない。** これは切り替え無しで直せる（今は何もしていない所なので、Maya 派が
失うものが無い）。

代わりに入れるのは 5 つ。どれも小さい。

| 順 | 中身 | 理由 |
|---|---|---|
| T1 | **スカルプト中はマニピュレータを消す** | 邪魔なだけでなく、指がハンドルに乗るとタンブルもできず彫りにも失敗する |
| T2 | **スカルプト中、何も無い所をペン / マウスで引いたらタンブル** | ZBrush / Nomad / ZBrush for iPad が全部この動き。今は何もしていない |
| T3 | **タンブルの中心を `04` の規則にする**（両モード） | 今は `cam.target` を回っていて、パンのあとに模型が画面を横切る（Maya のブレ）。`04` で決めた規則がズームにしか入っていない |
| T4 | **SHF を立ててタンブルすると軸の向きに吸着** | ZBrush の Shift。材料（標準ビュー 6 つ、SHF）はそろっている |
| T5 | **「指はカメラだけ」の切り替え** | Pencil を持っているとき、添えた指が模型に触れて彫るのを防ぐ。`04` で予定済み、旗はもうある |
| T6 | 門（通し確認と実機の確認項目） | |

**T6 が終わったら報告して止まる。** 実機の確認は `34` の分と一緒にしてもらう。

T3 と T4 は**モードで分けない**。ブレはモードの好みではなく `04` の規則が
入っていないだけで、モデリングでも嫌われる（Maya 使いは F を連打して逃げている
だけ）。分けると「モデリングから戻ったらカメラの手触りが変わる」が起きる。

## T1. スカルプト中はマニピュレータを消す

### なぜ「邪魔」で済まないか

`app.ts` の `isOnMesh`（`gestures.ts` が「ツールの対象か」を訊く所）は、
**マニピュレータのハンドルもツールの対象に数えている**（指で直接つかめるように。
`04` の方針）。だからスカルプト中に指がハンドルへ乗ると:

1. `isOnMesh` が true → タンブルにならず「ツール」になる
2. `startTool` はスカルプトモードなので `stroke.begin` へ行く
3. ハンドルは面ではないので当たらず、**「モデルの上をなぞってください」のトースト**

つまりハンドルは指を奪ったうえで失敗する。ZBrush も Nomad も、変形ツールを
選んだときだけギズモを出す。

### 直す

- `refreshManipulator()`: `tool !== "select"` に加えて **`mode === "sculpt"` でも
  `clear()`**
- `isOnMesh` ハンドラ: **スカルプト中はハンドルを見ない**。`clear()` してあれば
  `pick` は外れるはずだが、そこに頼らず明示的に飛ばす（後で誰かが `clear` の
  順番を変えても壊れないように）
- モードを切り替えたとき（`setMode`）に `refreshManipulator()` が走ることを確かめる。
  スカルプト → モデリングで戻ってくること

### 失うものが無いこと

スカルプト中のオブジェクトの変形は **3 本指**（つまむ / スワイプ / ひねり。
`25` の T2、`26` の T1〜T3）でできる。あれはギズモに依っていない
（`beginGestureTransform` はピボットだけ見る）。PC のキー（W / E / R）で
`state.manip` が変わっても、スカルプト中は何も出ないだけ。

## T2. 何も無い所をペン / マウスで引いたらタンブル

### いま

`gestures.ts` の `pointerdown`: **touch だけ**が `isOnMesh` を訊いて、外なら
タンブルにしている（457 行目あたり）。pen と、Alt 無しのマウス左は、必ず
「ツール」へ行く。モデリングではそれが正しい（何も無い所からの左ドラッグは
矩形選択。Maya と同じ）。

スカルプトでは矩形選択が無いので、何も無い所の左ドラッグは `stroke.begin` が
外れてトーストになるだけ。

### 直す

**スカルプトモードのときだけ**、pen と Alt 無しマウス左も touch と同じ道に乗せる。

- `GestureHandlers` に `freeDragTumbles(): boolean` を足す。app 側は
  `state.mode === "sculpt"` を返す
- `pointerdown` の touch の枝を
  `if (e.pointerType === "touch" || this.h.freeDragTumbles())` にする。
  中身はそのまま（`isOnMesh` が false ならタンブル + `startMarkingHold`）
- **マウスの Alt / 中 / 右の枝はこの前にあるので触らない。** Alt + 左は今までどおり
  タンブル、右はマーキングメニュー

### 決め

- **メッシュの上に着いたら今までどおり彫る。** 変えるのは「何も無い所」だけ
- **選んでいない別のオブジェクトの上**は「何も無い所」ではない。今までどおり
  ツールへ行って、言い訳（`strokeHint`）が出る。タップで選び直す動きは
  ここでは入れない（`やらないこと`）
- ペンで何も無い所を**長押し**したときのマーキングメニューは残す
  （`startMarkingHold` をそのまま呼ぶので、動かさずにいれば開く。動けば
  タンブルになって長押しは取り消される。指と同じ）
- `fingerCam`（T5）が立っているときは、**指はメッシュの上でもタンブル**。
  pen はこの旗を見ない（ペンは常にツール。`04` の大原則）

## T3. タンブルの中心を `04` の規則にする

### いま

```
tumble(dx, dy)    → cam.target のまわりを回る（Maya の COI そのもの）
pan(dx, dy)       → cam.target を動かす
dollyAbout(pivot) → ピボットが画面で動かないズーム（こちらは 04 どおり）
```

パンで `target` が模型の外へ出たあとにタンブルすると、**模型が画面を横切る**。
`04` の 4.2 は「回転の中心は指の下の点、外ならオブジェクトの中心」と決めているが、
それが入っているのは**ズームだけ**（`zoomPivot`）。タンブルは受け取ってすらいない。

### 直す

`Viewport` に **`tumbleAbout(pivot, dx, dy)`** を足す。`dollyAbout` と同じ考え方。

1. `target` を `pivot` のまわりに、θ の増分だけ**ワールドの上軸**で回し、
   φ の増分だけ**カメラの右軸**で回す
2. そのあと `theta` / `phi` を今までどおり増減する（φ の 0.05 の詰めもそのまま）

カメラの位置は `target + 球座標(θ, φ, 距離)` なので、`target` と球座標の両方を
同じ回転で回せば、カメラは `pivot` のまわりを回る。距離は変わらない。

`GestureHandlers.tumble` に `pivot` を渡す（`zoomPivot` と同じ形で、
**ジェスチャの始まりで 1 回**取って `gesture.pivot` に持つ。ドラッグ中に
取り直さない。毎コマ更新すると滑る。`04` の 4.2）。

### 中心の決め方（両モード共通）

| 状況 | 中心 |
|---|---|
| コンポーネントを選んでいる | 選択の箱の中心（`pivotWorld` がもう返す） |
| 指 / ペンの下に面がある | その点（`pickSurface`。`fingerCam` のときや、`36` の T2 で外から始めたあと面に入った場合ではなく、**始まりの点**で決める） |
| 外 | 選んでいるオブジェクトの中心（`pivotWorld`）。無ければ**全体の箱の中心**（`frameSelected` が計算しているもの） |
| 何も無い | 今までどおり `cam.target` |

`pivot` が null なら今までどおり `tumble(dx, dy)`。挙動が変わるのは「中心が
`target` と違うとき」だけなので、F を押した直後（`target` = 模型の中心）は
今までと同じに見える。

### 見ること

- パンで模型を画面の端に寄せてからタンブル → **模型の画面上の位置がほぼ動かない**
  （箱の中心を画面に落として、前後で数 px 以内）。今は大きく動く
- 距離が変わらない。F の直後は今までと同じ角度になる

## T4. SHF を立ててタンブルすると軸の向きに吸着

ZBrush の Shift。回転中に Shift を押すと、いちばん近い軸の向きに吸着する。

### 決め

| 要素 | 決め |
|---|---|
| 発動 | **SHF が立っている間のタンブル**。タブレットは SHF をラッチしてから指 1 本、PC は Shift + Alt + 左 |
| 吸着先 | カメラの視線ベクトルの成分がいちばん大きい軸。**6 つ**（前・後・左・右・上・下）のどれか |
| 角度 | `STANDARD_VIEWS` の θ / φ をそのまま使う。真上・真下の φ のずらしも同じ |
| 投影 | **変えない**。角度だけ吸着する（ZBrush もそう）。カメラメニューから選んだときの「上は平行投影」とは別 |
| ドラッグ中 | **生の角度は別に積む。** 吸着した値を `cam` に書き戻すと、次の小さな動きで同じ向きに吸着し直して隣の向きへ行けない。ジェスチャに `rawTheta` / `rawPhi` を持ち、そこへ増分を足し、`cam` には吸着した値を入れる |
| 離したとき | 吸着した角度で確定 |
| 中心 | T3 の中心をそのまま使う |

SHF はスカルプトの一時スムースでもある（`34` の T3）が、指のタンブルとペンの
ストロークは別の道なので両立する。タンブル中の SHF にはまだ何も割り当てて
いないので、ぶつからない。

### 見ること

- SHF を立て、斜めから少し引く → 6 つのどれかの角度に**ちょうど**なる
  （`STANDARD_VIEWS` の値と一致）。引き続けると隣の向きへ移る
- SHF を切って引く → 吸着した所から自由に回る
- 投影は変わらない（パースのまま）

## T5. 「指はカメラだけ」の切り替え

### いま

`gestures.ts` に `fingerCam = false` がある。立てると指は常にカメラになる
（`isOnMesh` を訊かない）。**UI が無い。** `04` の 4.1 で「ペンのみツール /
指でもツール」として予定していたもの。

### 直す

- 上段の「表示」の、「左利き」と同じ並びに **「指はカメラだけ」** を足す。
  同じ `item(...)` の作法で、同じ仕組みで残す（他の表示の設定と同じ）
- `state.ui.fingerCamera: boolean`（既定 **false**）。`gestures.fingerCam` に
  流す。既定を false にするのは、ZBrush for iPad も Nomad も既定は「指でも彫れる」
  だから。ペンを持っていない人（Android の指だけ）が最初に触って何も彫れない
  ほうが困る
- モデリングでも効く（指が常にカメラになるので、ツールはペンだけ）。
  スカルプト専用にしない

### 名前

「指はカメラだけ」。「ペンのみツール」だと、ペンが無い端末で何のことか分からない。

## T6. 門

### 通し確認（`scripts/smoke.mjs`）

**終わったらモード・選択・カメラ・`fingerCam` を必ず戻す**（`33` で 3 回引っかかった）。

1. スカルプトに入るとマニピュレータの group が空になり、モデリングへ戻すと
   出る。**スカルプト中に指をハンドルのあった場所へ置いて引くと、タンブルになる**
   （カメラの `theta` が動き、トーストが出ない）
2. スカルプトで、何も無い所からペンで引く → カメラが動く（`theta` が変わる）。
   メッシュの上から引く → 彫れる（頂点が動く）。**モデリングでは**何も無い所から
   ペンで引くと矩形選択のまま（カメラは動かない）
3. スカルプトで、何も無い所をペンで**動かさず長押し** → マーキングメニューが開く
4. **パンで模型を端へ寄せてからタンブル → 模型の画面上の位置が数 px 以内**
   （箱の中心を画面に落として前後で比べる。今は大きく動く）。距離は変わらない
5. SHF を立てて斜めから引く → `STANDARD_VIEWS` のどれかと角度が一致。
   投影は変わらない。切って引くと自由に回る
6. 「指はカメラだけ」を入れて、指をメッシュの上に置いて引く → 彫れずにタンブル。
   ペンは彫れる。切ると指でも彫れる
7. 「指はカメラだけ」が保存され、開き直しても残る（他の表示の設定と同じ経路）

### 実機で見てもらうこと（報告に書く。`34` の分と一緒に）

1. スカルプトでギズモが出ない。**モデリングへ戻すと出る**
2. スカルプトで、模型の外をペンで引くと回る。**模型の上は彫れる**
3. **パンで模型を端に寄せてから回す。模型がその場で回るか**（前は画面を横切った）
4. SHF を押したまま回す。正面・真横・真上にカチッと止まるか
5. 「表示」→「指はカメラだけ」を入れて、Pencil で彫りながら添えた指が模型に
   触れても彫らない
6. ZBrush に慣れた人が触って**「これで困る所」があるか**。あれば具体的に
   （どの操作を、どうしたかったか）

## 決めてあること

- カメラの 2 系統切り替えは作らない。Alt の意味と右ドラッグは Maya のまま
- **タンブルの中心と SHF の吸着はモードで分けない**
- 回転の中心はジェスチャの始まりで 1 回決めて、ドラッグ中は固定
- SHF の吸着は角度だけ。投影は変えない
- 「何も無い所」= レイがどのオブジェクトにも当たらない所。選んでいない
  オブジェクトの上は含めない
- ペンは `fingerCam` を見ない（ペンは常にツール）
- 「指はカメラだけ」の既定はオフ

## やらないこと

- ZBrush 式のカメラ一式（Alt でパン、右ドラッグで回転）
- スカルプト中のギズモ表示の切り替え（欲しくなったら ZBrush と同じで
  「変形」ツールをスカルプトの列に足す。今は要らない）
- 選んでいないオブジェクトをタップで選び直す（`05` の「タップで選ぶ」は別の話）
- 2 本指タップで取り消し（`04` で「任意」）
