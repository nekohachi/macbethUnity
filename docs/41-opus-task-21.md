## T1. X 対称を厳密に

### いま

`stroke.ts` の `stamp()`: 対称なら鏡映した点で `hit()` をもう 1 回（`excludeNearX` で
中心線の頂点は 2 回目を飛ばす）。**幾何で対称にしている**だけで、頂点どうしの
対応は見ていない。

ずれる理由は 3 つ:

1. 2 回目の `localNormals` / `localPlane` は**1 回目が動かしたあと**の位置から取る
2. 中心線の頂点（`|x| < radius × 0.01`）は 1 回目だけ動く。Standard の法線 1 本には
   わずかに x 成分があるので、中心線が片側へ寄る
3. スムースの隣の平均も同じ（1 回目のあとの位置を読む）

### 継ぎ目（中心線の筋）の本当の原因

`33` の T4 は「中心線の頂点が 2 回動くと筋が出る」として `excludeNearX` で
2 回目を飛ばした。**これが逆だった。** 筆が中心線をまたぐと、中心線の**隣**の
頂点は 1 回目と 2 回目の**両方**から減衰ぶんを受ける（鏡映した筆からの距離は
中心線を挟んで連続なので、x = +ε も −ε も 2 つの筆の和）。中心線だけ 1 回に
すると、**そこだけ半分**になって溝（筋）になる。

ZBrush も 2 つの筆が両方とも中心線に当たる。筆が中心線の真上なら全部が 2 倍で
一様。だから **`excludeNearX` は外す**（渡さない。core の口は残してよい）。
`tests/sculpt.test.ts` の「鏡映して 2 回当てても、中心線が二重に動かない」は
**逆の約束を固めているので書き換える**（下のテスト）。

ZBrush は **Topological Symmetry**: 頂点ごとに鏡映の相手を持ち、片側の変位を
相手へ写す。これなら差は浮動小数の丸めだけ。

### 直し

**鏡映表を作って、流すときに +側を −側へ写す。**

#### 鏡映表（core）

`src/core/symmetry.ts`（新設）:

```ts
/** 頂点 v の鏡映の相手。無ければ -1。中心線（|x| < tol）の頂点は自分自身。 */
export function buildMirrorMap(positions: Float32Array, vertexCount: number, tol: number): Int32Array;
```

- `tol` は境界箱の対角 × 1e-4（`fitBrushRadius` の対角と同じ計算）
- **整数の格子ハッシュ**で引く（`tools/softSelect.ts` の `mirrorPairs` は文字列キーの
  `Map` で、25 万頂点で数百 ms かかるうえヒープが太る）。`Math.round(y/tol), round(z/tol), round(|x|/tol)` を
  1 つの整数に畳んで `Int32Array` を並べ替え、二分探索。または `sculpt.ts` の
  `scratch` と同じ考えで、格子番号 → 先頭の頂点の CSR
- 相手が複数（同じ場所に重なった頂点）なら最初のもの。**自分自身が相手の相手で
  なければ -1**（片側だけ密度が違う所は対称にしない）

#### どこに持つか

段ごとに違う（頂点番号が段で変わる）。`app/levels.ts` の `levelsOf(o)` の隣に
`mirrorMapOf(o, level): Int32Array | null` を置き、`SceneObject` に
`mirrorMaps: Map<number, Int32Array>` で控える。

- **トポロジが変わったら捨てる**（`document.ts` の `markTopologyChanged` で
  `mirrorMaps.clear()`。`34` のマスクと同じ場所）
- 段を足したときは、その段で初めて要るときに作る（細分割は対称を保つので、
  ベースが対称なら段も対称）
- 作るのに 25 万頂点で何 ms かかるかを bench に足す（**B8**）。対称のスイッチを
  入れた最初のストロークで 1 回だけ払う

#### 写す（`stroke.ts` の `flush`）

`Live.primarySign`（押した点の x の符号。0 なら +1）を持つ。`flush()` で
`sculptAt` の**前**に:

```
for v in pending:
  m = mirror[v]
  if m < 0: continue                    // 相手なし。今まで通り（2 回目の当たりが動かしている）
  if m === v: p[v].x = 0                // 中心線はぴったり 0 に
  else if sign(p_before[v].x) === primarySign:   // +側（押した側）が正
      p[m] = (-p[v].x, p[v].y, p[v].z); pending.add(m); touched.add(m)
```

- 「どちらが正か」は**押した側**。押した側の頂点が動いていて、相手が動いていなくても
  写す（範囲が中心線を跨いでいないときの対称もこれで出る）
- **履歴**: 写す前に `history.trackSculpt` で相手の控えを取る（`hit()` が `fp.verts` で
  取っているのと同じ。相手が 2 回目の当たりの範囲に入っていれば取れているが、
  入っていないこともある）
- **マスク**（`34`）も同じ場所で `mask[m] = mask[v]`
- ムーブの掴み（`39` の T5）も `flush` を通るので、そのまま効く
- 2 回目の当たり（鏡映した点）は**残す**。相手が無い頂点（非対称なトポロジ）は
  それで動くし、法線・平面の初期値も鏡映側で作れる。写しで上書きされるので
  結果は厳密
- **`excludeNearX` は渡さない**（上の「継ぎ目」）。中心線は 2 つの筆の両方から受け、
  そのあと `x = 0` に置く

#### 対称の判定に使う x

`p_before[v].x` は**動かす前**の x（動いたあとは中心線を跨ぐことがある）。
`hit()` で `trackSculpt` した控え、または `flush` の入口で `pending` の x を
拾って符号だけ持つ（`Int8Array` を `pending` と一緒に）。簡単なほうでよい。

### 反対側にもカーソル（T1b）

対称オンのとき、`viewport.showBrushCursor` は**鏡映した点にも輪を出す**
（ローカル `(-x, y, z)`。ZBrush の赤い 2 つ目のサークル）。輪は 2 本目の `Line` を
同じ作りで持ち、対称オフなら隠す。`brushCursorForTest` は 2 本目の中心も返す。

### テスト

- core `tests/symmetry.test.ts`:
  - 球（対称）: 全頂点に相手があり、`mirror[mirror[v]] === v`。中心線は自分自身
  - 片側だけ細分割した板: 細かい側の余った頂点は -1
  - **写しの結果**: 球に Standard を `(0.3, 0.9, 0.2)` で対称に当てて、全頂点で
    `p[v] === mirror(p[mirror[v]])`（差 1e-6 以下）。**前の方法でどれだけずれていたか**
    （最大の差）も報告に書く
  - **継ぎ目**: 板に Standard を中心線の真上 `(0, 0, 0)` で対称に当てると、
    **対称なしで 2 回当てたのと全頂点が一致**（中心線だけ半分にならない）。
    `(0.2, 0, 0)` で当てたときは、x 方向の断面（z = 0 の列）の高さが
    **x = 0 で折れない**（隣との差が、隣どうしの差の 2 倍以内）
- `tests/sculpt.test.ts` の「鏡映して 2 回当てても、中心線が二重に動かない」は
  **消して**、上の「継ぎ目」に置き換える（`excludeNearX` の単体テストは core の口の
  テストとして残してよい）
- 通し確認: 対称オン → 彫る → 最大の左右差 < 1e-6。ムーブとマスクも 1 回ずつ。
  対称オンでホバーすると輪が 2 つ、オフで 1 つ

## T2. 筆の大きさは対象の比率

### いま

`GAUGES.sculpt.g2` は `radius` を **0.01〜10 のワールド単位で線形**。
`fitBrushToSelection` が選び直したときに対角の 6.6% を入れる（`33`）。
半径 1 の球では 0.05〜0.5 しか使わないので、ゲージの下 5% に全部が詰まっている。

### 直し

**半径は今まで通りワールド単位**（`brushAt`、カーソル、`strokeFootprint` は触らない）。
**ゲージが比率を読み書きする。**

| 何 | 直し |
|---|---|
| 状態 | `brush.sizeRatio`（既定 0.066）。`localStorage`（`rememberBrush`）に残す。`brush.radius` は派生値: `sizeRatio × objectDiagonal(o)` |
| ゲージ | `GAUGES.sculpt.g2`: min 0.005、max 0.5（0.5%〜50%）、**`curve: "square"`**。`get` は `sizeRatio`、`set` は `sizeRatio` を書いて `radius` を計算し直す |
| 表示 | ゲージの数字は `6.6%`（`gauges.ts` の `v.toFixed(2)` を `AbsoluteGauge.format?` で差し替え） |
| 選び直し | `fitBrushToSelection` は「6.6% を入れる」ではなく「`sizeRatio × 対角`を入れる」。**比率は保つ** |
| 対角 | `objectDiagonal(o)`: `fitBrushRadius` の境界箱の計算を切り出す。**スタンプで控える**（`SceneObject` にトポロジ / 形のスタンプがあれば使う。無ければ `mesh.positions` の長さと `activeLevel` で。毎コマ 25 万頂点をなめない） |

`curve: "square"` は `gauges.ts` の `t ↔ value` の変換に足す:
`value = min + (max − min) × t²`、`t = sqrt((value − min) / (max − min))`。
0.066 はつまみの 35% あたりに来る。細かい筆に幅が出て、大きい筆も端で取れる。

ゲージの `set` は今 `s.brush[key] = v` を直接書いている（`gauge()` の `into`）。
`g2` だけ**関数を書く**（`radius` と `sizeRatio` の 2 つを更新するため。`state.ts` の
`gauge()` の注意書き「`s[into][key]` と書かない」はそのまま守る）。

### なぜ画面 px ではないか

ZBrush と Nomad は**画面の大きさ**（ズームしても輪の見た目が同じ）。
それも良いが、声は「対象に対する比率」だった。比率なら**ズームしても彫れる量が
変わらない**（同じ強さで同じ深さ）ので、筆圧の手触り（`33`）が崩れない。
画面 px は「表示」の切り替えとして後で足せる（`42` 以降）。

### テスト

- `tests/brush.test.ts`: ゲージを 0 → 1 に動かすと `sizeRatio` が 0.005 → 0.5、
  `radius` が対角 × 比率。2 乗のカーブ（つまみ 0.5 で 0.129）
- 通し確認: 球を選ぶ → ゲージ「6.6%」→ 大きい立方体を選ぶ → 半径が変わるが
  「6.6%」のまま

## T3. 輪は見える所へ、向きは指の動きで

### いま（`radial.ts` の `openRadial`）

```ts
const edge = RING_INNER + 24;
const cx = clamp(clientX, edge, innerWidth - edge)
```

中心を指からほとんど動かさない。理由は注釈にある通り、**寄せると指が押した瞬間から
西の区画に居て、上へ引いても北にならない**（段の「足す」が押せなかった）。
その代わり、左端のツール列では西半分（RING_OUTER 176px）が画面の外。

### 直し

**輪の位置と、向きの測り方を分ける。**

- 輪の中心 `(cx, cy)` は**輪が丸ごと見える所**へ寄せる:
  `edge = RING_OUTER + 12`、下に一覧があればその分も（今の `below` と同じ）
- 向きは**押した点 `(px, py)` からの指の動き**で測る:
  `onMove` の `dx = e.clientX − px`、`dy = e.clientY − py`（今は `− cx`）
- 一覧（輪の下の行）も同じ: 指の位置を `(e.clientX + (cx − px), e.clientY + (cy − py))` に
  ずらして行に当てる。**指を輪の分だけ平行移動したもの**で全部を判定する、と
  考えれば 1 行で書ける
- `DEAD_RADIUS`（中心の遊び）はそのまま。押した点からその距離だけ動かなければキャンセル
- 押した点に小さい点（r 4）を描く。「ここから引く」が見える。輪との間に細い線

これで「指の場所」と「輪の場所」がずれても、**引いた向きと選ばれるものは一致する**。
`33` の実機報告（段が足せない）は**向きを中心から測っていた**のが原因で、
寄せたことが原因ではなかった。注釈を書き換えること。

### テスト

- 通し確認: 筆のボタン（左端）を長押し → 輪の `<path>` の最小 x ≥ 0。押した点から
  真上へ 100px 引いて離す → 北の項目（スタンダード）が選ばれる。左端から
  **左上**へ引く → 北西（`38` の並びでチェッカーではなく筆のもの）
- 段の「足す」（北だけの輪）が、左端から上へ引いて押せる（`33` の報告の再現）
- 一覧（筆の一覧 3 つ）が、寄せた輪の下で指をずらして選べる

## T4. アウトライナの長押しがキャンセル誤爆

### いま（`panels.ts` の `attachOutlinerRow`）

- 一覧は `touch-action: pan-y`。輪が開いたあと指を動かすと、ブラウザが**縦スクロールを
  始めて `pointercancel`** を送る。`radial.ts` の `onUp` は `pointercancel` も
  「離した」と受け取るので、その瞬間の位置（ほぼ中心 = キャンセル）で閉じる
- 開く前も、420ms の間に 12px 動くと待ちが消える（タブレットの指はそれくらい動く）

### 直し

| 何 | 直し |
|---|---|
| スクロールを取られない | 行に `touchmove` を **`{ passive: false }`** で付け、**長押し待ち中（`timer !== null`）か輪が開いている間（`isRadialOpen()`）だけ** `preventDefault()`。それ以外は止めない（ふつうのスクロールは今まで通り） |
| 動きの許し | `MOVE_PX` 12 → **20**。`HOLD_MS` 420 → **320**（ツール列の 200 と一覧のダブルタップ 400 の間） |
| `pointercancel` | `radial.ts` の `onUp` は `pointercancel` では**確定しない**（選んでいても run しない、ただ閉じる）。誤爆で何かを実行するより、何も起きないほうがよい |
| 目の長押し（不透明度） | 同じ行にあるので同じ `touchmove` の止め方を入れる（`attachEyeOpacity`） |

ブラウザは**スクロールを始める前の `touchmove`** なら `preventDefault` で止められる。
始めたあとは止められない（`cancelable: false` になる）。だから**長押し待ちの間から**
止めておく。待ちが `MOVE_PX` で消えたら止めるのもやめるので、指を滑らせれば
そこからスクロールになる。

### テスト

- 通し確認: 行に `pointerdown` → 330ms 待つ → 輪が開く → `pointermove` を 30px →
  まだ開いている（`isRadialOpen()`）→ 北へ引いて離す → その項目が実行される
- `touchmove` を `cancelable: true` で流して `defaultPrevented === true`（待ち中と開いている間）、
  待ちが消えたあとは `false`
- `pointercancel` を送ると閉じるが、何も実行されない

| `buildMirrorMap(positions, vertexCount, tol)` → `{ mirror, side, paired }`。整数の格子ハッシュを CSR に並べて引く（文字列キーの `Map` は作らない）。**同じ格子で当たらなかったときだけ隣の 26 個**を見る。相互でない対（片側だけ密度が違う所）は外す | `src/core/symmetry.ts`（新設） |
| `boundsDiagonal(positions)` を core へ切り出し。`fitBrushRadius` と対称の許容の両方が使う | 同上 |
| `SceneObject.mirrorMaps: Map<段, MirrorMap>`。**一度作ったら持ち続ける**（左右非対称に彫ったあとの座標から引き直すと相手が見つからないが、対応そのものはトポロジの話なので彫っても変わらない）。`markTopologyChanged` で捨てる | `document.ts` |

**継ぎ目（中心線の溝）の原因は `excludeNearX` だった。** `33` の T4 は「中心線の頂点が
2 回動くと筋が出る」として 2 回目を避けていたが、逆。筆が中心線をまたぐと、中心線の
**隣**の頂点は 2 つの筆の両方から減衰ぶんを受ける。中心線だけ 1 回にすると**そこだけ
半分**になって溝になる。彫るほうも、マスクも、ムーブの掴みも、渡すのをやめた。
core の口（`StrokeInput.excludeNearX`）は残してある。

### T1b: 反対側の輪

`showBrushCursor(o, at, radius, mirror)`。輪を 1 本描く所を `paintRing` に切り出して
2 本目を持つ。**同じ点を X で折り返すだけ**（相手の面の上に乗るとは限らないが、
どこへ効くかは伝わるし、面を引き直すより桁で軽い）。`brushCursorForTest` は
2 本目の画面座標も返す。

### T2: 筆の太さは対象の割合

- `BrushState.sizeRatio`（既定 0.066）。**ゲージが読み書きするのはこちら**で、
  `radius` はそこからの派生（`radiusFor(o, ratio) = 対角 × 割合`、0.01〜10 で頭打ち）
- `AbsoluteGauge` に `curve?: "square"` と `format?` を足した。サイズは
  **0.5%〜50%、2 乗のカーブ**。既定の 6.6% はつまみの下から 35%
- 選び直しても**割合は保つ**（`fitBrushToSelection`）。`localStorage` にも残す
- 対角は**レベル 0 で測る**（段を上げても外形はほとんど変わらないので、
  25 万頂点をなめ直さない）

### T3: 輪は見える所へ、向きは指の動きで

`33` の実機報告（左端で段が足せない）を「寄せたせい」と読んでいたが、本当の原因は
**向きを輪の中心から測っていた**こと。**位置と測り方を分けた**:

- 輪は `RING_OUTER + 12` で画面の中へ寄せる（左端で押しても西半分が切れない）
- 向きと一覧の当たりは**押した点から**測る
- 押した点に丸を描き、輪まで細い線でつなぐ

### T4: アウトライナの長押し

- 行と目のボタンに `touchmove` を `{ passive: false }` で足し、**長押しを待っている間と
  輪が出ている間だけ** `preventDefault()`（スクロールは始まる前しか止められないので、
  待っている間から止める）
- `HOLD_MS` 420 → **320**、`MOVE_PX` 12 → **20**
- `radial.ts` の `onUp` は **`pointercancel` では決めない**（閉じるだけ）

### 直したついで（通し確認）
