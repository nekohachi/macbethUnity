## T1. 対称のグループ

### 決め

1. **対称はアプリに 1 つ。** `state.symX` だけにする。`brush.symmetryX` は**消す**
   （読んでいる所は全部 `state.symX` へ。`stroke.ts` の 4 か所、`app.ts` の 6 か所、
   通し確認の 10 か所）。モデリングで入れればスカルプトでも入っている。
   同じオブジェクトを 2 つのモードで行き来するのに、対称が別々に入っているのは
   「入れたはずなのに効かない」の元。
2. **既定はオフ**、`localStorage`（`macbeth.symX`）に残す。Maya はオフ、ZBrush はオン。
   モデリングで頂点を引いたら反対側も動くのは、知らずに起きると事故なので、オフから。
   スカルプトの人は 1 回入れれば残る。**スカルプトの既定がオン → オフに変わる**ので、
   `37` の実機の表 20 と 24 は「対称を入れてから」になる（表に書き足す）。
3. **ツール列に「対称」のグループ**を足す。両方のモード。
   - モデリング: 選択 / 変形 / 編集 / **対称** / スナップ / 表示 / カメラ / 分割 / 追加（9 つ）
   - スカルプト: 筆 / **対称** / マスク / レイヤー / 段 / 焼く / シェード / カメラ / 分割
   - アイコンは `ICONS.sym`。**タップで入り切り**、`pressed` と `X` のバッジは `symX`
   - 筆のボタンの `X` バッジと、筆の一覧の「対称を入れる / 切る」は**消す**（置き場は 1 つ）
   - S キーと HUD の「対称X」はそのまま
4. **長押しの輪**
   | 方位 | 項目 | 中身 |
   |---|---|---|
   | N | 対称を入れる / 切る | `symX` の反転（タップと同じ） |
   | E | **対称に整える（+X → −X）** | 下を見る |
   | W | 対称に整える（−X → +X） | 同じ。向きが逆 |
   | S | ミラー | 今の `doMirror`（オブジェクトモードだけ出す） |
   オプション（カットイン）には `mirrorSection`（ミラーの軸 X / Y / Z）を**選択の
   オプションから移す**。ミラーの軸は対称の話なので、ここに居るほうが見つかる。
5. **相手は `41` の対応表。** `captureTarget` の `mirrorPairs` を `mirrorMapOf(o, 0, o.mesh)`
   に替える。`DragTarget.mirror` の形（`[from, to][]`）はそのまま:
   - 動かす頂点 `v` で `side[v] ≠ 0`、`mirror[v] ≠ v`、相手が動く側に居なければ組にする
   - **`mirror[v] === v`（中心線の頂点）は x を 0 に留める**（`stroke.ts` の 657 行と同じ）。
     `transform.ts` の `apply` と `applyGestureTransform` の「相手側を書く」所で、
     組に加えて**留める頂点の一覧**も持つ（`DragTarget.pinX: number[]`）
   - 両側とも動く組は今までどおり各自が動く（写さない）
   - 対応表が `null`（対が 1 つも無い）なら、入れたときに
     「対になる頂点がありません。「ミラー」で半分から作れます」と出す。効きはしない
   `softSelect.ts` の `mirrorPairs` は**消す**（残すと次にまた使われる）。
6. **対称に整える。** 対応表の組 `(a, b)`（`a` が +側）ごとに
   `p[b] = (−p[a].x, p[a].y, p[a].z)`、中心線の頂点は `x = 0`。
   座標だけなので履歴は差分（`pushPositions` の道）。名前は「対称に整える」。
   トーストに「n 頂点を写した · 中心線 m 頂点」。
   対応表が無ければ「対になる頂点がありません」。
   **左右非対称に触ったあとでも効く**（対応表はトポロジの話なので持ち続けている。`41`）。

### つなぐ

- `state.ts`: `symX` の読み書きを `localStorage` に。`brush.symmetryX` を消す
- `app.ts`: グループの追加（両モード）、`symmetryMenu()`、`doSymmetrize(sign)`、
  `captureTarget` の差し替え、筆のバッジと一覧の項目を消す、`selectOptions` から
  `mirrorSection` を外して対称のオプションへ
- `transform.ts`: `DragTarget.pinX`。`apply` と `applyGestureTransform` の両方で留める
- `stroke.ts`: `brush.symmetryX` → `state.symX`

### テスト（通し確認）

- ツール列は **9 つ**（`44-1` の「8 つ」を直す。`sym` が入っていること）。
  スカルプトの列にも `sym` がある
- 対称のボタンをタップ → `state.symX` が真、バッジ `X`。もう一度で消える。
  `localStorage` に残る
- 対称オンで +X の頂点を Y に引く → 相手（−X）も同じ Y に動く。**中心線の頂点を X に
  引いても x が 0 のまま**
- +X の頂点だけを動かして非対称にする → 「対称に整える（+X → −X）」→
  全頂点で `|p(a).x + p(b).x| < 1e-6`、y・z が一致。履歴に「対称に整える」。取り消しで戻る
- スカルプトの `X 対称` の通し確認（`41`）が、`state.symX = true` を入れてから通る

## T2. マニピュレータの向き

### 考え

`AXES`（ワールドの定数）が 3 か所に直に入っている。

| 所 | 使い方 |
|---|---|
| `render/manipulator.ts` | 矢印・箱・リングを描く（`rebuild`）、当たり（`pick`） |
| `tools/transform.ts` | ドラッグの軸（`beginDrag` の `t0`、`updateDrag` の移動・回転・スケール） |
| `app.ts` | ピボットのドラッグ（`beginPivotDrag` `updatePivotDrag`） |

**向きの「枠」（3 本の単位ベクトル）を 1 つ作って、この 3 か所へ渡す。**
`AXES` はワールドの枠を作るときにだけ使う。

Maya の移動ツールの「軸の向き」は **オブジェクト / ローカル / ワールド / 法線**
（声の並びそのまま）。それぞれ:

| 種類 | 枠 | いまのこのアプリで |
|---|---|---|
| **ワールド** | X Y Z | 今と同じ。**既定**（Maya の移動の既定） |
| **オブジェクト** | オブジェクトの回転を掛けた X Y Z | `view.group.matrixWorld` の回転だけ（スケールは剥がす） |
| **ローカル** | **親の空間**の X Y Z | 親子はまだ無い（`19` の 4「グループ / 階層」は先送り）。**今はオブジェクトと同じ**。ヒントにそう書く。並びは Maya のままにして、階層が入ったときに意味が生える |
| **法線** | 選んだコンポーネントの平均法線 N と、それに直交する U V | コンポーネントのときだけ。**オブジェクトモードではオブジェクトと同じ**（Maya もそう） |

### 決め

1. `state.manipSpace: "object" | "local" | "world" | "normal"`。既定 `"world"`。
   `localStorage`（`macbeth.manipSpace`）。**設定は 1 つ**で、移動・回転・スケール・
   ユニバーサルの全部に効く（Maya は道具ごとだが、タブレットで 3 回選ぶのは無理）。
2. **オプションの「種類」**: `manipulatorSection` に segmented の行を足す。並びは
   **オブジェクト / ローカル / ワールド / 法線**。4 つのマニピュレータどれでも出す
   （回転だけのときに隠すと「効いているのに見えない」になる）。ヒント:
   「ローカルは親の空間です。いまは親が無いのでオブジェクトと同じです。
   法線は面・エッジ・頂点を選んだときの向きです」
3. **枠の作り方**（`tools/frame.ts`。DOM を触らない。three の `Vector3` は使ってよい）
   ```ts
   export interface Frame { axes: [Vector3, Vector3, Vector3]; labels: [string, string, string] }
   export function worldFrame(): Frame                       // X Y Z
   export function objectFrame(matrixWorld: Matrix4): Frame  // 回転だけ取り出す
   export function normalFrame(n: Vector3, hintU: Vector3 | null, fallback: Frame): Frame
   ```
   - `normalFrame`: `N` を正規化。`U` は `hintU`（エッジを 1 本だけ選んでいればその向き）を
     `N` に直交させたもの。無ければ `fallback.axes[0]` を直交化、それが `N` とほぼ平行
     （`|dot| > 0.9`）なら `fallback.axes[2]`。`V = N × U`。**並びは `[U, V, N]`**
     （赤 = U、緑 = V、青 = N。Maya の色分けと同じ）。ラベルは `["U", "V", "N"]`
   - 平均法線は app で出す: 面なら面積で重み付けた面法線の和、エッジと頂点なら両端 /
     その頂点の頂点法線の和。ワールドへは法線行列で。和がゼロなら オブジェクト に落ちる
4. **枠はドラッグの始めに固定**（`DragState.frame`）。動かしている最中に法線が変わっても
   矢印は回らない（Maya と同じ）。離したら `refreshManipulator` で取り直す。
   `Manipulator.rebuild` の署名に枠を入れる（枠が変われば描き直す）。
5. **通し方**
   - `Manipulator.rebuild(center, manip, sig, frame)` / `pick(p, center, manip, tolerance, frame)`。
     `AXES[a]` を `frame.axes[a]` に
   - `beginDrag({ ..., frame })` → `DragState.frame`。`updateDrag` の `AXES[drag.axis]` を
     `drag.frame.axes[drag.axis]` に。スナップで軸に落とす所も同じ
   - **コンポーネントのスケール**は軸の向きに沿って伸ばす: `r += (k − 1)(r · a) a`
     （今の `r.x * k` は軸がワールドのときだけ正しい）
   - **オブジェクトのスケール**は `transform.scale[axis]` に掛けるまま。TRS では
     オブジェクト軸に沿った伸び縮みしか表せない（ワールド軸で斜めに伸ばすと歪みになる）。
     **オブジェクト / ローカルの枠なら絵と効きが一致する**（いままでのずれが直る）。
     ワールド / 法線の枠で回したオブジェクトの箱を引いたときは、絵はその軸・効くのは
     オブジェクト軸のまま。ヒントには書かない（触って分かる範囲。Maya も同じ）
   - **回転**は枠の軸まわりのクォータニオン。`apply` が左から掛けるのでどの枠でも正しい
   - **ピボットのドラッグ**も枠に沿う
   - 3 本指のジェスチャ（`26`）は**ワールド軸のまま**（軸は「視線にいちばん近い
     ワールド軸 1 本」と決めた。枠を混ぜると指の方向と合わなくなる）
6. **変形のボタンのバッジ**: ワールドなら無し、オブジェクト `O`、ローカル `L`、法線 `N`。
   HUD の `hudHint`（ドラッグ中）の軸名は `frame.labels`（法線なら U / V / N）。

### テスト

- `tests/frame.test.ts`（3 つ以上）
  - `objectFrame`: Y に 90° 回した行列 → `axes[0]` が (0, 0, −1)。スケールが入っていても長さ 1
  - `normalFrame`: N = +Y、hint 無し → `U` が +X、`V` が (0, 0, −1)... **右手系**
    （`U × V = N`）であること。N が +X のときは fallback の Z から取る
  - `normalFrame`: hint が (1, 1, 0) → `U` は (1, 0, 0) に直交化される
- 通し確認
  - 立方体を Y に 45° 回す → 種類を **オブジェクト** → 赤の矢印を引く → 位置の変化が
    `dx ≈ dz`（ワールド X ではない）。**ワールド**に戻して引くと `dz ≈ 0`
  - 上面を選ぶ → 種類を **法線** → 青の矢印を引く → 頂点が +Y に動く（x・z は変わらない）。
    バッジが `N`
  - 回したオブジェクトを **オブジェクト** の枠で赤の箱で伸ばす → `transform.scale[0]` だけ変わる
  - 種類が `localStorage` に残る

## 報告（2026-09-10。T1〜T4 済）

### T1: 対称のグループ

**対称はアプリに 1 つになった**（`state.symX`）。`brush.symmetryX` は消して、
`stroke.ts` の 4 か所と `app.ts` の 6 か所、通し確認の 10 か所をこれに寄せた。
モデリングで入れればスカルプトでも入っている。

- ツール列に「**対称**」のグループ。モデリングは 編集 の下、スカルプトは 筆 の下。
  タップで入り切り、バッジ `X`、長押しで 入切 / 整える（+X → −X · −X → +X）/
  ミラー（オブジェクトのときだけ）。オプションはミラーの軸（`mirrorSection` を
  「選択」からここへ移した）
- **既定はオフ**、`localStorage`。**スカルプトの既定がオン → オフに変わった**
- 相手は **`41` の対応表**（`mirrorTargets` を `levels.ts` に足した）。
  `tools/softSelect.ts` の `mirrorPairs`（座標を `toFixed(3)` の文字列で引く）は**消した**
- **中心線の頂点は x を 0 に留める**（`DragTarget.pinX`）。留めないと、中心線だけが
  相手なしに動いて左右が割れる。`apply` と `applyGestureTransform` の両方で効く
- 対になる頂点が無いメッシュで入れたときは、**その場で言う**
  （「対になる頂点がありません。「ミラー」で半分から作れます」）
- 「**対称に整える**」は座標だけなので履歴は差分（`beginPositions`）。
  **左右非対称に触ったあとでも効く**（対応表はトポロジの話なので彫っても変わらない）

ドラッグのたびに文字列の `Map` を作らなくなったぶん、掴み始めが軽くなった。

### T2: マニピュレータの向き

`AXES`（ワールドの定数）が**描画・当たり・ドラッグの 3 か所**に直に入っていたのを、
「枠」（`tools/frame.ts` の `Frame`）1 つに通した。`AXES` を読むのは `worldFrame()` だけ。

| 種類 | 枠 |
|---|---|
| ワールド（既定） | X Y Z |
| オブジェクト | オブジェクトの回転（**スケールは剥がす**。入れると矢印の長さと当たりがずれる） |
| ローカル | 親がまだ無いので**オブジェクトと同じ**。ヒントにそう書いた（`19` の 4） |
| 法線 | 選んだコンポーネントの平均法線 N と、直交する U V。**並びは [U, V, N]**（青が法線） |

- 設定は 1 つ（`state.manipSpace`、`localStorage`）で、移動・回転・スケールの全部に効く
- オプションの「**種類**」（segmented）と、変形のボタンのバッジ `O` / `L` / `N`
- **枠は押した時点で固定**（`DragState.frame`）。引いている最中に法線が変わっても矢印が回らない
- **コンポーネントのスケールを軸に沿わせた**: `r += (k − 1)(r · a) a`。
  今までの `r.x * k` は**枠がワールドのときしか合っていなかった**
- 平均法線は面なら面積の重み（Newell の生のベクトル）、エッジと頂点なら
  接している面を「選ばれたコーナーの数」だけ足す（＝頂点法線の和）。
  U は選んだエッジが 1 本ならその向き
- **枠は `refreshManipulator` で作って控える**。当たり判定（`pick`）は指を動かすたびに
  呼ばれるので、そこで法線の枠を作り直すとメッシュを毎コマ舐めることになる。
  引いている最中も作り直さない

オブジェクトのスケールは `transform.scale[軸]` に掛けるままにした。TRS では
オブジェクト軸に沿った伸び縮みしか表せない（ワールド軸で斜めに伸ばすと歪みになる）。
**オブジェクト / ローカルの枠なら、絵と効きが初めて一致する**（今までのずれが直った）。

### T3: マージの置き場

| いままで | いま |
|---|---|
| 変形の輪 SW = 距離でマージ | 変形の輪 SW = **ターゲットウェルド** |
| 編集の輪 SW = ターゲットウェルド | **消した**（`EditKind` から `"weld"` も外した） |
| — | 変形の輪の**下の一覧**に 距離でマージ / 中心にマージ（頂点モードのときだけ） |

溶接は道具ではなく、頂点を 1 つ掴んで別の頂点の上で離せばいつでも効く
＝マニピュレータのドラッグなので、変形が居場所として正しい。
頂点の文脈メニューと、変形のオプションのマージ距離はそのまま。
