# Opus 作業指示書 #26: S3-2 — 残りのベイク（曲率 / 位置 / ID / AO / 厚み）とタイル差分

作成: 2026-09-10。`45` のあと。`28` の **S3** の残り（`31` の 7 の 5 と 6）。
`44` で法線と高さは焼けるようになった。S3 はこの紙で終わり。

## 0. `44` で決まっていること（前提）

- **光線を飛ばさない。** ハイはローの細分割そのもので、UV の島も同じ場所を覆う
- ローは**レベル 0**、ハイは**いちばん上の段**
- テクセルごとに、ローをラスタライズ → 接空間、ハイをラスタライズ → その場で書く
- `BakeRecipe { size, padding, stamp }`、`SceneObject.bakeResult`（控え。`.mbz` に入れない）
- 2K で 49B/テクセル（約 205MB）。**溜めない**のが効く

## 1. 5 枚をどう出すか

| 絵 | 何 | 光線 |
|---|---|---|
| **曲率** | 尾根が白・谷が黒（Substance の Curvature） | 要らない |
| **位置** | ローの境界箱で正規化した位置（RGB） | 要らない |
| **ID** | 面のポリグループ（無ければマテリアル ID）の色分け | 要らない |
| **AO** | 上半球へ飛ばして遮られた割合 | **要る** |
| **厚み** | 裏（−法線）へ飛ばして当たるまでの距離 | **要る** |

### 決め: 光線は「**ハイの頂点ごと**」に飛ばす。テクセルへは補間で落とす

2K は 419 万テクセル。1 テクセル 16 本なら **6700 万本**で、JS では分どころか
十分に落ちる。**ハイの頂点は 23 万**（25 万四角形のレベル 2）なので、
頂点ごとなら 370 万本。しかも**テクスチャの大きさに関係なく同じ**（2K でも 4K でも）。

AO も厚みも**なめらかに変わる量**で、ハイはテクセルより細かい。
テクセルごとに飛ばしても、頂点ごとに飛ばして補間しても、絵はほとんど変わらない。
曲率もハイの頂点ごと（隣との差から出る量なので、もともと頂点の量）。

これは ZBrush や xNormal が「ハイの頂点色として焼いてから落とす」のと同じ考え方。

## T1. 光線の要らない 3 枚

### 出すもの（`BakeResult` に足す）

```ts
/** どの絵を焼くか。既定は法線と高さだけ（`44` と同じ重さ）。 */
export type BakeMap = "normal" | "height" | "curvature" | "position" | "id" | "ao" | "thickness";

export interface BakeResult {
  // …`44` のまま…
  /** 1 テクセル 1 バイト。焼いていなければ null。 */
  curvature: Uint8Array | null;
  ao: Uint8Array | null;
  thickness: Uint8Array | null;
  /** RGBA。焼いていなければ null。 */
  position: Uint8Array | null;
  id: Uint8Array | null;
}
```

**1 枚ごとに 1 バイト**（RGB が要るものだけ 4 バイト）。頼まれた絵だけ作る。
2K で曲率 + AO + 厚みを足しても +12MB。

### 決め

- **曲率**は頂点ごと。`c[v] = −Σ((p_u − p_v)·n_v / |p_u − p_v|) / 価数`
  （四角形の辺をなめる。`u` は面の次のコーナー）。
  尾根で正、谷で負。**8 ビットへは `128 + c × gain × 127`**（`gain` の既定 4）。
  平らは 128。ハイの法線は `44` の `buildFrames` がもう作っている
- **位置**は `(p_high − 箱の最小) / 箱の対角`。**箱はローで測る**（ハイで測ると、
  彫るたびに全部の色が変わる）。RGB、A は 255
- **ID** は `low.polygroup[f]`（全部 0 なら `low.materialId[f]`）。
  番号 → 色は**決め打ちの表**（黄金比で回す HSV。同じ番号なら毎回同じ色）。
  ラスタライズしているのはローなので、面の番号はそのまま取れる
- **埋める（dilate）のは焼いた絵ぜんぶ**。`44` の `dilate` を「チャンネルの一覧」に広げる

### テスト（core）

- 平らな板: 曲率がぜんぶ 128
- 山を彫った板: てっぺんが 128 より上（尾根 = 白）、裾が 128 より下
- 位置: 箱の端が 0 と 255 に来る。**ハイを動かしても箱はローのまま**
- ID: ポリグループが 2 つなら色が 2 種類。同じ番号は同じ色
- 頼まなかった絵は `null`（メモリを使わない）

## T2. AO と 厚み

### 決め

- **ハイの三角形で BVH を 1 つ作る**（`buildBvh`。`42` の再投影と同じ）
- 頂点ごとに、法線の側の半球へ `samples` 本（既定 **16**）。
  向きは**コサイン重み**（Hammersley の 2 次元列を半球へ写す。乱数を使わない＝
  同じ形なら毎回同じ絵）
- 始点は `p + n × eps`（`eps` = 箱の対角 × 1e-4）。自分に当たるのを避ける
- 当たった距離が `maxDist`（既定 = 箱の対角 × 0.5）**より近ければ遮られた**とみなす。
  遠くの当たりを数えると、閉じた形が全部真っ黒になる
- `ao[v] = 1 − 遮られた本数 / 本数`。**白 = 開けている**（Substance と同じ）
- **厚み**は同じ列を `−n` の側へ飛ばして、いちばん近い当たりまでの距離。
  `thickness[v] = 1 − 平均距離 / maxDist`。**白 = 薄い**
- テクセルへは頂点の値を重心座標で補間（法線や高さと同じ道）

### 速さ

`raycastBvh` はいちばん手前の当たりを返す（両面）。AO は「近くに何かあるか」だけ
知りたいが、**近い順に打ち切る仕組みは足さない**。まず素直に書いて測る（T5）。

### テスト（core）

- **開けた板**（1 枚の平面）: AO がほぼ 1（255 近く）
- **溝を彫った板**: 溝の底が縁より暗い
- **薄い板**（2 枚を近づけた箱）: 厚みが大きい（＝白い）。厚い所は黒い
- 本数を倍にしても値がだいたい同じ（±0.1）

## T3. タイルと差分焼き

`31` の 4 の「動いた頂点が触る升目だけ焼き直す」。

### 決め

- 升目は **256px** 固定（`TILE = 256`）。2K なら 8 × 8 = 64 枚
- `bakeMaps` に `only?: Uint8Array`（升目ごとに 0 / 1）と `into?: BakeResult` を足す
  - `only` があれば、**三角形の UV の外接する升目**が 1 つも立っていなければ飛ばす
    （テクセルごとの判定だけでは面をなめる時間が減らない）
  - `into` があれば、その配列に書き込む（作り直さない）
  - `covered` と `heightRange` は**焼いた升目のぶんだけ**取り直して、`into` の値と混ぜる
- app 側は `SceneObject.bakeDirty: Uint8Array | null`（控え。`.mbz` にも履歴にも入れない）
  - **ストロークを離したとき**（`stroke.ts` の `flush` のあと）、動いた頂点の UV から
    升目を立てる。ハイの UV はローと同じ島なので、ハイの頂点の UV をそのまま使う
  - レベル 0 を触った / トポロジを変えたときは**全部立てる**（形が丸ごと変わる）
- 「焼く」をタップしたとき、**焼いた絵があって升目が一部だけ立っていれば差分**、
  そうでなければ全部。トーストにどちらか出す

### テスト

- core: 升目を 1 つだけ立てて焼くと、そこだけ変わって他は前のまま
- 通し確認: 彫る → 升目が立つ → 「焼く」で差分（トーストに「n 升目」）→ 立っていた升目が消える

## T4. つなぐ（app）

- `BakeRecipe` に `maps: BakeMap[]` と `aoSamples: number`。既定は
  `["normal", "height"]` と 16。**`.mbz` に入れる**（`44` と同じ場所）
- **オプション（カットイン）に `bakeSection`**: 大きさ（1K / 2K / 4K）、
  焼く絵のチェックボックス 7 つ、AO の本数（4 / 8 / 16 / 32）
  - 大きさは長押しの輪からここへ移す（輪は方位が足りない）
- **長押しの輪**: N 焼く / E 触った所だけ焼く / W 全部焼く / S 書き出し（法線）
- **輪の下の一覧**に、焼いてある絵の書き出しを並べる（法線 / 高さ / 曲率 / AO /
  厚み / 位置 / ID）。焼いていない絵は出さない
- 書き出しは PNG。1 チャンネルの絵は**グレーに広げる**（`grayToBytes`）

### テスト（通し確認）

- 曲率と AO を入れて焼く → その 2 枚が `null` でない。入れていない絵は `null`
- 「曲率を書き出し」で 1024 × 1024 の PNG が落ちる
- 彫る → 「触った所だけ焼く」→ トーストに升目の数が出て、`bakeDirty` が消える

## 報告（2026-09-10。T1〜T5 済）

### T1: 光線の要らない 3 枚

`BakeResult` に `curvature` / `ao` / `thickness`（1 テクセル 1 バイト）と
`position` / `id`（RGBA）を足した。**頼まなかった絵は `null`**（作らない）。
`maps` に無い絵は 1 バイトも使わないので、既定（法線と高さ）の重さは `44` のまま。

- **曲率**は頂点ごと。隣が接平面のどちら側に居るかを辺の長さで割って平均する。
  尾根で正・谷で負、平らが 128。隣は面のコーナーの並びからなめる（`Map` を作らない）
- **位置**は**ローの箱**で正規化（ハイで測ると、彫るたびに全部の色が変わる）
- **ID** はポリグループ（全部 0 ならマテリアル ID）。番号 → 色は**黄金比で色相を回す**
  ので、隣の番号でも色が離れ、同じ番号なら毎回同じ色
- 埋める（dilate）のは**焼いた絵ぜんぶ**。1 枚だけ伸ばすと縁でその絵だけ色が変わる

### T2: AO と 厚み

**光線はハイの頂点ごと**（`46` の 1 の決め）。テクセルごとだと 2K で 6700 万本、
頂点ごとなら 370 万本で、しかも**テクスチャの大きさに関係しない**。

- 向きは**コサイン重みの半球**（Hammersley の列。乱数ではないので毎回同じ絵）
- AO は `occludedBvh`（**いちばん手前は探さない**。当たった時点で止める）を
  `bvh.ts` に足した。距離は箱の対角の 15%（Substance の Attenuation と同じ考えで、
  彫った溝や皺を出すのが目的なので近くでよい）
- 厚みは距離が要るので `raycastBvh`。**対角いっぱいまで見る**（半分にすると、
  球のように厚いものが「当たらない = 厚い」で全部黒くなる）

#### 指示書に無かった直し: **光線ごとに配列を作っていた**

`raycastBvh` は木を下る積み木（`Int32Array`）を**呼ぶたびに作っていた**。
ピッキングは 1 コマ数本なので誰も気づかなかったが、ベイクは 1 回で 700 万本飛ばす。
モジュールに 1 本置いて使い回すようにしたら、**56.0 → 47.8 秒**（15%）。
光線は再帰しないので 1 本で足りる。

### T3: タイルと差分焼き

- 升目は 256px 固定。`bakeMaps` に `only`（升目ごとの 0 / 1）と `into`（前の結果）
- **三角形の外接する升目が 1 つも立っていなければ、その面はなめない。**
  テクセルごとに見るだけでは、面をなめる時間が減らない
- `SceneObject.bakeDirty`。**ストロークを離したとき**に、動いた頂点の UV から立てる
  （`stroke.ts` の `end`）。焼いていないオブジェクトでは何もしないので掛かりは増えない
- レベル 0 を動かした / トポロジを変えたときは**全部立てる**（形が丸ごと変わる）

### T4: つないだ（app）

- `BakeRecipe` に `maps` と `aoSamples`（`.mbz` に入れる。古いファイルは既定へ）
- オプション（カットイン）に **`bakeSection`**: 大きさ 1K / 2K / 4K、焼く絵の
  チェックボックス 7 つ（法線と高さは土台なので外せない）、AO の本数 4 / 8 / 16 / 32。
  **大きさは長押しの輪からここへ移した**（絵が 7 枚になって方位が足りない）
- 長押しの輪: 焼く / 触った所だけ焼く（升目が立っているときだけ）/ 全部焼く / 法線を書き出し
- **輪の下の一覧に、焼いてある絵の書き出し**（焼いていない絵は出さない）
- タップは**升目が立っていれば差分**、そうでなければ全部

### T5: 門（CI・25 万四角形）

| 何 | 門 | 出た数字 | |
|---|---|---|---|
| **B10 2K の法線 + 高さ** | ≤ 5000ms（変えない） | **1765ms** | ✓ |
| **B11 2K の 曲率 + AO + 厚み** | ≤ 20000ms | **25265ms**（8 本） | **✗** |
| B6a ストロークの 1 コマ | 変えない | 18.5ms（`45` は 22.5ms） | ✓ |
| B5 いちばん使ったメモリ | — | 680.9MB | |

#### **B11 は門に届かなかった。正直に置く。**

| 直し | B11 |
|---|---|
| 素直に書いた（16 本） | 63.2 秒 |
| `occludedBvh`（当たったら止める）+ AO の距離を対角の 15% に | 56.0 秒 |
| **光線の積み木を使い回す**（呼ぶたびに `Int32Array` を作っていた） | 47.8 秒 |
| **本数を 16 → 8 に**（指示書の「超えるならサンプル数を下げる」） | **25.3 秒** |

中身は 23 万頂点 × 8 本 × 2 方向 = **370 万本**で、1 本あたり 6.8µs。
JS の BVH としては妥当な数字で、**ここから先は本数か頂点数を減らすしかない**。
4 本まで落とせば 13 秒ほどで門に入るが、AO がざらつく。

**大事なこと: 光線は頂点ごとなので、テクスチャの大きさを 1K に落としても速くならない。**
効くのは**段**（レベル 2 の 23 万頂点 → レベル 1 なら 5.7 万頂点で 4 分の 1）。

次の紙で決めてほしいのは 3 つ:

1. **25 秒を飲む**（押したときだけの 1 回きり。トーストで待たせる）
2. **既定を 4 本にする**（13 秒。ざらつきは「本数」で上げてもらう）
3. **AO だけ 1 つ下の段で飛ばす**（4 分の 1。細分割の並びは
   「頂点点 → エッジ点 → 面点」なので、レベル n の頂点の**先頭 V(n−1) 個**が
   そのままレベル n−1 の頂点。対応は取れる。ただし `bakeMaps` に段を渡す口が要る）

**いまは 1 を採って、既定 8 本で置いた。**

### テスト

- core **8 本**（`tests/bake.test.ts` は 7 → 15）
  - 頼まなかった絵は `null`
  - 曲率: 平らは 128、尾根は上、裾（折れ目）は下
  - 位置: 箱の端が 0 と 255。**ハイを動かしても箱はローのまま**
  - ID: ポリグループ 2 つで色が 2 種類。同じ番号は同じ色
  - AO: 開けた板は明るい。溝の底は縁より暗い
  - AO: 本数を倍にしても値はだいたい同じ（±0.25）
  - 厚み: 薄い箱ほど白い（**閉じた形でないと測れない**ので箱で見る）
  - 升目: 立てた所だけ焼き直す。立てていない升目は前のまま
- core + app **393**（385 → 393）
- 通し確認 `dist` と `app/` 緑（+3）

通し確認で 1 つ引っかかった: **球の AO は真っ白が正しい**（凸なので何も遮らない）。
「どこか暗いはず」と書いていた確認のほうが間違い。遮る形の AO は core のテスト
（溝を彫った板）で見ている。

### 実機で見てもらうこと

`37` の表の 42〜45。**AO は重い**ので、まず 1K か、本数 4 で試してもらいたい。
