（「スカルプト中のマテリアル表示」。`31` の 6 章）で、**v2.0 マテリアルの最初の一歩**でもある。

## 0. ねらい

`44` 〜 `46` で 7 種類の絵が焼けるようになり、`48` で外へ出せるようになった。
けれど**アプリの中では、焼いた絵を一度も見ていない**。いま確かめる方法は

1. PNG で書き出す
2. Blender か Substance で貼る

の 2 手で、「焼けているか」「向きが合っているか」を**その場で**見られない。
`31` の 6 章はこう書いてある:

> スカルプト中に**マテリアルの表示を重ねられる**（シェードの中身に「マテリアル」を足す）。

| # | いま | 直し |
|---|---|---|
| 1 | 焼いた絵はメモリにあるのに、画面はずっと灰色 | **T2**: 表示に**「マテリアル」**を足す。ローに法線マップと AO を貼る |
| 2 | 焼き直しても画面に何も起きない | **T3**: 焼いたら貼り直す（差分焼きは同じ配列なので `needsUpdate` だけ） |
| 3 | 向きが合っているかは Blender まで行かないと分からない | **T2**: **3D の見た目が答え合わせになる**。緑が逆なら凹凸が逆に見える |

**これは v2.0 のマテリアルそのものではない。** 塗り・レイヤー・マスクはまだ作らない。
「焼いた絵を貼って見る」だけ。だが `31` の言う
「調整のたびに往復しなくていい」の**いちばん手前の 1 段**がこれ。

## T1. 焼いた絵を three のテクスチャにする（`src/app/render/bakeTexture.ts`。新設）

### 決め

- `DataTexture` を**焼いた配列からそのまま**作る（PNG を経由しない。
  2K で 16MB の変換を挟む意味がない）
- **`flipY` は既定の false のまま。** 焼いた配列は行 0 が v = 0 で、
  WebGL も `flipY` が false なら行 0 が v = 0。**そのまま合う**
  （PNG に出すときだけ縦を返している。`44` の `rgbaToPng`）
- 持ち方は**オブジェクトごとに 1 組**（`view` ではなく `SceneObject` の脇）。
  ペインを分けても同じテクスチャを使い回す
- 中身:

```ts
export interface BakeTextures {
  normal: DataTexture | null;
  ao: DataTexture | null;
  /** 作ったときの焼き方（差し替えの判定に使う） */
  size: number;
}
/** 焼いた結果からテクスチャを作る / 使い回す。焼いていなければ null。 */
export function bakeTextures(o: SceneObject): BakeTextures | null
/** 焼き直したときに呼ぶ。同じ配列なら `needsUpdate` だけ、大きさが変われば作り直す。 */
export function refreshBakeTextures(o: SceneObject): void
export function disposeBakeTextures(o: SceneObject): void
```

- AO は**グレー 1 バイト**（`Uint8Array`）なので、`RedFormat` の `DataTexture` で貼る
  （RGBA へ広げると 2K で 16MB 無駄に食う）。three の `aoMap` は赤だけを見る
- 色空間は**両方とも線形**（`NoColorSpace`）。法線も AO も色ではなくデータ

### 気を付けること

- テクスチャは**捨てるのを忘れない**。オブジェクトを消したとき、トポロジが
  変わって焼き方が消えたとき、焼き直して大きさが変わったとき
- `.mbz` には入れない（焼いた絵自体が入らない。`44` の決め）

## T2. 表示「マテリアル」（`Display` に `material` を足す）

### 決め

1. `Display` に `"material"`。キーは **`M`**（数字はもう `0` まで埋まっている）
2. 「表示」の長押しの輪に **`SW`** で「マテリアル」（`28` の S3 の名前に合わせる）
3. 材質は `MAT.surf` の複製に **`normalMap`** と **`aoMap`** を足したもの
   （`view.material ??= materialPreview()`）。`MeshPhongMaterial` は両方とも持てる
4. **貼るのはローだけ**（いま見ている段が 0 のとき）。段を上げているとき
   （スカルプトの途中）は**法線マップを外す**。ハイには既に形として入っているので、
   重ねると二重にかかる。**AO は段を上げていても貼る**（形には入っていない）
5. 焼いていないオブジェクトは**素の灰色のまま**。トーストで
   「まだ焼いていません（焼くと絵が乗ります）」と 1 回言う
6. HUD の表示名は `MATERIAL`

### 接線

three は接線が無ければ**画面の微分**から接空間を組む（`normalMap` の既定）。
焼いた基底とは厳密には違うが、**見て確かめるには十分**。
`48` の T2 で `bakeFrames` を出せるようにしてあるので、
**ジオメトリに `tangent` を持たせるのは次の紙**（重さが増えるので、
見た目に差が出るか実機で見てから決める）。

## T3. 焼き直したら貼り直す

- `runBake` の終わりで `refreshBakeTextures(o)` → `applyDisplayAll()`
- **差分焼き**（`46` の T3）は同じ配列を書き換えるので、`needsUpdate = true` だけ。
  升目ごとの部分更新（`texture.addUpdateRange`）まではやらない
  （2K の転送は 16MB で数 ms。差分の口を作る手間に合わない）
- トポロジが変わって焼き方が消えたら（`markTopologyChanged`）テクスチャも捨てる

## T4. 門

- 単体テスト: `bakeTexture.ts` は three を触るので **通し確認で見る**
  （core + app の数は減らさない）
- 通し確認（`dist` と `app/`）に 2 件:
  1. 焼いて「マテリアル」にすると、面の材質に `normalMap` と `aoMap` が付く。
     **テクスチャの中身が焼いた配列と同じ**（先頭のテクセルを突き合わせる）
  2. 段を上げると法線マップが外れ、AO は残る。焼いていないオブジェクトでは
     素の材質のまま
- **焼く速さは変えない**（B10 / B11 に触らない）
- 表示を切り替えても例外が出ない（`43z` の表示の検査がそのまま通る）

### 実機で見てもらうこと（`37` の表に足す）

| # | 手順 | 期待 |
|---|---|---|
| 1 | 段を 2 つ足して彫る → 焼く → 表示「マテリアル」 | **ローに彫った凹凸が乗って見える**（段 0 のままなのに細かい形が見える） |
| 2 | そのまま光の向きを変える（回す） | 凹凸が光に正しく反応する（**逆さに見えたら緑が逆**） |
| 3 | AO も焼いてから見る | 溝が暗くなる |

## 報告（2026-09-11）

T1 〜 T4 すべて済み。**core + app 411 テスト**（`48` から変わらず。
新しいコードは three を触るので通し確認で見ている）。
通し確認は `dist` と `app/` の両方で緑（新しい検査 2 件）。

### T1. 焼いた絵をテクスチャに（`src/app/render/bakeTexture.ts`）

- `DataTexture` を**焼いた配列からそのまま**作る（PNG を経由しない）
- **`flipY` は false のまま。** 焼いた配列は行 0 が v = 0、WebGL も `flipY` が
  false なら行 0 が v = 0 で、**そのまま合う**。縦を返すのは PNG に出すときだけ
- AO は `RedFormat` の 1 バイト（RGBA に広げない）。色空間は両方とも `NoColorSpace`
- 持ち方はオブジェクト id の表で 1 組。オブジェクトを消したら `syncAll` で捨てる

### T2. 表示「マテリアル」

- `Display` に `"material"`、キーは **`M`**、輪は「表示」の **SW**
- 材質は `MAT.surf` の複製に `normalMap` と `aoMap`（`materialPreview()`）。
  地の色は少し明るくした（AO が掛かると沈むため）
- **法線マップはローだけ**（`shownLevel === 0`）。段を上げているときは形の側に
  既に入っているので外す。**AO はどの段でも貼る**（形には入っていない）
- 焼いていないオブジェクトは素の灰色のまま（材質そのものを差し替えない）
- **スカルプトに入っても「マテリアル」は外さない**ようにした（`31` の 6 章）。
  前は入った瞬間に「スムースシェード」へ切り替わっていた（`40` の T4）。
  自分で選んだ表示なので勝手に外さない

### T3. 焼き直したら貼り直す

- `runBake` の終わりで `refreshBakeTextures(o)` → `applyDisplayAll()`
- **差分焼きは同じ `Uint8Array` を書き換える**ので、送り直すだけ（テクスチャは同じもの）。
  大きさや AO の有無が変わったときだけ作り直す

### 通し確認に足した検査（2 件）

| 名前 | 見ているもの |
|---|---|
| マテリアル表示（ロー） | 法線と AO が貼られる・**焼いた配列そのもの**（写していない）・256px・`flipY` が false・HUD が `MATERIAL`・焼いていないものは素のまま |
| マテリアル表示（段） | 段を上げると法線が外れて AO は残る・段 0 に戻すと戻る・焼き直しても同じテクスチャ・別の表示にすると外れる |

### これで何が確かめられるようになったか

**焼いた絵の答え合わせが画面でできる。** 緑が逆さなら凹凸が逆に見えるし、
UV がずれていれば模様がずれる。`48` で Blender / Substance まで持って行かないと
分からなかったことが、その場で分かる。

### 残り（次の紙の候補）

- 接線をジオメトリに持たせる（いまは three が画面の微分から組んでいる）。
  実機で差が見えるか確かめてから
- v2.0 の本体（塗り・レイヤー・マスク）。`31` の 5 章
- B11 の 3 択（`46` の宿題。実機の数字待ち）
