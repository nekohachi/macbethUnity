## T1. 編集の輪にもマージ

`45` の T3 でマージを編集の輪から変形の輪へ移し、`52` で変形の輪の NW に置いた。
ただ**切ったあとに閉じる**のは編集の流れの中なので、そこから離れたくない、という声。

- 編集の輪は N / E / S / W / NW の 5 つしか埋まっていない。空いていた
  **SE を「距離でマージ」**、**SW を「中心にマージ」** にする
- 変形の輪からは**消さない**。どちらからでも出せてよい
- ターゲットウェルドは変形の輪だけに置いたまま（道具ではなく、頂点を掴んで
  離すだけで効くものなので、置き場は 1 つでよい）

## T2. 輪は大きさそのままで、寄せるだけ

### 何が起きていたか

`52` で「端では輪を縮めてから、入らない分だけ寄せる」にした。下限 0.62 倍なので
ツール列では**外径 176 → 109**。画面には収まったが、**文字が小さくて読めない**。

縮めた理由は「寄せを小さくしたいから」だった。だが `52` では**向きを輪の中心から
読む 1 本立て**にもしている。中心から読むなら、寄せがいくら大きくても
**見えている通りに選べる**。つまり縮める理由はもう無い。

### 決め

- **縮めない**。`RING_OUTER` は 176 のまま
- 画面に入る所まで**寄せるだけ**（左のツール列なら右へ 80px ほど。右の引き出しなら左へ）
- 縮めるのは**画面そのものが輪より狭いとき**だけ（`innerWidth - 12 < 352` の細い端末）

### 引き換え — 見ないで振り抜く使い方

押した点から**まっすぐ上**へ振り抜く読み方（`41` の T3）は、寄せた輪では成り立たない。
80px 右に寄った輪の中心から見ると、まっすぐ上は**北西**に見えるからだ。
`52` で読み方を 1 本にした時点でこうなっており、今回はその寄せが大きくなった。

- **ビューポートの指のジェスチャ**（2 本指・3 本指）は画面の真ん中で開くので寄せは 0。
  ここでは押した点 = 輪の中心で、**見ないで振り抜く使い方はそのまま効く**
- 寄せが出るのは**端のボタン**だけで、そこは元々**見てから押す**場所

### 付け足し — 「置いたまま離す」の安全弁を緩める

`52` で入れた「開いた時に指が乗っていた区画は、そこから出るまで選ばない」は
そのまま残す。ただし寄せが大きくなると、**指の下の区画を選びたい**場面が増える
（左のツール列で押すと、指は西の区画の上に居る。西 = スケール）。

- **25px 動かせば解ける**ようにする。長押し中の指のぶれ（10px ほど）では解けず、
  狙って動かせば解ける

## 報告（実装のあと）

### T1. 編集の輪にもマージを入れた

編集の輪は 8 方位のうち 7 つが埋まった:

| 方位 | 中身 |
|---|---|
| N | マルチカット |
| E | ベベル |
| SE | **距離でマージ**（`Merge 0.050`） |
| S | ブリッジ |
| SW | **中心にマージ** |
| W | 押し出し |
| NW | 接続 |

変形の輪（NW = 距離でマージ、一覧に中心にマージ）はそのまま。
`doMergeByDistance()` は `52` のとおり、頂点モードでなければ自分で入る。

### T2. 輪の大きさを戻した

実測（1280×800、`dist`）:

| 押した所 | `52`（縮めた） | `53`（そのまま寄せる） |
|---|---|---|
| ツール列（変形） | 外径 **109**・寄せ 11px | 外径 **176**・寄せ 80px |
| 削除ボタン（左下） | 外径 176・寄せ 147px | 外径 176・寄せ 147px |

輪の左端はどちらも +6px 以上で、画面からは出ない。

安全弁の解除は **25px** にした。通し確認では 15px のぶれで離しても
オブジェクトが消えないこと、36px 先の西の区画は選べることを見ている。
