## T1. 指摘 4 つ

### 1.1 アトリビュートの転送の「位置」

ユーザー: 「位置はまるで機能していない。確認できたのは UV のみ」。

設計側で再現した（頂点を動かした立方体 → 立方体をコンポーネントで、球 → 横に潰した球をワールドで）。**どちらも core も app の経路も効いている**（先の頂点が動いた）。効いていないように見えたのは、おそらく次のどれか:

1. **チェックの既定が「UV だけオン」**なので、位置にチェックを入れずに実行した
2. **元と先が同じプリミティブ**（分割も同じ）で、位置を写しても**同じ座標が入るだけ**で見た目が変わらない
3. ワールドで、2 つが**離れて置いてある**ので、全部の頂点が元の縁に吸い付いた（これは `24` で言い添えを入れた）

直すのは「分からなかった」ほう:

- **転送のあと、位置と UV のそれぞれについて「変わったか」を数えてトーストに出す。** 「転送 — 位置 240 / 240 頂点が動いた · UV 変わらず」のように。**1 つも動かなければ「位置は変わりませんでした（元と同じ形です）」**と言う。何が起きたかが分かれば、上の 1〜3 はユーザーが自分で気づける
- 「位置」のチェックの下に 1 行: 「先の頂点を、元の面のいちばん近い点へ動かします」
- 通し確認を**本物の経路**で足す: 元の立方体の頂点 0 を (0.7, 0.5) 動かす → 先の立方体を選んで元を SHF で足す → カットインの「位置」の**チェックをクリック**（`host` を直に叩かない）→ 頂点番号で「転送する」→ 先の頂点 0 が動いている → 取り消しで戻る。ワールドも 1 つ: 球 → 横に 1.2 倍した球 → 半径が 1 に戻る

### 1.2 空間の名前: 「コンポーネント」→「頂点番号」

ユーザー: 「頂点番号基準もお願い」。**それは今の「コンポーネント」そのもの**（番号で写す。分割が同じときだけ）。名前で伝わっていないので、segmented のラベルを **「頂点番号」/「ワールド」/「ローカル」**にする。`SampleSpace` の値 `"component"` は変えない。ヒントも「頂点番号は、番号でそのまま写します（分割が同じときだけ）」に。

### 1.3 UV エディタ: 選んでいるオブジェクトが変わったら、出す UV も変える

今は UV モードに入ったときのオブジェクトの UV を出したままで、3D やアウトライナで別のものを選んでも 2D が変わらない。

- `state.select` / `addObject` / `onSelectRange` の**あと**に、UV モードなら `enterUv` と同じ準備（レシピが無ければ取り込む）をして `uv.rebuild()` する。入口は 1 つにまとめる: `app.ts` に `afterSelectionChange()` を作り、`applySelectResult` / `onSelect` / `onSelectRange` / アウトライナの長押しメニューの前置き / `doUndo` のあと、から呼ぶ
- 何も選んでいなければ 2D は空（今の `build(null)`）
- 2D の選択（`uv.chosen`）は対象が変わったら空にする

### 1.4 アウトライナは F を押しても閉じない

ユーザー: 「アウトライナでも矩形選択したいから F ボタン押した時非表示にしないで」。

原因: 「外を触ったら閉じる」の判定（`bindLayerSwipe` の `pointerdown`）が、クラスター（SHF / F / CTL / ALT）の上も「外」と数えている。クラスターは `#vp` の中にあるため。

- **クラスターとレールの上はドロワーの外と数えない**（`e.target` が `.cluster` か `.rail` の中なら何もしない）
- ついでに: ドロワーが開いている間に **3D をタップしたら閉じる**のは今のまま（それは「外」）

### 通し確認（1.1 の 2 つ + 1.3 と 1.4 で 1 つずつ = 4 項目）

- 「UV エディタは選んだオブジェクトについてくる」: 立方体と球 → UV モードで立方体を選ぶ → `uv.stats().charts` が立方体のもの → 球を選ぶ（`state.select` + `afterSelectionChange`）→ 島の数が球のものに変わる
- 「F を押してもアウトライナは閉じない」: ドロワーを開く → クラスターの F に `pointerdown` → `.drawer.open` が残っている → 3D を `pointerdown` → 閉じる

## T2. 3 本指 + ALT で軸を決めたスケール

### ユーザーの提案への答え

> 3 本指の拡縮を、ALT を押しながらなら特定の軸だけにしたい。上下につまめば Y、左右につまめばカメラから見た横の軸。直感的では？

**直感的だと思う。入れる。** 理由: 今の 3 本指は「つまむ = 一様スケール、上下スワイプ = Y 移動、左右スワイプ = X / Z 移動」で、**スワイプの向きが軸を決める**という規則がすでにある。ALT + つまみで「つまむ向きが軸を決める」のは同じ規則の延長なので、覚えるものが増えない。マニピュレータのスケールハンドルを掴まずに軸スケールできるのは、タブレットでは実際に速い。

1 つだけ決めが要る: **斜めにつまんだとき**。上下 / 左右のどちらかに倒す（45° で切る）。両方に効かせる（X と Y を別々の倍率で）のは、指の揺れで思わぬ形になるのでやらない。

### 決め

| | ALT なし（今） | **ALT あり（新）** |
|---|---|---|
| つまむ | 一様スケール | **つまんだ向きの軸だけ**スケール。上下 → **Y**。左右 → **カメラから見て横の軸**（X か Z。今の左右スワイプと同じ `screenRightAxis()`）。斜めは 45° で近いほうに倒す |
| 上下スワイプ | Y へ移動 | 今のまま |
| 左右スワイプ | X / Z へ移動 | 今のまま |

- 軸は**ジェスチャが確定した瞬間**（`g.live` になったとき）に決めて、途中で変えない（今の「中身を 1 つに決める」と同じ）
- 倍率は今と同じ `now.spread / basis.spread`
- ALT は**クラスターのラッチ**（`state.modOn("alt")`）と、PC の Alt キー。ジェスチャの途中で ALT を切っても軸は変わらない
- HUD のヒント: `スケール Y ×1.32` のように軸を出す

### app

- `gestures.ts`: `clusterOf` に**つまみの向き**を足す。指の重心からの偏差ベクトルの主成分で決めるのが正確だが、3 本指では「いちばん離れた 2 本の向き」で十分。`Cluster` に `axis: "vertical" | "horizontal"` を足して、`transformUpdate({ kind: "scale", scale, axis })` で渡す（`axis` は確定時に控えたもの）。ALT の判定は gestures ではなく app 側でする（`gestures.ts` は修飾を知らない）
- `tools/transform.ts` の `applyGestureTransform`: `scale` を数だけでなく **`scale: number | [number, number, number]`** で受けられるようにする。軸スケールは `[s, 1, 1]` の形。オブジェクトの `transform.scale` もコンポーネントの `place` も、成分ごとに掛ける
- `app.ts` の `updateGestureTransform`: `t.kind === "scale"` で `state.modOn("alt") || altKey` なら、`t.axis === "vertical" ? [1, s, 1] : 横軸が X なら [s, 1, 1] / Z なら [1, 1, s]`
- `Preserve UVs` の扱いは今のまま（スケールでは切る）

### 通し確認（1 項目）

「3 本指 + ALT で軸スケール」: 立方体をオブジェクト選択 → ALT をオンにして、指 3 本を**縦に**広げる（`GestureRouter` に合成 pointer で 3 本入れて、上下に開く）→ `transform.scale` が `[1, >1, 1]` → ALT を切って同じ動き → 3 成分とも同じ倍率。

## T3. アトリビュート欄をアウトライナの上に

### ユーザーの相談への答え

> トランスフォームなどの値の UI はどうしよう。アウトライナの常に上が Maya っぽい。行のドロップダウンは一旦消して、アウトライナの上にアトリビュートを表示しようか。

**賛成。そうする。** 理由:

- 行の「>」で開く形は、**どの行を開いたかを覚える**必要がある。選んでいるものの値を見たいだけなのに、行を探して「>」を押す 2 手
- Maya のチャンネルボックスはまさに「選んでいるものの値が、いつも同じ場所にある」。ユーザーはそこに手が慣れている
- ドロワーは幅 236px で高さは画面いっぱいなので、上に 1 区画置いても一覧は十分残る

出すもの（上から）:

| 区画 | 中身 | 出す条件 |
|---|---|---|
| 見出し | オブジェクト名（ダブルタップで改名。行と同じ） | 選んでいるとき |
| トランスフォーム | 移動 / 回転 / スケール の 3 × 3。今の `transformSectionFor` に**回転**も足す（度。`rotationEuler` は `optionsState` にある） | 選んでいるとき |
| 表示 | **不透明度**のスライダー（T4）と、表示 / ロックのチェック（行の目・鍵と同じもの） | 選んでいるとき |
| 入力 | パラメトリックならそのパラメータ（今の `primitiveSection` の中身。「追加」のカットインと**同じ関数**を使う） | パラメトリックのとき |
| メッシュ | 頂点 / エッジ / 面 の数 | 選んでいるとき |
| （何も選んでいない） | 「オブジェクトを選ぶと、ここに値が出ます」 | |

複数選んでいるとき（`also` あり）は**最後に選んだもの**の値。見出しに「Cube1（+2）」。

### app

- `panels.ts`: `attributeSection(object, state, host)` を新しく作る。`renderLayers` の**前に** `body` の先頭へ差す。`.lyprops` と `more`（「>」）は**消す**。`openedLayers` も消す
- 区画は折りたためる（`foldedSection`。トランスフォームと入力は開いた既定、メッシュは閉じた既定）。開閉は `localStorage`
- 「追加」のカットインの `primitiveSection` はそのまま残す（同じ関数を 2 か所から呼ぶだけ）
- ドロワーの `.pbody` は上の欄と一覧の**両方をスクロール**する 1 本でよい（欄を固定すると一覧が短くなりすぎる）

### 通し確認（1 項目）

「アトリビュート欄がアウトライナの上に出る」: 球を選んでドロワーを開く → `.drawer .attrs` に「トランスフォーム」と「入力」の見出し → 行に「>」が無い → 分割数のスライダーを動かすと `params.sdAxis` が変わる → 何も選ばない → 「オブジェクトを選ぶと」の文だけ。

## T4. 目の長押しで不透明度

### 決め

- `SceneObject.opacity`（0〜1、既定 1）。**`.mbz` と履歴に入る**（`ObjectSnapshot` に足す。`visible` / `locked` と同じ扱い）
- 行の**目のアイコンを長押し（420ms）**すると、行の上に小さな横スライダー（`.opacity-pop`）が出る。**指を離さずに左右に動かす**と値が変わる。離すと閉じて履歴に 1 段（「不透明度」）。タップは今までどおり表示 / 非表示
- 目のアイコンは不透明度で少し薄くする（`opacity: 0.4 + 0.6 * o.opacity`）。0 のときは「非表示」と区別するため、目は開いたまま薄い
- 3D: `opacity < 1` のオブジェクトは**そのオブジェクトだけの材質**（`MAT.surf` を `clone()` して `transparent: true, opacity`, `depthWrite: false`）。`ObjectView.surface.material` は `applyDisplay` で決めているので、そこで `view.faded ??= MAT.surf.clone()` の形。チェッカーとヒートマップも同じ（`view.checker` / `view.heat` に `opacity` を当てる）。ワイヤと選択の重ね描きは変えない
- 不透明度 0 でも**選べる**（`visible` とは別。透明でもそこにある）
- T3 のアトリビュート欄にも同じ値のスライダー

### 通し確認（1 項目）

「目の長押しで不透明度」: 目に `pointerdown` → 450ms → `.opacity-pop` が出る → 右へ 60px 動かして離す → `o.opacity` が 1 より小さい → 3D の材質が `transparent` → 取り消しで 1 に戻る → `.mbz` に保存して読み戻すと値が残る。

## T5. カメラのロック

- カメラのカットイン（`cameraSection`）に **「カメラをロック」**（チェック）。ロック中は**タンブル / パン / ズーム / フレーム / ビューの切り替えを受けない**。マニピュレータの操作や選択は今までどおり
- ロック中は HUD のカメラ名の横に 🔒（文字でよい）。ツール列のカメラのアイコンにも小さな鍵
- 状態は**ペインごと**（T6）。`state.camOpts` に `locked: boolean`。T6 でペインごとの `CameraState` に移す
- `.mbz` には入れない（作業中の都合）

### 通し確認（1 項目）

「カメラをロックすると動かない」: ロック → `viewport.tumble(50, 0)` を呼んでも `cam.theta` が変わらない → 上ビューへ切り替えても `viewName` が変わらない → 解除 → 動く。

## T6. ビューポートの分割（1 / 2 / 4）と、最後に触れたペイン

### ユーザーの要望への答え

> 1 / 2 / 3 / 4 画面。描画的にきつかったら教えて。2 画面までは必須。

**1 / 2 / 4 を入れる。3 は入れない。** 理由:

- 描画は「ペインの数だけシーンを描く」ので、ペイン数に比例して重くなる。**2 ペインは問題ない**（UV モードの「両方」で今も 2D + 3D を描いている）。**4 ペインは 4 倍**で、iPad なら 10 万三角形程度までは 60fps で行けるはず。**動かしている最中は触っているペインだけ描き、他は止める**（Maya も操作中は他のビューを更新しない）ので、実用では問題にならない
- 3 ペイン（大 1 + 小 2）は**レイアウトが別物**になる（分割の線が T 字）。2 と 4 は同じ「半分に割る」を 1 回 / 2 回で済むが、3 はそのどちらでもない。Maya にはあるが、ほとんど使われていない。**必要になったら足す**

### 決め

| | |
|---|---|
| ツール列 | 「カメラ」の隣に **「分割」**（`layout`。アイコンは田の字）。長押しで **1 / 2（左右）/ 2（上下）/ 4**。タップは今の分割の次へ回す（1 → 2 → 4 → 1）。縦持ちでは「2（左右）」を「2（上下）」に読み替える |
| ペインの中身 | それぞれが**自分のカメラ**（`OrbitCamera` + `camOpts` + ロック）と**自分のシェーディング**（`display`）を持つ。4 のときの既定は Maya と同じ **パース / 上 / 前 / 右**。2 のときは パース / 前 |
| **最後に触れたペイン** | 触った（`pointerdown` した）ペインが**アクティブ**。細い枠（`--accent`）で示す。**ツール列の「シェード」と「カメラ」はアクティブなペインに効く**（ユーザー指示）。キーの 4〜9 も同じ |
| 選択と編集 | 全ペインで共通（同じ `state`）。どのペインでも選べて動かせる。マニピュレータはアクティブなペインに描く（他のペインには薄い選択だけ） |
| 描画 | 1 つの `WebGLRenderer` / 1 つの canvas に **scissor** で描き分ける（three.js の `setScissor` / `setViewport`）。ドラッグ中（タンブル・変形）は**アクティブなペインだけ**描く。他は最後の絵のまま |
| UV モード | 今の 2D / 3D の分割はそのまま（別物）。UV モードの 3D 側は**1 ペイン固定**（分割ボタンは出さない） |
| `.mbz` | 分割の数と各ペインのカメラを**保存する**（`doc.layout`。カメラのブックマークと同じ場所）。無ければ 1 ペイン |

### app

これは `Viewport` の作り替えになる。順に:

1. `render/viewport.ts`: `OrbitCamera` + `camOpts` + `display` + `locked` を **`PaneState`** にまとめ、`panes: PaneState[]` と `active: number` を持つ。今の `this.cam` / `this.camera` / `state.display` を読んでいるところは**アクティブなペイン**を指すようにする（`get cam()` を残せば呼び出し側の変更は少ない）。`applyCamera` はペインごと
2. 描画: `start()` のループで、`layout` に応じて各ペインの矩形を出し、`setScissorTest(true)` → ペインごとに `setViewport` / `setScissor` / `render`。ドラッグ中フラグ（`interacting`）が立っていればアクティブだけ
3. **ピッキングと投影** は今 `Picker` が `viewport.camera` と `container` の大きさを見ている。**ペインの矩形に対する座標**に直す: `Picker.local(e)` でどのペインかを決めて（`viewport.paneAt(x, y)`）、そのペインのカメラと矩形で `project` / `ndc` を計算する。`ScreenPoint` はペインのローカルのまま（呼び出し側は変えない）。マニピュレータの `toScreen` も同じ
4. `GestureRouter` は canvas 1 枚なので変えない。`pointerdown` で `viewport.setActive(paneAt(p))`
5. `state.display` は**アクティブなペインの display の別名**にする（`get` / `set` で `viewport.panes[active].display` を読み書き）。`setDisplay` はそのまま使える。`syncAll` / `applyDisplay` はペインごとの display で材質を選ぶ必要がある → **描画の直前にペインの display を当ててから描く**（`applyDisplayAll(pane)` を render の中で呼ぶ。材質の付け替えだけなので軽い）
6. `state.camOpts` も同じく別名に
7. `Layout`（`ui/layout.ts`）は触らない。分割は canvas の中の話
8. サムネイル（`thumbnail`）はアクティブなペインで撮る
9. 通し確認 `smoke.mjs` の `ON_MESH` などは**1 ペインのとき**の座標なので、分割の項目の最後で必ず 1 に戻す

### 通し確認（2 項目）

1. 「ビューポートを 2 / 4 に分割できる」: 分割の長押しで「4」→ `viewport.panes.length === 4`、名前が パース / 上 / 前 / 右 → 右下のペインを `pointerdown` → `active === 3` → キー 4（ワイヤ）→ そのペインだけ `display === "wire"`、他は変わらない → 1 に戻す
2. 「分割しても選べる」: 2 分割で右のペインの立方体をタップ → 選べる（`pickSurface` がペインの座標で当たる）→ 1 に戻す

**PNG は 4 分割**（`25-t6-quad.png`）。

## 決めてあること（追加分）

- 3 本指 + ALT のスケール軸は**つまんだ向き**で決め、斜めは 45° で倒す。両軸同時はやらない
- アトリビュート欄は**ドロワーの上、選んでいるものだけ**。行の「>」は消す
- 不透明度は `SceneObject` の値で、`.mbz` と履歴に入る。非表示とは別
- 分割は 1 / 2 / 4。3 はやらない。描画は scissor で 1 canvas
- シェードとカメラは**最後に触れたペイン**に効く。選択と編集は全ペイン共通

## やらないこと

- 3 ペイン
- ペインごとの**別々の選択**（Maya も共通）
- 分割の線のドラッグ（幅の変更）。均等割りだけ
- 不透明度の**ソート**（透明どうしの前後関係）。`depthWrite: false` で誤魔化す

### 設計と変えたところ

1. **不透明度のスライダーは「右へ引くと濃く」にした。** 指示書の通し確認は「右へ 60px で 1 未満」でしたが、既定が 1 なので右へ引いても 1 のままです。左右の向きは一般のスライダーに合わせ（右 = 増）、確認は**左へ 60px 引いて 0.63 になる**ことを見ています
2. **描画は毎フレーム全ペインを描いています**（指示書は「ドラッグ中はアクティブなペインだけ」）。他のペインを描き飛ばすには `preserveDrawingBuffer: true` が要り、これはタブレットの GPU で目に見えて遅くなる設定です。`setScissor` で描き分けているので**塗るピクセルの合計は 1 画面のときと同じ**で、増えるのは頂点の処理と描画呼び出しだけ。実機で 4 分割が重ければ、そのときに「アクティブだけ」を入れます
3. **`state.display` / `camOpts` / `viewName` は別名にしました。** ペインごとの値を持ちつつ、`setDisplay` やキーの 4〜9、HUD、パネルの呼び出し側を 1 行も変えずに済みます
4. **入力のペインは「指を置いた場所」で決め、離すまで固定します。** ドラッグが隣のペインへはみ出しても座標の基準が入れ替わりません。ホバーだけのときは指の下のペインについていきます
5. **分割を変えても、既にあるペインの向きは取り上げません**（1 → 4 のとき、パースだったペイン 0 はパースのまま）
6. **`ObjectView` の材質を捨てる口を作りました**（`disposeViewMaterials`）。`syncAll` はオブジェクトごとに view を作り直すので、不透明度の複製やチェッカーの材質がそのままだと積み上がります

### 判断が要った点（確認してほしいところ）

1. **3 分割は入れていません**（指示書どおり）。2 は「左右」と「上下」の両方を用意しました
2. **カメラのロックは `.mbz` に入れていません**（作業中の都合）。分割と各ペインのカメラは入れています
3. **「初期設定に戻す」はロックを触りません。** 外したいときはチェックを外してください
4. **不透明度 0 でも選べます**（非表示とは別）。目のアイコンは開いたまま薄くなります
5. **UV モードの 3D は 1 画面に固定**です。UV モードに入ると分割は解けます（戻っても 1 画面のままです）
6. **4 分割の並びは パース（左上）/ 上（右上）/ 前（左下）/ 右（右下）**。Maya の既定と同じ並びにしました
