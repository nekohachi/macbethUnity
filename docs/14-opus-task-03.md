## 1. タスク 8: 3 本指で選択を直接変形する（ユーザー要望。最優先）

### 要望

> 三本指での拡大・縮小の動作は、選択している面・線・オブジェクト・点をマニピュレータを操作しなくても拡大縮小できるようにして

### 設計

3 本指は今「何もしない（idle）」で、3 本指ダブルタップだけが「やり直す」に使われている。ここに **3 本指の変形ジェスチャ**を入れる。1 本の指はツール、2 本はカメラ、3 本は選択の変形、という割り当てになる。

| 3 本指の動き | 効果 | 中心 |
|---|---|---|
| **ピンチ（指の間隔）** | **選択の均等スケール（必須）** | 選択のピボット |
| ねじり（指の角度） | 選択をビュー軸まわりに回転 | 選択のピボット |
| 平行移動（重心） | 選択をビュー平面で移動 | — |

3 つとも同じ計算で出るので、同じ処理に入れる。**受け入れ条件はピンチ**。ねじりと平行移動は同じハンドラで一緒に効くようにするが、しきい値の調整はピンチを優先する。

**決めておくこと:**

- 対象は「今選ばれているもの」。オブジェクトモードならオブジェクト、コンポーネントモードなら選択中のコンポーネント。**何も選んでいなければ 3 本指は何もしない**（カメラに化けさせない。2 本指と役割を混ぜない）
- ピボットは `pivotWorld()`（Maya と同じ: オブジェクト = 原点、コンポーネント = 境界箱中心）。マニピュレータを表示していなくても同じ
- **ソフト選択と対称編集が効く**。`captureTarget()` を通すので、重みと鏡映ペアはそのまま乗る
- ツールが「選択・変形」のときだけ。マルチカット / ベベル中は無視
- 履歴は 1 ジェスチャで 1 件。動かなかったら積まない（ドラッグと同じ規則）
- **3 本指ダブルタップ（やり直す）と排他**にする。2 本指と同じデッドゾーン方式: 「重心の移動 + 間隔の変化 + 角度の変化（px 換算）」の合計が **10px** を越えた時点で変形として確定し、`tap.moved = true` にしてタップ判定を落とす。越えないうちに全部離れたらタップ側に任せる
- 確定した時点の重心・間隔・角度を基準にし直す（2 本指と同じ。飛びを防ぐ）
- 指が 4 本以上になったら何もしない。3 本から 2 本に減ったら idle のまま（離す途中の誤動作防止。今の規則と同じ）
- HUD に `スケール ×1.25` のように出す

### 実装の指示

`input/gestures.ts`:

- `down()` で `pointers.size === 3` のとき `mode: "threefinger"`。重心 (cx, cy)、重心からの平均距離 d、各指の重心まわりの平均角度 a を控える。`live: false, acc: 0`
- `move()` で live でなければ `acc += |Δ重心| + |Δd| + |Δa| × d`（角度は弧長に換算して px にする）。10 を越えたら live にして基準を取り直し、`this.h.transformBegin()` を呼ぶ。**false が返ったら（選択が無い）idle に落とす**
- live 中は毎回 `this.h.transformUpdate({ scale: d / d0, angle: a − a0, dx: cx − cx0, dy: cy − cy0 })`。値は**開始基準からの累積**で渡す（差分の積み上げではない。ドラッグと同じ考え方）
- `up()` で 3 本のうちどれかが離れたら `this.h.transformEnd()`。以後は idle

`GestureHandlers` に足すもの:

```ts
transformBegin(): boolean;
transformUpdate(t: { scale: number; angle: number; dx: number; dy: number }): void;
transformEnd(): void;
```

`tools/transform.ts` に足すもの:

```ts
/** 3 本指の変形。均等スケール → ビュー軸回転 → ビュー平面移動の順に、ピボットまわりで合成する。 */
export function applyGestureTransform(
  drag: DragState,
  object: SceneObject,
  t: { scale: number; angle: number; dx: number; dy: number },
  camera: { position: Vector3; right: Vector3; up: Vector3 },
  pixelToWorld: number,   // 画面 1px がピボット位置で何ワールド単位か
): void
```

- 内部は既存の `apply()` を使う。オブジェクトなら transform を、コンポーネントなら控えたワールド座標に重み付きで当てる
- スケールは `max(0.02, scale)` で裏返り防止。回転はビュー軸（カメラ位置 − ピボット）まわり。移動は `right × dx + up × (−dy)` を `pixelToWorld` 倍
- `app.ts` では `transformBegin` で `history.snapshot()` と `captureTarget()`、`beginDrag` 相当の `DragState` を作る（handle は新しく `HANDLE_GESTURE = 40` を定義）。`transformUpdate` で `applyGestureTransform` → `refreshPositions` / `applyTransform` → オーバーレイと HUD。`transformEnd` で変わっていれば `commit("変形")`

### 通し確認に足す

- オブジェクトを選び、合成した 3 本の touch ポインタで間隔を 1.5 倍に広げる → `transform.scale` が 1 より大きくなる。取り消しで戻る
- 同じ 3 本を動かさずに 2 回タップする → やり直しが起きる（排他の確認）。既存の「やり直しで戻る」項目を 3 本指の合成イベントで置き換えてよい

### 注意

- 2 本指の判定コードをコピーして 3 本に広げるのではなく、**重心 / 間隔 / 角度の計算を関数に切って 2 本指と共有**する。同じ数字（10px）を 2 か所に書かない
- しきい値 10px は 2 本指で実機確認済みの値。3 本指でも同じ値から始め、**変える場合は変えずに報告**する（`13` の規則）

## 2. タスク 4: 入口の切り替え（承認）

`13` のタスク 4 をそのまま実行する。要点:

- `app.html` → `index.html` に改名し、Vite の入口にする。`vite.config.ts` の `input` と `server.open`、`scripts/publish.sh`、`scripts/smoke.mjs` の `ENTRY` 判定を合わせる
- **ルートの `index.html`（プロトタイプの単体ページ）は消える。** プロトタイプは `prototype/modeling-ui-prototype.html` に残し、`publish.sh` が `app/prototype/index.html` として同梱する
- `prototype/make-pages.sh` を消す
- **公開 URL は `/macbethUnity/app/` のまま**（`publish.sh` の出力先は `app/`）。ルート `/macbethUnity/` はブランチ配信なので、リポジトリ直下に `index.html` が無くなると 404 になる。そこで **リポジトリ直下の `index.html` は `app/` へ転送するだけの 1 行ページ**にする（`<meta http-equiv="refresh" content="0; url=./app/">`）。ユーザーが前に開いた URL も生きる
- README の「タブレットで開く」表を書き直す。「新しいシェル」という言い回しをやめて、これが本体だと分かる書き方にする
- 通し確認は `ENTRY` の自動判定でそのまま通るはず。`npm run smoke` と `node scripts/smoke.mjs app` の両方が緑であること

**実装時の報告（Opus）:** 「入口を `index.html` に改名」と「リポジトリ直下の `index.html` を転送ページにする」は、同じ 1 つのパスを取り合うので両立しません（Vite の入口がリポジトリ直下にあると、ブランチ配信のルートがその開発用 HTML を返してしまい、`/src/app/main.ts` を読もうとして壊れます）。転送ページの方をリポジトリ直下に残し、**入口は `web/index.html`（Vite の `root` を `web/`）** に置きました。`server.open` は `/`、ビルドの出力は `dist/index.html` なので `publish.sh` の改名も要らなくなっています。狙い（アプリが本体、公開 URL は `/macbethUnity/app/` のまま、ルートは転送）はそのままです。

## 3. タスク 9: マルチ解像度 V4〜V6

`08` の 4 章。`src/core/multires.ts` に足す。

| 項目 | 内容 | 合格 |
|---|---|---|
| V4 | 球（レベル 2 まで細分割した立方体でよい）をレベル 4 まで。局所的な突起をスカルプト。レベル 0 に戻って突起近傍の頂点をサイズの 30% 動かす。レベル 4 に戻る | 突起頂点の `delta` のノルムが編集前後で変わらない（1e-5）。突起の基部が `S(4)` からの距離を保っている |
| V5 | divide → スカルプト → レベル 0 → 最大レベル、を 10 回 | 頂点座標が初回と一致（1e-5）。累積誤差なし |
| V6 | レベル 0 の頂点を 1 つ動かしたときの**差分更新**が全体再計算と一致 | 1e-6 |

V6 は差分更新の実装が要る。方針:

- `Multires.setBase()` に「動いた頂点の集合」を渡せる口を足す（`setBase(mesh, movedVertices?)`）
- レベル L で影響を受ける頂点は、レベル L−1 の影響頂点の **2 リング**（Catmull-Clark の頂点点は 1 リング、エッジ点 / 面点は隣接面まで見るので合わせて 2 リング）。各レベルで影響集合を広げながら、その頂点だけ細分割の規則を当て直し、その頂点のフレームとデルタだけ再適用する
- 他の頂点は前回の結果をそのまま使う。**キャッシュは頂点単位で持つ**（今の `cache: Mesh[]` を、レベルごとの `positions` を差し替える形にする）
- 全体再計算との差が 1e-6 を越えたら、影響集合の広げ方が足りない。リングを増やす前に**どの頂点がずれたか**を出して原因を確かめること

## 4. Phase B の続き（順番どおり）

`12` の B3〜B7。各項目とも **core + テスト → 予測表示（要るなら）→ オプション → 通し確認 1 項目**。

| 順 | 機能 | 決め |
|---|---|---|
| B3 | ブリッジ | 2 つのエッジ列（同数）を面で繋ぐ。対応付けは最近傍 + 向き（列の始点と終点の距離の和が小さい方）。数が違えば null。エッジの編集メニュー東 |
| B4 | マージ（距離指定）、頂点の削除（周囲を 1 面に）、頂点の押し出し | 小粒。頂点の削除は `dissolveEdges` の頂点版（その頂点に集まるエッジを全部溶かす）。頂点の押し出しは Shift ドラッグの「未対応です」を実装に置き換える |
| B5 | 接続（Connect） | 同じ面に属する 2 頂点（またはエッジ中点）の間に辺を通す。3 つ以上なら順に。マルチカットと同じ予測表示 |
| B6 | スナップ | **CTL ラッチ = スナップ**。グリッド（1 / 0.5 / 0.25 の刻み、オプションで切替）→ 頂点 → エッジの順。Maya の X / V / C も割り当てる。スナップ先を光らせる（ターゲットウェルドの緑と同じ材質） |
| B7 | 面の複製 / 抽出、結合 / 分離、ミラー、数値入力 | 編集メニューの空き枠へ |
