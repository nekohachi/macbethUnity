## 0. 前提の訂正: ブラシに wasm は要らない（たぶん）

`30` と `32` で「**B2b が 160ms なのでブラシも wasm へ**」と書いた。**これは B2b の
読み違い。** 訂正する。

B2b が測っているのは `multi.setBase(base, moved)`、つまり**レベル 0 を動かして
上の段へ伝える**道。ブラシのストロークはこれを通らない。

| | 何が起きるか | 重さ |
|---|---|---|
| **いちばん上の段で塗る** | P(N) の頂点を動かし、触った頂点の `deltas[N-1]` を取り直す。S(N) は動かないので**基底も作り直さない** | **触った頂点の数だけ**。メッシュの大きさに依らない |
| 途中の段で塗る | 上の段の S が変わるので、そこから上へ伝える | 段の数 × 触った範囲 |
| レベル 0 を編集（モデリング） | 全段へ伝える（= B2b） | **160ms** |

**ふだんのスカルプトは 1 行目。** だから S2-2 は **JS のまま作って、測ってから
決める**。wasm が要るのは 3 行目（`03` の売りである「ハイを見ながらローを直す」）で、
それは S2-2 の範囲外。**`28` の S2-2 から「デルタの取り直しを wasm」を外し、
`S2-5`（新設）へ送る**（下の 6 章）。

ただし今の `Multires.sculpt(level, edited)` は**メッシュ全体のデルタを取り直して
`stack = null`（全段組み直し）する**。1 コマごとに呼べる形ではない。ここは直す（T2）。

## T1. ブラシの状態を分ける、筆圧を通す

### 見つかっているバグ

`src/app/state.ts` の `GAUGES.sculpt` は `g1`/`g2` とも **`s.soft[key]` を読み書き
している**（`gauge()` の `get`/`set`）。`soft` はモデリングの**ソフト選択**の
強度と範囲。つまり今は、

- スカルプトでブラシサイズを変えると、モデリングのソフト選択の範囲まで変わる
- その逆も起きる

**別々に持つ。** 通し確認で「片方を変えてももう片方が動かない」を見る。

### 決め

- `AppState` に **`brush`** を足す:

| 名前 | 既定 | 意味 |
|---|---|---|
| `kind` | `"standard"` | `"standard"` / `"move"` / `"smooth"` |
| `strength` | 0.5 | 0〜1 |
| `radius` | 0.4 | ワールド単位。**オブジェクトの大きさで初期値を決める**（対角の 8%）。0.01〜10 |
| `invert` | false | ALT を押している間だけ反転（`Standard` は凹み、`Move` は逆向き、`Smooth` は効果なし） |
| `pressureSize` | true | 筆圧を半径に効かせる |
| `pressureStrength` | true | 筆圧を強度に効かせる |
| `symmetryX` | true | T4 |

- `gauge()` に**どこへ書くかを渡せるようにする**。`soft` 用と `brush` 用の 2 つ。
  `GAUGES.sculpt` は `brush` を、`model` / `uv` は今までどおり `soft` を書く
- **半径はワールド単位**。画面の px ではない（カメラを寄せてもブラシの効き方が
  変わらないほうが彫りやすい）。画面にはカーソルの円を出す（T3）

### 筆圧

- `src/app/input/gestures.ts` の `pointers.set(...)` に **`pressure`** を足す
  （`e.pressure`。マウスと、筆圧を返さないペンは押している間 0.5 になるので、
  **0 のときは 0.5 として扱う**）。`move` でも更新する
- ハンドラ（`GestureHandlers`）の 1 本指ドラッグに `pressure` を渡す
- **傾き（`tiltX` / `tiltY`）は今は取らない。** `05` のアルファ回転で要るが、
  アルファ自体が S2-4 なので、そのとき一緒に
- カーブは**まだ付けない**（`05` は「それぞれ独立したカーブで調整可能に」だが、
  調整 UI は S2-4）。いまは:
  - 半径 = `radius × (0.35 + 0.65 × p)`
  - 強度 = `strength × p²`（弱い筆圧で効きすぎないように 2 乗）
  - `pressureSize` / `pressureStrength` が false ならその項を 1 にする

### 通し確認（1 項目）

「ブラシの強度とソフト選択の強度は別物」: スカルプトで強度を 0.9 にする →
モデリングへ戻ってソフト選択の強度が変わっていない → 逆も同じ。

## T2. core にストローク（`src/core/sculpt.ts`、新規）

### 決め: 差分スカルプト（`src/core/multires.ts` に足す）

今の `sculpt(level, edited)` は残す（全体を入れ替える道。`.mbz` 読み込みなどで使う）。
**新しく `sculptAt(level, verts)` を足す:**

- レベル L の**表示メッシュ P(L) がすでに書き換わっている**前提で、`verts` の
  デルタだけを取り直す。式は `captureDeltas` と同じ（`delta = Tᵀ (P − S)`）を
  **1 頂点ずつ**適用したもの。**同じ式を 2 か所に書かない**（`captureDeltas` から
  1 頂点版を切り出して両方が呼ぶ）
- **`stack = null` にしない。** S(L) も基底も変わっていないので、控えはそのまま使える
- **L より上の段があれば、そこへ伝える**（`updateFrom` と同じ要領で、`verts` から
  上へ）。いちばん上の段なら何もしない
- `deltas[L-1]` が `null`（まだディテール無し）なら、その場で `Float32Array` を作る

### 決め: ブラシ 3 つ

入力はすべて「**動かす頂点とその重み**」に落とす。重みは

```
w = falloff(距離 / 半径) × 強度 × 筆圧
falloff(t) = t >= 1 ? 0 : (1 - t²)²      // 滑らかな釣鐘。端で 0、中心で 1
```

| ブラシ | 何をするか |
|---|---|
| **Standard** | 頂点を**その頂点の法線方向**へ `w × 半径 × 0.25` 動かす。`invert` で逆。法線は P(L) のもの（S(L) ではない。彫った上にさらに彫れるように） |
| **Move** | 指の動き（3D のずれ）をそのまま `w` 倍して足す。ずれは**カメラに平行な面**の上で取る（`26` の 3 本指と同じ考え方）。`invert` は無効 |
| **Smooth** | 頂点を**隣接頂点の平均**へ `w` で寄せる。`P += w × (平均 − P)`。**1 コマで 1 回だけ**（何度も掛けると縮む）。`invert` は無効 |

- **Standard の「盛りすぎ」対策はしない。** ZBrush の Clay 系は S2-4
- **半径の外は触らない。** 重み 0 の頂点をデルタに書くと、履歴の差分が無駄に太る

### 決め: 触る頂点の集め方

- `trianglesNear(bvh, point, radius)`（`29` の B-T5 で作った）で三角形を拾い、
  その頂点を集める。**BVH は表示メッシュ P(L) のもの**（`viewport.bvhOf`）
- 集めた頂点を `Set` ではなく **`Uint32Array` で返す**（履歴とレンダの部分更新に
  そのまま渡すため）

### API

```ts
export interface StrokeInput {
  /** 当たった点（オブジェクト空間）。 */
  point: [number, number, number];
  /** Move のときの移動量（オブジェクト空間）。他のブラシでは無視。 */
  move?: [number, number, number];
  radius: number;
  strength: number;
  invert: boolean;
  kind: "standard" | "move" | "smooth";
}

/** 触る頂点を集める。 */
export function strokeVerts(mesh: Mesh, bvh: Bvh, tri: Triangles, point, radius): Uint32Array;

/** mesh.positions を書き換える。戻り値は実際に動いた頂点。 */
export function applyStroke(mesh: Mesh, verts: Uint32Array, input: StrokeInput): Uint32Array;
```

`applyStroke` は `Mesh` を書き換えるだけ。マルチ解像度も履歴も知らない。

### テスト（`tests/sculpt.test.ts`、新規）

- **Standard**: 平面の真ん中を押すと、中心がいちばん動き、半径の外は 1 ミリも動かない。
  `invert` で符号が反転する
- **falloff**: 中心の重みが 1、端が 0、その間が単調に減る
- **Move**: 全部の頂点が同じ向きに動く。動く量は中心がいちばん大きい
- **Smooth**: ぎざぎざの平面に掛けると、頂点の**ばらつき（分散）が減る**。
  かつ**外周は動かない**（半径の外）
- **Smooth を 10 回掛けても平面が縮まない**（体積が飛ばない。1 コマ 1 回の確認）
- **`sculptAt` が `sculpt` と一致する**: 適当に何頂点か動かして、
  `sculptAt(L, verts)` の結果と、`sculpt(L, 全体)` の結果が**完全一致**
- **`sculptAt` は下の段を壊さない**: レベル 2 で塗ったあと、レベル 0 と 1 の
  頂点が 1 つも動いていない
- **段をまたいで効く**: レベル 1 で塗ると、レベル 2 の形も動く（上へ伝わっている）

## T3. つなぐ（入力・描画・履歴）

### 決め: 入力

- スカルプトモードで**ペン / 1 本指のドラッグ = ストローク**。指 2 本以上は
  今までどおりカメラ（Nomad 方式のまま。`04`）
- **押した瞬間**: レイを飛ばして当たり点を出す。当たらなければ何もしない
- **動いている間**: 1 コマにつき 1 回、`applyStroke` → `sculptAt` → 部分更新
  - **点と点の間を埋める**（速く動かすと飛び飛びになる）。前の点との距離が
    半径の 1/4 を超えたら、その間を 1/4 刻みで補間して複数回当てる
- **離したとき**: 履歴に積む。`refreshPositions` で法線を作り直す（`29` の B-T6 と同じ形）
- ALT を押している間は `invert`（修飾ボタンの `ALT` がそのまま使える。`29` の A-T1）

### 決め: 描画

- **カーソルの円**: 当たり点に、半径ぶんの円を面に沿って出す（`overlay` に
  `LineLoop` を 1 本）。触っていない間もホバーで出す。**これが無いとサイズが分からない**
- 1 コマの更新は **`refreshMoved(o, verts)`**（`29` の B-T6 で作ったもの）。
  法線は据え置き、離したときに直る
- BVH は `refitBvhPartial`（同じく B-T5）

### 決め: 履歴（**ここが肝**）

ストロークは**レベル 0 の座標を変えない**ので、今の `positions` 差分は使えない。
`full` で積むと 1 ストロークで数 MB。**`sculpt` の段を足す**（`29` の B-T4 の 3 種類に
4 つ目）:

```ts
{ kind: "sculpt"; label: string;
  diff: { ref: SceneObject; level: number; verts: Uint32Array;
          before: Float32Array; after: Float32Array }   // 3 × verts.length のデルタ
  sel: SelectionSnap }
```

- `beginSculpt(o, level, verts)` で `before` を控え、`commitPending` で `after` を読む。
  **既存の `beginPositions` と同じ骨格**にする
- 戻す / やり直すときは、デルタを書き戻して **`sculptAt` の逆**（`writeDetail` で
  その頂点だけ P を作り直す）→ `invalidateLevels()` はしない（段は生きたまま）
- **ストローク 1 本 = 履歴 1 段**。ドラッグ中は積まない
- **1 ストロークで触った頂点をためる**（コマごとの `verts` の和集合）。
  `before` は**ストロークの最初の値**

### 通し確認（2 項目）

1. 「ストロークで盛り上がり、取り消すと戻る」: 球をレベル 2 まで上げ、
   真ん中を 1 回塗る → 触った頂点が法線方向へ動く → **レベル 0 は動いていない** →
   取り消すと元に戻る → やり直すとまた盛り上がる
2. 「ストロークの履歴は差分」: 上の 1 ストロークの履歴の段が `sculpt` で、
   **10KB 未満**（`full` なら数 MB）

PNG: `33-t3-stroke.png`（球に何本か彫った絵。カーソルの円が見えること）。

## T4. X 対称

### 決め

- **`brush.symmetryX`（既定 オン）。** オブジェクト空間の X = 0 で鏡映
- やり方: ストロークの当たり点を X 反転した点でも `strokeVerts` + `applyStroke` を
  もう一度呼ぶ。**頂点の対応表は作らない**（トポロジが対称でなくても効く。
  `05` の「v1.5 でトポロジ対称」は後回しでよい）
  - Move のときは移動量の X も反転する
- 中心線（|x| < 半径の 1%）の頂点は**2 回動かさない**（両方の呼び出しで拾われるので、
  2 回目は重みを 0 にする。段差が出るのを防ぐ）
- ツール列の「ブラシ」グループの長押しに **対称 X の入り切り**を置く

### 通し確認（1 項目）

「対称オンで両側が同じだけ動く」: 球の X > 0 側を塗る → X < 0 側の対応する位置も
同じだけ動く（左右の高さの差が 1e-5 未満）→ 切ると片側だけ動く。

## 6. `28` の直し（この指示書で決めたこと）

- **S2-2 から「デルタの取り直しを wasm」を外す。** 0 章の理由
- **S2-5 を新設**（S2-4 のあと、S3 の前）: **「ハイを見ながらローを直す」**。
  中身は
  - `Multires.setBase` の差分更新を wasm へ（計画を wasm 側に常駐させる。
    `native/core.c` の場所取りを「呼び出しごとに戻す」から「計画ごとの区画」へ）
  - `FramePlan` の `number[][]` を CSR に（`32` の T5 で分かった、実データ 19MB に
    対してヒープ 165MB の主因。詰めれば段をもう 1 つ上げられる）
  - モデリングモードでハイを重ねて表示する
  - **これは `03` の売りそのもの**なので、S2 の締めに置く

## 決めてあること

- ブラシの半径は**ワールド単位**。画面 px ではない
- 筆圧のカーブの調整 UI は S2-4。いまは決め打ち
- ストローク 1 本 = 履歴 1 段。差分で持つ
- 対称は**空間の鏡映**。頂点の対応表は作らない
- `src/core/sculpt.ts` は `Mesh` を書き換えるだけ。マルチ解像度も履歴も知らない

## やらないこと

- 残りのブラシ（Clay / Pinch / Inflate / Flatten / Trim / Polish）は S2-4
- マスク、裏面マスク（S2-3）
- アルファ、ストロークタイプ、減衰カーブの編集（S2-4）
- スカルプトレイヤー（S2-4）
- 傾き（altitude / azimuth）の取り込み（アルファと一緒に S2-4）
- wasm（要ると分かってから。S2-5）

## 実装の報告（Opus、2026-09-09）

T1〜T5 すべて済み。branch `claude/tablet-3d-modeling-app-f6b1x5`。
**core 277 テスト、通し確認 120 項目。** `dist` と `app/` の両方で通る。

### 門の結果（B6。CI の swiftshader、6 万四角形のレベル 2）

| | ms | 目標 |
|---|---|---|
| ストロークの 1 コマ・いちばん上の段 | **6.5** | 16 ✓ |
| ストロークの 1 コマ・1 つ下の段（上へ伝える） | **8.3** | 16 ✓ |

**0 章の見立てどおりだった。** ブラシは `setBase` を通らないので、B2b の 160ms
とは関係がない。CI（実機よりずっと遅い）で両方 16ms に入っているので、
**S2-2 に wasm は要らない。** 実機で確かめてから S2-3（マスク）へ進める。

### 指示書から変えたところ

| | 指示書 | 実装 | なぜ |
|---|---|---|---|
| `applyStroke` の引数 | `(mesh, verts, input)` | `(mesh, footprint, tri, input)` | 法線と隣接を**当たった範囲の三角形から**作るので、頂点番号だけでは足りない。全体の隣接表を持たないための設計 |
| Standard の 1 回ぶん | 半径 × **0.25** | 半径 × **0.08** | 0.25 だと 1 なぞりで半径の 2 倍盛れて形が破綻した（下記） |

**強さの数字について。** ストロークは半径の 1/4 ごとに当てるので、1 回なぞる
だけで同じ頂点に 8 回ほど乗る。0.25 のままだと球が尖って裂けた。0.08 にすると
1 なぞりで半径の 3 割ほど（実測 0.096 / 半径 0.28）。**手触りの数字なので、
実機で触って決め直してほしい。**

### 途中で見つけて直したバグ 2 つ

1. **段を上げているとピッキングが壊れていた。** `picking.ts` が `o.mesh`
   （レベル 0）を読む一方、ビューと BVH は `shown()`（表示中の段）で作られて
   いた。レベル 2 の三角形索引でレベル 0 の座標配列を引くので、当たらないか
   まるで違う場所に当たる。`32` の T3 で表示を段対応にしたときからの取りこぼし。
   ストロークを書いて初めて踏んだ（**それまで誰も段を上げてピックしていなかった**）
2. **スカルプトで選択中のワイヤが出ていた。** 選んでいるものは常にワイヤを
   出す決まりだが、スカルプトでは必ず選択中なので、段を上げると 1.7 万本が
   乗って彫った面が見えなかった

### 実機で見てほしいこと

## ブラシの当て方を ZBrush に合わせた（2026-09-09。ユーザー指示）

ユーザーの報告: **筆圧は効いている。強さがちょうどよいかは分からない。**
ZBrush と同じにしてほしい。

### 「分からない」の正体

**当てる回数がペンの進んだ距離ではなく、イベントの回数で決まっていた。**

前は `steps = max(1, ceil(距離 / 刻み))`。つまりイベントが 1 回来るたびに
最低 1 回は当てていた。同じ線を引いても、

- ゆっくり動かす（イベントが多い）→ 濃くなる
- 速く動かす（イベントが少ない）→ 薄くなる

手の速さで結果が変わるので、**強さを決めようがない**。これが「ちょうどよいか
分からない」の原因。

### 直したこと（ZBrush の Stroke → Spacing と同じ）

| | 前 | 後 |
|---|---|---|
| 当てる間隔 | イベントごとに最低 1 回 | **半径の 1/4 進むごとに 1 回**（距離で決める） |
| 1 打ちの深さ | 半径 × 0.08 | 半径 × **0.0625**（`DAB_DEPTH`） |
| 既定の強さ | 0.5 | **0.25**（ZBrush の Z Intensity 25） |
| 既定の筆の太さ | 対角の 8% | **対角の 3%**（ZBrush の Draw Size に近い） |

ムーブだけは別扱い。積み上げではなく掴んで動かすものなので、指の動きを
そのまま渡す（距離で刻まない）。

強さ 1 で 1 なぞり ≒ 半径の半分（0.0625 × 8 打ち）。既定の 0.25 なら
半径の 1 割強で、**重ねて彫っていく**手触りになる。

通し確認に「同じ線なら、速く引いても遅く引いても同じだけ盛れる」を足した。
実測で **1.00 倍**（前は速さで何倍も変わっていた）。

### 速さへの効き

筆を細くしたぶん、1 コマで触る頂点が減った。CI（25 万四角形のレベル 2）:

| | 前 | 後 |
|---|---|---|
| B6a いちばん上の段 | 28.8ms（1.9 万頂点） | **11.2ms**（7 千頂点） |
| B6b 1 つ下の段 | 49.1ms | 31.3ms |

面積は半径の 2 乗で効くので、8% → 3% で 7 分の 1。

### 実機の数字（この直しの前。ユーザー提供）

| | iPad mini 6（25 万） | MovinkPad 14（100 万） |
|---|---|---|
| B6a ストローク 1 コマ・上の段 | 22ms | 104.5ms |
| B6b 1 つ下の段 | 28ms | 165.7ms |
| 触った頂点（上 / 下） | 19921 / 5041 | 79996 / 20078 |
| B4a 描画 1 フレーム | 10ms | 38.6ms |
| B2b デルタの取り直し | 54ms | 167.8ms |

**筆を細くしたので、実機でも 7 分の 1 前後になる見込み。** mini は 22 → 5ms 前後、
MovinkPad は 104 → 20ms 前後。**測り直してほしい。**

なお B6 は「その端末で扱える最大級のメッシュに、既定の筆で当てる」数字。
ふだん彫る大きさ（数万〜数十万四角形）ならもっと軽い。

## 既定の強さと太さを実機の値にした（2026-09-09。ユーザー指示）

ユーザーの報告: **さっきより良くなった。強度 0.67 とサイズ 0.23 くらいが
初期スフィアのサイズでちょうど良かった。**

### 入れた値

| | 前 | 後 |
|---|---|---|
| 既定の強さ | 0.25（ZBrush の Z Intensity 25） | **0.67** |
| 既定の筆の太さ | 対角の 3% | **対角の 6.6%** |

既定の球は境界が 2×2×2 で対角 3.4641。その 6.6% がちょうど 0.23 になる
（`fitBrushRadius`）。太さは**ワールド単位**なので、割合で持たないと
大きい像と小さい像で使い物にならない。

### 太さを戻したぶんの重さ

触る頂点は**半径の 2 乗**で増えるので、3% → 6.6% で 5 倍近くになる。
CI（25 万四角形のレベル 2、swiftshader）:

| | 3% のとき | 6.6% のとき |
|---|---|---|
| B6a いちばん上の段 | 11.2ms（7 千頂点） | 26.2ms（1.6 万頂点） |
| B6b 1 つ下の段 | 31.3ms | 45.2ms |

### 打つたびの往復をやめた（`stroke.ts` の `flush`）

半径の 1/4 ごとに打つので、1 イベントで 2〜3 打ち当たる。前はその**打つたびに**
デルタの取り直し（`sculptAt`）と頂点バッファの書き換え（`refreshMoved`）を
していた。同じ頂点を何度も往復するので、太い筆ほど無駄が大きい。

1 打ちの内訳を測った（CI、25 万四角形、半径 0.23、1.66 万頂点）:

| | ms |
|---|---|
| 範囲を拾って動かす（`strokeFootprint` + `applyStroke`） | 11.8 |
| デルタの取り直し（`sculptAt`） | 1.0 |
| 描画と BVH の書き換え（`refreshMoved`） | 8.9 |
| 合計 | 21.7 |

後ろの 2 つを**1 イベントに 1 回**へまとめた。3 打ちのイベントなら
65ms → 45ms（3 割減）。

引き換えに、同じイベントの中では BVH の箱が 1 打ちぶん古い。1 打ちで動く量は
半径の 1/16（`DAB_DEPTH`）なので葉の箱に対して十分小さく、拾い落としは出ない。

### 実機で測ってほしいこと

`?bench=1&size=25`（mini）/ `?bench=1&size=100`（MovinkPad）の **B6a**。
筆が 5 倍の面積になったので、前回（mini 22ms → 細くして未計測、
MovinkPad 104.5ms）から動く。

ただし B6 は「その端末で扱える最大級のメッシュに当てる」数字。
**信じるべきは、ふだん彫る大きさで指が引っかかるかどうか。**
