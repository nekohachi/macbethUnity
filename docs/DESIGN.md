# お絵描きアプリ 設計ドキュメント

iOS / Android 向けペイントアプリの全体設計。

- **書き味**: CLIP STUDIO PAINT / SAI 級のブラシフィール(低遅延・手ぶれ補正・筆圧表現)
- **画像加工**: Photoshop 的なフィルタ・色調補正・選択範囲・変形
- **UI**: Procreate 的なミニマルでジェスチャ中心の UI

---

## 1. 要件の整理と「書き味」の正体

「クリスタ/SAI のような書き味」は感覚的な言葉だが、技術的には次の要素に分解できる。設計はここから逆算する。

| 要素 | 技術要件 |
|---|---|
| 遅延の少なさ | ペン先→画面反映まで **20ms 以下**(理想は 1 フレーム)。GPU 直描画 + 入力予測が必須 |
| 線の滑らかさ | 入力点の補間(Catmull-Rom / ベジェ)、SAI 的な**手ぶれ補正(スタビライザー)** |
| 筆圧・傾き表現 | Apple Pencil(240Hz)/ S Pen 等の筆圧・傾き・方位を、サイズ・不透明度・にじみへマッピングする**筆圧カーブ** |
| 混色・にじみ | 単純なアルファ合成でなく、下地の色を拾う**ウェットミキシング**(水彩境界、絵の具の伸び) |
| アンチエイリアス | ブラシスタンプのシェーダで距離場ベースの綺麗なエッジを出す |

この要件群は「UI フレームワークで canvas に線を引く」レベルでは絶対に満たせない。**GPU 直叩きの独自描画エンジン**が中核になる。

## 2. 技術スタック選定

### 結論(推奨構成)

```
┌─────────────────────────────────────────────┐
│  UI 層(プラットフォームごとに薄く)           │
│   iOS: SwiftUI + UIKit / Android: Compose    │
│   ※ 1コードベースにしたければ Flutter でも可  │
├─────────────────────────────────────────────┤
│  ブリッジ層(FFI / Swift-C++ interop / JNI)   │
├─────────────────────────────────────────────┤
│  コアエンジン(C++ または Rust、共有コード)    │
│   ・ブラシエンジン ・レイヤー合成             │
│   ・タイルキャンバス ・フィルタ ・Undo/Redo   │
│   ・ファイルI/O(独自形式 + PSD)              │
├─────────────────────────────────────────────┤
│  GPU 抽象化層                                 │
│   iOS: Metal / Android: Vulkan(旧機種GLES3)  │
│   ※ wgpu(Rust) や Dawn を使えば抽象化を省ける │
└─────────────────────────────────────────────┘
```

- **コアエンジンを C++/Rust で共有**し、UI だけ各 OS ネイティブで書くのが、CSP・Procreate・Infinite Painter などプロ級アプリの実績ある構成。
- Rust を選ぶなら **wgpu** で Metal/Vulkan の差を吸収でき、将来の Web 版(WebGPU)にも道が開ける。C++ なら Metal/Vulkan を個別実装するか Dawn/MoltenVK を使う。

### 選択肢の比較

| 構成 | 書き味の上限 | 開発コスト | 備考 |
|---|---|---|---|
| **C++/Rust コア + ネイティブ UI(推奨)** | ◎ | 高 | プロ級アプリの定番。UI は2重実装だが薄い |
| Flutter UI + C++/Rust コア(FFI) | ○〜◎ | 中 | UI が1コードベース。キャンバスは Texture 連携(iOS では Metal テクスチャ共有)で低遅延を維持できる |
| Unity | ○ | 中 | RenderTexture + コンピュートシェーダで描画自体は可能。ただし①プロアプリらしい UI 構築が苦手 ②Apple Pencil の予測入力等のペン API へ素のアクセスがなくネイティブプラグインが必要 ③アプリサイズ・起動時間・ランタイム料金の懸念。**ゲーム開発経験チームのプロトタイプ用途なら現実的** |
| React Native / Flutter 単体(エンジンなし) | ✕ | 低 | 遅延・混色・大キャンバスが要件に届かない |

> リポジトリ名が macbethUnity なので Unity を想定している可能性があるが、長期的にストアで戦うなら「共有コア + ネイティブ UI」を推奨。Unity で始める場合も、描画ロジックをシェーダ+C# の独立モジュールに閉じ込めておけば後で移植できる。

## 3. コアエンジン設計

### 3.1 キャンバス:タイルベース管理

キャンバス全体を 1 枚のテクスチャで持つと 4K×4K RGBA16F で 128MB/レイヤーになり破綻する。

- キャンバスを **256×256 のタイル**に分割し、レイヤーごとにスパースなタイルマップで保持
- 触られていないタイルはメモリ確保しない。メモリ逼迫時は LRU でディスクへ退避(ページング)
- 色は **16bit float(linear)** で保持し、合成を線形空間で行う(8bit sRGB 合成は暗部の混色が濁り、書き味を損なう)

### 3.2 ブラシエンジン(書き味の心臓部)

パイプライン:

```
入力イベント(座標, 筆圧, 傾き, タイムスタンプ)
  → ① 入力補間: イベント列をスプライン(Catmull-Rom)化
  → ② スタビライザー: 移動平均 / ばね追従(SAI 方式)。強度 0〜100 をユーザー設定
  → ③ 予測: OS の予測入力(iOS predictedTouches / Android MotionEvent 予測)で
        先端を仮描画し、確定入力で置換(遅延体感を削る)
  → ④ スタンプ生成: スプライン上に spacing 間隔でブラシチップを配置
        筆圧カーブ → サイズ/不透明度/流量へマッピング
  → ⑤ GPU 描画: チップをインスタンシングで「ストロークバッファ」に描画
  → ⑥ 合成: ストロークバッファをレイヤーに flow/opacity ルールで合成
```

重要な設計判断:

- **ストロークバッファ方式**: ストローク中は専用の一時バッファに描き、ペンを離した時点でレイヤーへ焼き込む。これで「1ストローク内で不透明度が重なりすぎない」SAI 的な挙動と、ストローク単位 Undo が自然に実現できる。
- **ウェットミキシング**: 「にじみ・混色」ブラシは、チップ描画時に下地の色をサンプリングしてブラシ内の保持色と混合する(Procreate の「にじみ」、クリスタの「色混ぜ」)。コンピュートシェーダで実装。
- **ブラシ定義はデータ駆動**: チップ形状(テクスチャ or 距離場)、散布、テクスチャ、筆圧カーブ、混色率などを JSON 等のパラメータで記述し、エンジン本体を変えずにブラシを量産できるようにする。

### 3.3 レイヤーシステム

- レイヤーツリー(グループのネスト対応)
- **合成モード**: Photoshop 互換の主要モード(乗算、スクリーン、オーバーレイ、加算発光、焼き込み…)をシェーダで実装
- クリッピングマスク、レイヤーマスク、透明度ロック、塗りつぶし/調整レイヤー(v2)
- 合成の最適化: 編集中レイヤーの「下」と「上」を事前合成キャッシュし、毎フレーム再合成するのは(下キャッシュ + 編集中 + 上キャッシュ)の 3 枚だけにする — 100 レイヤーでも 60fps を維持する定石

### 3.4 Undo / Redo

- コマンドパターン + **タイル差分スナップショット**: ストローク確定時に、変更されたタイルの変更前データだけを圧縮保存
- メモリ上限を超えた履歴はディスクへ、さらに古いものは破棄(履歴数はユーザー設定)

### 3.5 画像加工(Photoshop 的機能)

すべて GPU シェーダ(フラグメント or コンピュート)として実装し、**プレビューは低解像度で即時、確定時にフル解像度適用**の 2 段構えにする。

- 色調補正: トーンカーブ、レベル、色相/彩度/明度、カラーバランス、グラデーションマップ
- フィルタ: ガウスぼかし(分離カーネル)、モーションブラー、シャープ、ノイズ、モザイク、ゆがみ(Liquify)
- 選択範囲: 矩形/なげなわ/自動選択(flood fill)。選択は 8bit マスクとして持ち、ぼかし・反転・拡縮に対応。以降の全操作がマスクを考慮
- 変形: 拡縮回転(バイリニア/バイキュービック)、自由変形(ホモグラフィ)、メッシュ変形(v2)

## 4. UI 設計(Procreate 風)

原則: **画面はキャンバスに最大限譲る。ツールは「呼び出したときだけ」現れる。**

- 上部バー(極小): ギャラリー / 選択・変形・調整・ブラシ・指先・消しゴム / レイヤー / カラー
- 左端サイドバー: ブラシサイズ・不透明度のスライダー + 修飾ボタン(Procreate 同配置)
- パネルはすべてポップオーバー/シートで、開きっぱなしにしない
- **ジェスチャ**(書き味と同じくらい体験を決める):
  - 2本指タップ = Undo、3本指タップ = Redo
  - ピンチ = ズーム+回転(同時)、素早いピンチイン = 全体表示フィット
  - 長押し = スポイト
  - 4本指タップ = UI 非表示(フルスクリーン)
  - QuickMenu(長押しやボタンで放射状メニュー)にユーザーが機能を割当可能
- パーム リジェクション: ペン接続時は指入力を「ジェスチャ専用」に切替(指で描く/描かないは設定)
- カラー: HSV ホイール + パレット + スポイト。カラーピッカーは片手で完結するサイズに

## 5. ファイルフォーマットと互換性

- **独自形式**: zip コンテナ(内部: メタ JSON + レイヤーごとのタイルデータを LZ4 圧縮 + サムネイル)。追記保存で高速化
- **PSD 入出力**: レイヤー構造・合成モード・マスクをマッピング(完全互換は目指さず、主要機能の往復を保証)。実装は Ag-psd 相当を C++/Rust で
- 書き出し: PNG / JPEG / PSD / タイムラプス動画(v2)
- 自動保存: ストローク N 回ごと + バックグラウンド移行時に差分保存(モバイルはいつ kill されるか分からない前提)

## 6. パフォーマンス目標(受け入れ基準)

| 項目 | 目標 |
|---|---|
| ペン遅延(入力→表示) | ≤ 20ms(予測込み体感 ≤ 10ms) |
| 描画フレームレート | 60fps 維持(ProMotion 機で 120fps) |
| キャンバス | 4096×4096 × 50 レイヤーをミドルレンジ端末で操作可能 |
| 起動→描き始め | ≤ 2 秒 |
| クラッシュ時データ損失 | 直近ストローク数回分まで |

## 7. 開発ロードマップ

### Phase 0: 技術検証(1〜2ヶ月)
- Metal / Vulkan で「1レイヤーに低遅延でブラシ描画」だけのプロトタイプ
- **ここで書き味を徹底的に作り込む。書き味が出ないなら以降を作る意味がない**
- 筆圧カーブ・スタビライザー・予測入力・混色の検証

### Phase 1: MVP(3〜4ヶ月)
- タイルキャンバス、レイヤー(合成モード5種)、Undo/Redo
- ブラシ 10 種(ペン・鉛筆・エアブラシ・水彩・消しゴム)
- 基本 UI(ツールバー、レイヤーパネル、カラーピッカー、主要ジェスチャ)
- 保存/読込(独自形式)、PNG 書き出し

### Phase 2: v1.0(+3ヶ月)
- 選択範囲・変形、色調補正(トーンカーブ、色相/彩度)、フィルタ(ぼかし、シャープ)
- クリッピング/レイヤーマスク、全合成モード
- PSD 入出力、ブラシカスタマイズ UI、ギャラリー

### Phase 3: v1.x〜
- ゆがみ(Liquify)、メッシュ変形、調整レイヤー
- 定規・パース定規(クリスタ的)、対称描画
- タイムラプス録画、ブラシ共有、クラウド同期

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| 書き味が既存アプリに届かない | Phase 0 に集中投資。実機(iPad + Apple Pencil / Galaxy Tab + S Pen)で毎日描いて評価。絵描きのテスターを早期に入れる |
| Android の端末差(GPU/ペン) | Vulkan 必須世代に絞る(minSdk 29〜)。ペンは S Pen / USI を優先サポート |
| メモリ不足クラッシュ | タイルページング + メモリ警告での積極解放を最初から設計に入れる |
| 2 プラットフォーム同時開発の負荷 | コアを共有し、まず iPad 版に集中 → Android を後追いにするのが定石(Procreate も iPad 専業) |
