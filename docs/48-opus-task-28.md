作成: 2026-09-11。`47` のあと。`28` の「**E 書き出し（glTF + テクスチャセット）**」。
S3（ベイク）は `46` で終わっている。焼いた絵を**外へ持ち出す口**がこの紙。

## 0. ねらい

いま「焼く」で作れる絵は 7 種類あるのに、**外へ出せるのは PNG 1 枚ずつ**
（`44` の T3、`46` の T4）。glTF（`.glb`）は出せるが**形だけ**で、絵は付いていない。
つまり Substance / Blender へ渡すには、

1. `.glb` を書き出す
2. 法線を書き出す
3. AO を書き出す
4. 曲率を書き出す …
5. 向こうで貼り直す

という手順になる。`28` の「**スカルプト → 焼く → Substance / Blender がファイル 1 つで回る**」に
届いていない。

| # | いま | 直し |
|---|---|---|
| 1 | `.glb` は形だけ。マテリアルは灰色 1 つ | **T2**: 焼いた法線と AO を `.glb` の中に埋める（1 ファイルで完結） |
| 2 | 曲率 / 位置 / ID / 厚み / 高さは glTF に置き場が無い | **T1・T3**: **テクスチャセット一式（.zip）**。`.glb` + 全部の PNG を 1 つに |
| 3 | 絵の名前が `Bake_normal_1024.png`（大きさ入り） | **T3**: テクスチャセットの規則 `<オブジェクト名>_<チャンネル>.png` に揃える（`11` の 3 章。あとで読み戻すときの手がかり） |
| 4 | 焼いていない / 古いまま出せてしまう | **T4**: `古` なら焼き直してから出す。焼いていなければ断る |

## T1. ZIP を書く（`src/core/io/zip.ts`）

### 決め

- **無圧縮（store）だけ。** 中身は PNG で、もう縮んでいる。deflate を持ち込むと
  コードも時間も増えるだけ（2K × 7 枚で 30MB ほど。tablet では圧縮の方が重い）
- 出す形は **ZIP の最小構成**: ローカルヘッダ + 中身 …… を並べて、
  最後に中央ディレクトリと EOCD
- CRC-32 は自前（表を 1 回作って使い回す）
- 名前は UTF-8（フラグの bit 11 を立てる）。**日付は 0 で置く**
  （オブジェクト名に日本語が入るので UTF-8 は必須）

```ts
export interface ZipEntry { name: string; data: Uint8Array }
/** 無圧縮の ZIP を 1 つ作る。順番はそのまま。 */
export function zipStore(entries: ZipEntry[]): Uint8Array
```

- 4GB は超えない前提（ZIP64 は作らない）。**超えそうなら投げる**のではなく、
  呼ぶ側が枚数を減らす（2K × 7 枚 = 30MB なので当分来ない）

### テスト（`tests/zip.test.ts`。新設）

- 署名: 先頭が `PK\x03\x04`、末尾に `PK\x05\x06`
- 数: EOCD の「この ZIP の中の数」が入れた数と同じ
- 中身: ローカルヘッダの CRC・サイズが実際と合う。**中身のバイトがそのまま入っている**
- 名前: 日本語の名前が UTF-8 で入り、フラグの bit 11 が立っている
- 空: 0 個でも EOCD だけの正しい ZIP になる

## T2. glTF に絵とマテリアルを足す（`src/core/io/gltf.ts`）

### 決め

1. `GltfNode` に **`maps?: { normal?: Uint8Array; occlusion?: Uint8Array }`**（PNG のバイト列）。
   **PNG を作るのは app**（canvas を使う）。core は受け取って詰めるだけ
2. 絵があるノードは**そのノード専用のマテリアル**を持つ。1 つも無ければ
   今までどおり**灰色 1 つを共有**（`material: 0`。既存のテストがそのまま通る）
3. 詰め方は glTF の作法どおり: `images[].bufferView` + `mimeType: "image/png"` →
   `textures[]`（`sampler` は既定の 1 つ）→ `materials[].normalTexture` /
   `occlusionTexture`
4. **接線（TANGENT）も出す。** 法線マップは接空間なので、向こうで別の接線を
   組まれると陰影がずれる。焼くときと**同じ式**で出す（`bake.ts` の `buildFrames` と
   同じ、UV の微分から。VEC4 で w が符号）
5. **絵を添えるときは `smoothAngle` を 180 にする**（全部なめらか）。
   法線マップは「なめらかな法線」に対して焼いてあるので、書き出しでハードエッジに
   割ると二重にかかる。角は法線マップの側に入っている
6. `occlusionTexture` は glTF では**赤だけ**を見る。AO は灰色の PNG なので
   そのままで合う

### 気を付けること（緑の向き）

法線マップの緑は **OpenGL 向き**（+Y が上。glTF / Blender / Substance の既定）。
焼いた `sy` は「dP/dv の向き」で、**書き出しの PNG は縦に反転**している
（`44` の `rgbaToPng`）。埋める PNG も同じ経路を通るので、
**焼いた絵をそのまま埋めれば合う**はずだが、**確かめること**。
確かめ方は T5 のテストに置いた。合っていなければ、埋めるときに緑を反転するのではなく
**焼き方の側を直す**（PNG で出したものと `.glb` の中身が食い違うと後で必ず困る）。

### テスト（`tests/gltf.test.ts` に足す）

- 絵を渡さなければ、今までどおり `materials` は 1 つで `images` は無い
- 法線と AO を渡すと `images` 2 つ・`textures` 2 つ・`materials` は**ノードの数**、
  `normalTexture.index` と `occlusionTexture.index` が違うものを指す
- 画像のバイトが**渡したものと 1 バイト違わず**取り出せる（`bufferView` で切って比べる）
- `TANGENT` が VEC4 で、w が ±1、**接線が法線と直交**している
- 絵を渡したノードは、`smoothAngle` を 0 にしても頂点が割れない（180 扱い）

## T3. 書き出しの口（app）

### メニュー（「ファイル」→「書き出し」）

| 名前 | 中身 |
|---|---|
| `OBJ を書き出す (.obj)` | 今のまま |
| `glTF を書き出す (.glb)` | 今のまま（形だけ） |
| **`glTF + 焼いた絵 (.glb)`** | 法線と AO を埋めた 1 ファイル |
| **`テクスチャセット一式 (.zip)`** | `.glb` + **焼いた絵を全部** PNG で |

- 出すのは**選んでいるオブジェクト**の焼き方（`bakeResult`）。
  選んでいなければ「オブジェクトを選んでください」
- **名前の規則**（`11` の 3 章）:

  ```
  <名前>.zip
   ├ <名前>.glb
   ├ <名前>_normal.png
   ├ <名前>_height.png
   ├ <名前>_ao.png          ← 焼いた絵だけ。頼まなかったものは入らない
   ├ <名前>_curvature.png
   ├ <名前>_position.png
   ├ <名前>_id.png
   └ <名前>_thickness.png
  ```

  チャンネル名は **Substance と同じ綴り**（`normal` / `height` / `ao` /
  `curvature` / `position` / `id` / `thickness`）。`44` の
  `Bake_normal_1024.png` から**大きさを外す**（読み戻すときに邪魔）
- `.glb` の中に埋めるのは **normal と ao だけ**（glTF に置き場があるのはこの 2 つ）。
  残りは ZIP の中の PNG として渡す
- PNG のバイトは `rgbaToPng` の Blob から `arrayBuffer()` で取る。
  **`mapBytes` → PNG は 1 か所にまとめる**（`src/app/bake.ts` に
  `pngBytes(result, kind): Promise<Uint8Array>`）

### 進み具合

2K × 7 枚の PNG 化は数秒かかる。**トーストで「書き出しています…」**を出して、
終わったら「`名前.zip` を書き出しました — 7 枚・12.3MB」。

## やらないこと

- **読み込み**（glTF も ZIP も）。外から持ってくるのは別の紙
- deflate（無圧縮の ZIP だけ）
- 高さマップを glTF の変位に載せること（`KHR_materials_displacement` は
  まだ標準ではない。ZIP の PNG で渡す）
- マテリアルを複数（テクスチャセットは**オブジェクトに 1 つ**。
  `materialId` ごとに分けるのは v2.0 のマテリアルの紙で）
- ベースカラー（まだ塗っていない。v2.0）
- **B11 の 3 択**（`46` の宿題）。実機の数字を見てから決める（`37` の表の 45 番）

## 報告（2026-09-11）

T1 〜 T5 すべて済み。**core + app 411 テスト**（`47` の 400 から +11）。
通し確認は `dist` と `app/` の両方で緑（新しい検査 4 件）。

### T1. ZIP（`src/core/io/zip.ts`）

- `zipStore(entries)` と `crc32(data)`。無圧縮（store）だけ、UTF-8 の名前、日付は 0
- 中央ディレクトリと EOCD まで手で組む。**1 回の走査で大きさを数えてから 1 枚の
  `Uint8Array` に書く**（継ぎ足すと 30MB でコピーが増える）
- テスト 5 つ。CRC は知られている検査値（`"123456789"` → `0xCBF43926`）で確かめた

### T2. glTF に絵とマテリアルと接線

- `GltfNode.maps`（PNG のバイト列）。絵のあるノードは**専用のマテリアル**、
  1 つも無ければ今までどおり灰色 1 つを共有（既存のテストがそのまま通る）
- `images[].bufferView` + `textures` + `samplers` を JSON に足した。
  `normalTexture` と `occlusionTexture` に繋ぐ
- **TANGENT（VEC4）を出す。** 焼くときと同じ `bakeFrames`（`44` の `buildFrames`）を
  使うので、向こうで基底が組み直されても一致する
- 絵を添えるノードは**角で割らない**（`smoothAngle` を 180 扱い）。法線マップは
  なめらかな法線に対して焼いてあるので、割ると二重にかかる

**ついでに 2 つ直した（どちらも「絵を貼って初めて分かる」ずれ）:**

1. **V をひっくり返して出すようにした。** このアプリの UV は下から上、
   glTF は「(0,0) が画像の左上」。形だけの `.glb` では誰も気づかないが、
   絵を貼ると上下が逆さになる。**焼いた PNG（`rgbaToPng` で縦を返してある）が
   そのまま `.glb` の中でも単体でも正しく貼れる**形に揃えた
2. **接線を法線に直交させた**（`buildFrames` にグラム・シュミットを 1 つ）。
   MikkTSpace と Substance / Blender はこの基底を前提にしている。
   前は正規化するだけだったので、角のある形で基底がわずかに歪んでいた

### T3・T4. 書き出しの口

- 「ファイル」に 2 つ足した: **`glTF + 焼いた絵 (.glb)`** と
  **`テクスチャセット一式 (.zip)`**
- 名前は `<オブジェクト名>_<チャンネル>.png`（大きさは入れない）。
  ZIP の中は `Head.glb` + `Head_normal.png` + …
- `pngBytes(result, kind)` を `app/bake.ts` に作って、**PNG にする口を 1 つ**にした
  （1 枚ずつの書き出しも、埋めるのも、ZIP も同じ経路）
- 絵を付ける相手は**名前ではなく並び**で決める（同じ名前のオブジェクトがあっても
  間違えない）。隠れているオブジェクトを選んでいたらそう言う
- 焼き具合: `none` は断る、`古` は**焼き直してから**出す（トーストにそう出る）、
  `済` はそのまま

### 通し確認に足した検査（4 件）

| 名前 | 見ているもの |
|---|---|
| glTF + 焼いた絵 | 画像 2 枚・テクスチャ 2・`normalTexture` / `occlusionTexture`・TANGENT・埋まった PNG が 512px |
| **埋めた法線マップの向き** | PNG の行 `size−1−y` が焼いた配列の行 `y`（227 テクセルで一致） |
| テクスチャセット一式 | `Head.glb` + 焼いた枚数ぶんの PNG。名前が規則どおり |
| 焼き具合 | `古` のまま出すと焼き直して `済` になる。焼いていなければ断る |

### 数字

書き出しは押したときだけの処理なので、ベンチには入れていない。
512 の 4 枚（法線・高さ・AO・曲率）で **ZIP は 0.3MB**、`.glb` は 216KB。
2K の 7 枚なら 30MB ほどになる見込み。

### 残り

- **B11 の 3 択**（`46` の宿題）は手つかず。実機の数字を見てから（`37` の 45 番）
- 読み込み（glTF / ZIP）、FBX、USD は未着手（`28` の E の残り）
