あなたはタブレット向け 3D モデリング・スカルプトアプリを新規開発するリポジトリで作業します。

グラフィックスにも OS にも依存しない純粋な C++ ライブラリとして実装し、
その正しさと性能を検証することです。

**UI もレンダラもモバイル対応も、このタスクの範囲外です。作らないでください。**

## 2. 仕様

### 2.1 ベースメッシュ

レベル 0 のコントロールケージ。四角形と三角形の混在を許容します。

```cpp
struct BaseMesh {
    std::vector<float3>  positions;    // 頂点座標
    std::vector<int32_t> faceOffsets;  // size = faceCount + 1
    std::vector<int32_t> faceCorners;  // 面を構成する頂点インデックス列
    std::vector<float>   edgeCrease;   // エッジごとのクリース値 0.0〜10.0
    std::vector<float>   cornerSharp;  // 頂点ごとのシャープネス 0.0〜10.0
};
```

クリース値は **OpenSubdiv の semi-sharp crease のセマンティクス**に従います
（整数部が完全鋭角として扱う細分割回数、小数部が補間）。USD も同じ表現です。

### 2.2 マルチ解像度スタック — このタスクの核心

各レベルの頂点座標をそのまま保持するのではなく、
**細分割で得られる滑らかな面からのズレを接空間で保持します**。

レベル `L`（`L >= 1`）について:

```
S(L) = Refine(P(L-1))        細分割で得られる滑らかな面の頂点座標
T(L) = Frame(S(L))           S(L) から構築する正規直交の接空間基底（頂点ごとの 3x3 行列）
P(L) = S(L) + T(L) * delta(L)   実際の頂点座標
```

- `delta(L)` は接空間で表現されたスカルプトのディテール。**これがレベルごとに保存される唯一のデータ**です
- `P(0)` はベースメッシュの頂点座標そのもの（デルタなし）

**重要な制約が 2 つあります。必ず守ってください。**

1. **接空間 `T(L)` は必ず `S(L)`（滑らかな面）から構築すること。`P(L)` から構築してはいけません。**
   `P(L)` から作ると循環参照になり、ローモデル編集時にディテールが破綻します。

2. **接空間の構築はトポロジのみに依存する決定的な手順にすること。**
   推奨する構築方法:
   - 法線 `N` = 隣接面の面法線の面積重み付き平均を正規化したもの
   - 接線 `T1` = **インデックスが最小の隣接頂点**への方向ベクトルを、`N` に直交する平面へ射影して正規化
   - 従法線 `T2 = N × T1`
   - `T = [T1, T2, N]`（正規直交なので逆行列は転置）

   「インデックス最小の隣接頂点」を使うのは、頂点位置が変化しても基底の選び方が変わらないようにするためです。
   トポロジは固定なので、これで決定性が保証されます。

### 2.3 必要な操作

```cpp
class MultiresMesh {
public:
    // レベル 0 のベースメッシュを設定
    void setBase(const BaseMesh& base);

    // 最上位レベルを 1 つ増やす（delta は 0 で初期化）
    void divide();

    // 最上位レベルを 1 つ削除
    void deleteHigher();

    int  maxLevel() const;

    // 表示・編集対象のレベルを設定（スライダー相当）
    void setActiveLevel(int level);
    int  activeLevel() const;

    // 現在のレベルの頂点座標（読み取り）
    std::span<const float3> positions(int level) const;

    // 指定レベルの頂点を新しいワールド座標に設定する。
    //   level == 0   → ベースメッシュの編集。上位レベルのディテールは保持される
    //   level >= 1   → スカルプト。delta が更新される
    // いずれの場合も、指定レベルより上位のレベルが再計算される。
    void setPositions(int level, std::span<const int32_t> indices,
                                 std::span<const float3>  newPositions);

    // 概算メモリ使用量（バイト）
    size_t memoryUsage() const;
};
```

`setPositions` の内部処理:

```
level == 0 の場合:
  P(0) を更新
  for L = 1 .. maxLevel:
      S(L) = Refine(P(L-1))
      T(L) = Frame(S(L))
      P(L) = S(L) + T(L) * delta(L)     ← delta は変更しない。これが形状保持の要

level >= 1 の場合:
  delta(L) = transpose(T(L)) * (newPosition - S(L))
  P(L) を更新
  上位レベルについて level == 0 の場合と同じループを回す
```

### 2.4 差分更新（性能要件を満たすために必要）

レベル 0 の頂点を 1 つ動かすたびに全レベルを再計算すると、レベル 5 以上で対話的な速度が出ません。
**変更された頂点の影響範囲だけを再計算する差分更新を実装してください。**

Catmull-Clark の影響範囲は局所的です。レベル `L-1` の頂点 `v` が動いたとき、
レベル `L` で影響を受けるのは `v` に隣接する面から生成される頂点のみです。
この対応関係は `Far::TopologyRefiner` から取得できます。

まず全体再計算の素朴な実装で正しさを担保し、
そのあとに差分更新を実装して**両者の結果が一致することをテストで保証してください**。

### 2.5 OBJ 入出力（テスト用の最小実装）

検証用のメッシュを読み書きするためだけに必要です。凝った実装は不要です。

- 読み込み: `v`、`f`、`g`（ポリグループとして保持）
- 書き出し: `v`、`f`、`g`
- マテリアルもテクスチャ座標も不要

## 4. 合格条件（これが達成できたかどうかがこのタスクの成否です）

すべて `core_tests` と `multires_bench validate` で自動検証できるようにしてください。

### V1. 細分割の基本
立方体（8 頂点 6 面）をレベル 5 まで細分割し、頂点数が Catmull-Clark の理論値と一致すること。

### V2. クリースの伝播
立方体の上面を囲む 4 本のエッジにクリース値 10.0 を設定してレベル 5 まで細分割したとき、
そのエッジが鋭角のまま保たれること。**判定基準: 該当エッジの二面角が 90 度から 5 度以内**。
同じ立方体でクリース値 0.0 の場合は明確に丸まること（二面角が 150 度以上）。

### V3. 剛体変換不変性 ← 最重要
これが**マルチ解像度の正しさを最も厳密に検証する項目**です。

1. 立方体をレベル 4 まで細分割する
2. レベル 4 でランダムにスカルプトする（各頂点を法線方向に乱数で変位させる）
3. レベル 4 の頂点座標を `A` として保存する
4. レベル 0 に戻り、**ベースメッシュ全体に剛体変換を適用する**（任意の回転 + 平行移動 `M`）
5. レベル 4 に戻り、頂点座標 `B` を取得する

**合格条件: `B` が `M * A` と一致すること（各成分の誤差 1e-4 以内）。**

接空間デルタが正しく実装されていれば、これは厳密に成立します。
ワールド座標で差分を持っているなど実装が誤っていると、この検証は必ず失敗します。

### V4. ローモデル編集でのディテール保持
1. 球（またはレベル 2 まで細分割した立方体）をレベル 4 まで細分割する
2. レベル 4 で局所的な突起をスカルプトする
3. レベル 0 に戻り、突起の近傍にある頂点を、ベースメッシュのサイズの 30% 程度大きく動かす
4. レベル 4 に戻る

**合格条件:**
- 突起が消えていないこと。突起頂点の `delta` のノルムが編集前後で変化していないこと（誤差 1e-5 以内）
- 突起が表面から浮いていないこと。突起の基部の頂点が、滑らかな面 `S(4)` からの距離を保っていること
- `export` した OBJ を目視して、ディテールが引き伸ばされたり剥がれたりしていないこと

### V5. レベルの往復
`divide` → スカルプト → `setActiveLevel(0)` → `setActiveLevel(maxLevel)` を 10 回繰り返しても、
頂点座標が初回と一致すること（誤差 1e-5 以内）。**累積誤差が発生しないことの確認**です。

### V6. 差分更新の一致
レベル 0 の頂点を 1 つ動かしたとき、差分更新の結果と全体再計算の結果が一致すること（誤差 1e-6 以内）。

## 5. 性能要件

ベースメッシュ 1000 四角形、レベル 5（約 100 万四角形 = 200 万トライアングル）で測定します。
測定は 64bit デスクトップ、リリースビルド、シングルスレッドで構いません。

| 項目 | 目標 |
|---|---|
| レベル 0 の頂点 1 つを移動 → 最上位まで反映（差分更新） | **50ms 以内** |
| `setActiveLevel` によるレベル切り替え | **200ms 以内** |
| レベル 5 全体の再構築（全体再計算） | 2000ms 以内 |
| メモリ使用量（全レベルのデルタ + 座標） | **300MB 以内** |

`bench` サブコマンドでこれらを計測し、数値を表形式で出力してください。
**目標を満たせなかった場合も、数値をそのまま報告してください。** 達成できたことにしないでください。

## 6. 進め方

1. CMake の骨格と OpenSubdiv の組み込みを先に通し、立方体を 1 回細分割できることを確認する
2. 全体再計算の素朴な実装で `MultiresMesh` を作り、**V1〜V5 を先に通す**
3. そのあとに差分更新を実装し、V6 と性能要件に取り組む
4. 各段階でコミットする

**正しさを先に確立してから最適化してください。** 逆順でやると、どちらが原因か切り分けられなくなります。

## 9. 補足: なぜこの設計なのか

背景を知りたい場合は `docs/03-multires-core.md` を参照してください。要点のみ再掲します。

このアプリの差別化の核は「**ハイメッシュのディテールを保ったまま、ローモデルを Maya 相当のツールで編集できる**」ことです。
ZBrush はサブディビジョンレベルを持っていますが、低レベルで本格的なポリゴン編集ツールを使わせてくれません。
Nomad Sculpt にはそもそもマルチ解像度がありません。ここが唯一無二の売りになります。

なお、**トポロジを変更する操作（エッジループ挿入、ベベル等）では上位レベルを維持できません**。
デルタはレベル間の頂点の対応関係に依存しているためです。ZBrush が同じ制約を持つのはこれが理由です。
このタスクではトポロジ変更を扱わないので、その前提で実装して構いません。
