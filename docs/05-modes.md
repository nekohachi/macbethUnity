
# 05. 各モードの機能スコープ

## 5.0 モード切り替えの設計

タブでモードを切り替えますが、内部的には **1つのドキュメントに対する複数のビュー**として設計します。モードごとにシーンを持つのではありません。

```
IEditorMode
  ├ ツールセット
  ├ 選択のセマンティクス（頂点／UVシェル／マスク／テクスチャセット）
  ├ ビューポートのオーバーレイ描画
  ├ 使用するパネル構成
  └ Enter() / Exit()  ※切り替えは 100ms 以内で完了させる
```

モード間で選択情報を橋渡しできると強力です。たとえば:

- モデリングで面を選択 → スカルプトに切り替えるとその面がマスク解除領域になる
- スカルプトでポリグループを作成 → モデリングでその面群が選択される
- モデリングで面を選択 → UV モードでその UV シェルが選択される

これは他社アプリにない使い勝手になるので、実装を推奨します。

## 5.1 モデリングモード（Maya 参考）

v1 の実装対象を絞り込みます。Maya の全機能は不要で、下記があれば実用になります。

### 選択

- オブジェクト / 頂点 / エッジ / 面 の 4 モード
- ドラッグ選択、投げ縄選択、エッジループ選択（ダブルタップ）、エッジリング選択
- **ソフト選択**（減衰カーブ編集付き）— タブレットでの形状調整では Maya 以上に重要です
- 選択の拡張・縮小

### 変形

- 移動 / 回転 / スケールのギズモ
- **ギズモはタッチ用に作り直してください。** Maya のギズモをそのまま出すと指で掴めません。ハンドルは 44pt 以上の当たり判定を持たせ、軸ハンドルに加えて平面ハンドル、スクリーン空間ハンドルを用意します
- スナップ（グリッド / 頂点 / エッジ / 面）

### 編集ツール（v1）

| ツール | 備考 |
|---|---|
| 押し出し（Extrude） | 面・エッジ両方 |
| ベベル（Bevel） | セグメント数指定 |
| エッジループ挿入 | プレビュー表示必須 |
| マルチカット | ペンでの操作と相性が良い |
| ブリッジ | |
| マージ / ターゲットウェルド | |
| 削除（頂点・エッジ） | 余分な頂点の後始末を正しく行うこと |
| 穴を埋める | |
| 結合 / 分離 | |
| ミラー・対称編集 | ワールド軸対称とトポロジ対称の両方 |
| スムース / リラックス | |
| **クリース設定** | 細分割に直結するので v1 必須 |

### v1 で見送るもの

ブーリアン、リトポロジーツール、変形デフォーマ、ヒストリ（コンストラクションヒストリ）。特に **Maya のようなヒストリ機構は実装しないでください**。実装コストが跳ね上がり、モバイルでは重すぎます。破壊的編集＋ Undo で十分です。

## 5.2 スカルプトモード（ZBrush for iPad 参考）

### ブラシ（v1）

Standard / Clay / ClayBuildup / Move / Smooth / Pinch / Inflate / Flatten / Trim / Damien Standard（鋭いクリース用） / Polish

### ブラシの構成要素

- **半径と強度に筆圧をマッピング**（それぞれ独立したカーブで調整可能に）
- **アルファ**（グレースケールのスタンプテクスチャ）
- **ストロークタイプ**: ドット / ドラッグレクト / スプレー / フリーハンド
- **減衰カーブ**の編集
- 傾き（altitude）と方位（azimuth）をアルファの回転・変形に反映

### マスキング

- ペンでのマスク描画（Ctrl 押下中）
- マスクのぼかし / シャープ / 反転 / 全解除
- ポリグループ単位のマスク
- キャビティマスク（凹部だけマスク）
- 裏面マスク（backface masking）— これがないと薄い形状が破綻します

### 対称

- X / Y / Z 軸対称、放射状対称
- v1.5 でトポロジ対称、ポリグループ単位の局所対称

### サブディビジョンレベル

`03-multires-core.md` を参照。スカルプトモードの中核です。

### スカルプトレイヤー（v1.5 推奨）

ZBrush のレイヤーに相当。レベルごとのデルタバッファを複数持ち、それぞれに強度スライダーを付けるだけで実装できます。**マルチ解像度の仕組みができていれば追加コストが小さく、価値が非常に高い**機能です。

### v1 で見送るもの

ダイナメッシュ、ZRemesher 相当の自動リトポロジー、サブツール間ブーリアン、Fibermesh。今回のワークフロー（低ポリを作ってから細分割）ではダイナミックトポロジーの優先度は低めです。

## 5.3 UV モード（Maya 参考）

### ビュー

2D の UV エディタと 3D ビューを分割表示。片方での選択がもう片方に同期します。

### 機能（v1）

- 展開（Unfold）— LSCM / ABF++ アルゴリズム
- 自動 UV（投影展開、自動シームによる展開）
- カット / ソー（縫合）
- ピン留め
- シェルの整列、回転、スケール、直線化
- レイアウト（パッキング）
- チェッカーマップによる歪み表示、歪みのヒートマップ表示
- **UDIM 対応**（少なくとも 1001〜1010）
- 対称 UV

### ライブラリ

- **自動 UV とパッキング: xatlas（MIT ライセンス）** を推奨。実績が豊富で、`xatlas.cpp` と `xatlas.h` の 2 ファイルだけで組み込めます
- **対話的な展開: LSCM / ABF++ を自前実装**（線形ソルバは Eigen などを利用）
- **Blender のコードは GPL なので流用できません。** アルゴリズムの論文を参照して実装してください。ここは法的に注意が必要です

## 5.4 マテリアルモード（Substance Painter 参考）※ v2.0

ご指示どおり今回は作りません。設計方針だけ残します。

### 構成

- 2D ビュー（UV 空間）と 3D ビューの同時表示、ペイントの相互同期
- チャンネル: BaseColor / Roughness / Metallic / Normal / Height / AO / Opacity / Emissive
- レイヤースタック（塗りレイヤー、ペイントレイヤー、マスク、フォルダ、ブレンドモード）
- ジェネレータ（カーブチャ、AO、位置に基づくマスク生成）
- スマートマテリアル

### ベイク

法線（ハイ→ロー）、AO、カーブチャ、厚み、ポジション、ワールド法線、ID マップ。タブレットではメモリが厳しいので **2K を既定、4K を上限**とします。

### 「Substance のマテリアルを読み込む」について

率直にお伝えします。**Substance のファイル形式を直接読み込むことは、現実的にはできません。** 詳細は `06-file-formats.md` に書きましたが、要点は以下です。

- `.sbsar` の実行には Adobe の Substance 3D Materials SDK が必要で、商用ライセンス契約が要ります。モバイル向けの提供可否は Adobe との個別交渉になります
- `.spp`（Painter プロジェクト）と `.sbs`（Designer ソース）は非公開形式で、正式な読み込み手段がありません

**現実的な代替案:**

1. Substance Painter から書き出した**テクスチャセット（PNG / TGA / EXR）を読み込む**。実務上これで 9 割の用途は満たせます
2. マテリアルグラフの交換には **MaterialX（`.mtlx`、オープン標準）**を採用する。Adobe も Autodesk も対応しており、将来性があります
3. 将来的に Adobe とライセンス交渉ができたら `.sbsar` 対応を追加する

## 5.5 アニメーションモード ※ v3.0

今回は作りませんが、データ構造だけ将来を阻害しないようにしておきます。

- メッシュに**スキンウェイト用のスロットを予約**しておく（頂点あたり 4 ボーン想定）
- シーングラフを**階層構造**にしておく（後からジョイントを差し込めるように）
- FBX / USD の入出力時に、スキンとボーン情報を**読み飛ばさず保持して書き戻す**（パススルー）

3 番目が特に重要です。アニメーション機能がなくても、**「Maya でリグを組んだモデルを本アプリで開いて修正し、リグを壊さずに書き戻せる」**なら実用価値が跳ね上がります。v1 から意識してください。
